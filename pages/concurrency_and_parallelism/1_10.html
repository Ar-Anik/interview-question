Python Concurrency & GIL — Interview Questions

Process, Thread, Concurrency, Parallelism, CPU/I/O Bound, GIL, Threading & Thread Lifecycle

সংক্ষিপ্ত উত্তর

Process হলো operating system-এর একটি independent execution unit যার নিজস্ব virtual address space থাকে। Thread হলো একটি process-এর ভিতরের execution path; একই process-এর threads সাধারণত একই memory space share করে।

মূল পার্থক্য

  • Memory: আলাদা process-এর memory space আলাদা। একই process-এর threads memory space share করে।
  • Communication: Process-এর মধ্যে communication-এর জন্য IPC যেমন Pipe, Queue, Socket বা shared memory দরকার। Threads shared memory ব্যবহার করে তুলনামূলক সহজে data share করতে পারে।
  • Isolation: Process বেশি isolated; একটি process crash করলে সাধারণত অন্য process সরাসরি একই address space-এর corruption-এর শিকার হয় না।
  • Creation/Context switching: সাধারণভাবে process-এর overhead thread-এর চেয়ে বেশি।
  • CPU parallelism in CPython: GIL থাকা CPython-এ সাধারণ Python bytecode-এর CPU-bound execution-এর জন্য multiple threads একই সময়ে একাধিক CPU core-এ execute করতে পারে না। Multiple processes আলাদা interpreter process হওয়ায় CPU-bound work parallelভাবে চালানো যায়।
Interview line: Process provides isolation with a separate address space; threads are lighter execution units inside a process and normally share that process's memory.

সংক্ষিপ্ত উত্তর

Concurrency হলো একাধিক task-এর progress একই সময়ে manage করা। Parallelism হলো একাধিক task সত্যিই একই সময়ে multiple execution resource-এ execute হওয়া।

সহজভাবে

  • Concurrency: “একাধিক কাজের মধ্যে execution এগিয়ে নেওয়া।”
  • Parallelism: “একাধিক কাজ একই মুহূর্তে execute করা।”

উদাহরণ

একটি CPU যদি task A কিছু সময় execute করে, তারপর task B-তে switch করে, আবার A-তে ফিরে আসে, তাহলে concurrency আছে; কিন্তু একই সময়ে A এবং B execute হচ্ছে না।

দুইটি CPU core-এ task A এবং task B একই সময়ে execute হলে সেটি parallelism।

Important: Concurrency does not necessarily mean parallel execution. Parallelism is one way concurrency can be achieved when multiple execution resources are available.

CPU-bound

যে কাজের execution time-এর বড় অংশ CPU computation-এর জন্য ব্যয় হয়, সেটি CPU-bound।

উদাহরণ: বড় numerical calculation, image processing, compression, complex data processing।

I/O-bound

যে কাজের execution time-এর বড় অংশ input/output operation-এর জন্য অপেক্ষায় ব্যয় হয়, সেটি I/O-bound।

উদাহরণ: network request, database query, file read/write, external API call।

Python-এ কেন গুরুত্বপূর্ণ?

  • CPU-bound: GIL থাকা CPython-এ CPU-bound Python code-এর জন্য threads সাধারণত CPU parallelism দেয় না; multiprocessing বেশি উপযোগী।
  • I/O-bound: একটি thread I/O-এর জন্য অপেক্ষা করার সময় অন্য thread Python code execute করতে পারে; তাই threading I/O-bound workload-এ উপকারী হতে পারে।
Shortcut: CPU-bound → computation-heavy → multiprocessing often helps. I/O-bound → waiting-heavy → threading or async I/O can help.

সংক্ষিপ্ত উত্তর

GIL (Global Interpreter Lock) হলো CPython interpreter-এর একটি synchronization mechanism, যা সাধারণ Python bytecode execution-এর ক্ষেত্রে একই process-এ একই সময়ে একাধিক thread-কে Python interpreter state-এ একসাথে execute করতে বাধা দেয়।

তাই GIL থাকা CPython-এ CPU-bound pure-Python code-এর ক্ষেত্রে একাধিক thread সাধারণত একাধিক CPU core-এর full parallel execution পায় না।

গুরুত্বপূর্ণ nuance

GIL মানে “এক সময়ে পুরো application-এ শুধু একটি thread exist করতে পারে” নয়। অনেক thread একই process-এ exist করতে পারে; কিন্তু GIL থাকা অবস্থায় সাধারণ Python bytecode execution-এর relevant অংশে এক সময়ে একটি thread GIL ধরে এগোয়।

Modern Python note: CPython 3.13 থেকে free-threaded CPython build-এর experimental support এসেছে, যেখানে GIL disable করা যায়। পরবর্তী Python releases-এ এই capability আরও উন্নত হয়েছে। তবে standard/default CPython build-কে ধরে সাধারণ interview discussion-এ GIL-এর traditional behavior ব্যাখ্যা করা হয়।

মূল কারণ

CPython-এর মূল implementation-এর design-এ memory management এবং interpreter internals thread-safe রাখা সহজ করার জন্য GIL গুরুত্বপূর্ণ ভূমিকা পালন করেছে।

Reference counting-এর সঙ্গে সম্পর্ক

CPython ঐতিহাসিকভাবে reference counting ব্যবহার করে object-এর lifetime manage করে। একাধিক thread একই object-এর reference count একই সময়ে পরিবর্তন করলে race condition-এর ঝুঁকি তৈরি হয়।

GIL interpreter-level synchronization-এর একটি বড় অংশ সহজ করে, ফলে CPython-এর object model ও C extension ecosystem-এর অনেক অংশ তুলনামূলকভাবে সহজ design-এ পরিচালিত হয়েছে।

Interview answer

GIL was introduced in CPython primarily to simplify thread safety of the interpreter and its memory-management model, especially around reference counting. The trade-off is that threads cannot execute Python bytecode in true parallelism under the traditional GIL.

Important: GIL শুধু “reference counting-এর জন্য” নয়। CPython-এর interpreter implementation, C API এবং historical extension ecosystem-এর design-এর সঙ্গেও এর সম্পর্ক আছে।

GIL সবচেয়ে বেশি গুরুত্বপূর্ণ

  • CPython-এর traditional GIL-enabled build ব্যবহার করা হচ্ছে।
  • একাধিক threads আছে।
  • Threads CPU-bound Python bytecode execute করছে।
  • Application multiple CPU cores ব্যবহার করে CPU-bound Python work parallel করতে চায়।

GIL কম গুরুত্বপূর্ণ বা অন্যভাবে প্রভাব ফেলে

  • I/O-bound workload-এ thread I/O-এর জন্য অপেক্ষা করার সময় অন্য thread এগোতে পারে।
  • কিছু native extension GIL release করে expensive native computation চালাতে পারে।
  • Multiprocessing-এ প্রতিটি process-এর আলাদা Python interpreter থাকে, তাই একটি process-এর GIL অন্য process-কে একইভাবে block করে না।
  • Free-threaded CPython build-এ GIL disabled থাকতে পারে, তাই traditional GIL limitation প্রযোজ্য নয়।
Interview shortcut: GIL matters most when multiple threads are trying to execute CPU-bound Python code in a traditional GIL-enabled CPython build.

Threading I/O-bound workload-এ বেশি উপকারী

Threading ব্যবহার করে একাধিক I/O operation overlap করা যায়। একটি thread যখন network, database, file বা অন্য blocking I/O-এর জন্য অপেক্ষা করছে, তখন অন্য thread কাজ করতে পারে।

উদাহরণ

  • একাধিক HTTP API request
  • একাধিক file operation
  • Database/network I/O
  • Blocking third-party library ব্যবহার করা

কখন threading ideal নয়?

Traditional GIL-enabled CPython-এ pure-Python CPU-bound task parallel করার জন্য threading সাধারণত উপযুক্ত নয়। সেই ক্ষেত্রে multiprocessing বা workload অনুযায়ী অন্য concurrency approach বিবেচনা করা হয়।

Example: 100টি independent HTTP request sequentially করার বদলে একাধিক thread দিয়ে request-গুলো overlap করলে waiting time কমানো যায়।

CPU-bound workload-এ multiprocessing গুরুত্বপূর্ণ

Multiprocessing একাধিক independent process তৈরি করে। প্রতিটি process-এর নিজস্ব Python interpreter এবং memory space থাকে। Traditional GIL-enabled CPython-এ এটি multiple CPU cores-এ CPU-bound Python computation parallelভাবে চালাতে সাহায্য করে।

উদাহরণ

  • Large numerical computation
  • CPU-heavy data transformation
  • CPU-heavy image processing
  • Independent batch processing

Trade-off

  • Process creation এবং management-এর overhead বেশি।
  • Processes সাধারণত memory share করে না।
  • Data exchange-এর জন্য IPC বা serialization দরকার হতে পারে।
  • একটি shared mutable state design করা threads-এর তুলনায় জটিল হতে পারে।
Interview line: For CPU-bound Python work under traditional CPython, multiprocessing can achieve real CPU parallelism because each process has its own interpreter and GIL.

সংক্ষিপ্ত উত্তর

Python-এর threading module একই process-এর মধ্যে multiple threads তৈরি এবং manage করার standard API দেয়।

Basic example

import threading

def worker():
    print("Worker is running")

thread = threading.Thread(target=worker)

thread.start()
thread.join()

print("Done")

এখানে কী হচ্ছে?

  1. Thread(...) একটি thread object তৈরি করে।
  2. start() thread-এর execution শুরু করার জন্য OS/Python runtime-এর কাছে scheduling শুরু করে।
  3. Thread-এর target function হিসেবে worker() নির্ধারিত।
  4. join() calling thread-কে অপেক্ষা করায় যতক্ষণ target thread শেষ না হয়।

Shared memory-এর সতর্কতা

একই process-এর threads shared objects access করতে পারে। তাই shared mutable state-এ race condition হতে পারে। প্রয়োজন অনুযায়ী Lock, RLock, Semaphore, Event বা Condition ব্যবহার করা হয়।

Important: threading concurrency দিতে পারে, কিন্তু traditional GIL-enabled CPython-এ CPU-bound Python bytecode-এর জন্য এটি সাধারণত multi-core CPU parallelism দেয় না।

Conceptual lifecycle

  1. New / Created: Thread object তৈরি হয়েছে, কিন্তু start() এখনও call হয়নি।
  2. Runnable / Ready: start() call হয়েছে এবং thread execution-এর জন্য eligible।
  3. Running: scheduler thread-টিকে CPU execution দিচ্ছে।
  4. Waiting / Blocked: thread lock, I/O, event, condition বা অন্য synchronization/resource-এর জন্য অপেক্ষা করতে পারে।
  5. Terminated: target function শেষ হয়েছে; thread-এর execution শেষ।

Python example

import threading
import time

def worker():
    time.sleep(1)
    print("Worker finished")

t = threading.Thread(target=worker)

# New / Created
t.start()

# Started; worker may be running or waiting
t.join()

# Terminated
print("Thread finished")

একটি গুরুত্বপূর্ণ correction

এগুলো conceptual lifecycle states। Python-এর threading.Thread API Java-এর মতো formal public state enum দেয় না। Python-এ is_alive(), start(), join() ইত্যাদি API দিয়ে thread-এর lifecycle manage করা হয়।

আরও গুরুত্বপূর্ণ

  • start() একটি Thread object-এর জন্য একবারই call করা যায়।
  • Thread শেষ হয়ে গেলে একই Thread object আবার start() করা যায় না।
  • join() calling thread-কে target thread শেষ হওয়া পর্যন্ত অপেক্ষা করায়।
  • daemon=True হলে process-এর non-daemon threads শেষ হয়ে গেলে daemon thread process shutdown-এর সময় চলতে থাকা অবস্থায় থাকতে পারে এবং program shutdown-এ অপেক্ষা করে না।
Interview line: A thread is created, started, becomes eligible for execution, may run or wait/block, and eventually terminates when its target function finishes.
