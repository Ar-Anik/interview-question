Python Concurrency — Interview Questions 11–20

ThreadPoolExecutor, Race Conditions, Locks, Synchronization, Deadlock, Starvation & asyncio

সংক্ষিপ্ত উত্তর

ThreadPoolExecutor হলো Python-এর concurrent.futures module-এর একটি high-level API, যা একটি pool of worker threads তৈরি করে এবং submitted task-গুলো সেই threads-এর মাধ্যমে execute করে।

কেন দরকার?

প্রতিটি কাজের জন্য manually Thread() তৈরি করলে thread creation, lifecycle এবং cleanup manage করতে হয়। ThreadPoolExecutor এই management-এর বড় অংশ নিজে handle করে।

Basic example

from concurrent.futures import ThreadPoolExecutor

def fetch_data(item):
    return f"Processed {item}"

with ThreadPoolExecutor(max_workers=4) as executor:
    results = list(executor.map(fetch_data, [1, 2, 3, 4, 5]))

print(results)

এখানে কী হচ্ছে?

  1. ThreadPoolExecutor(max_workers=4) সর্বোচ্চ ৪টি worker thread-এর pool তৈরি করে।
  2. executor.map() task-গুলো submit করে এবং result iterator দেয়।
  3. Available worker threads task-গুলো execute করে।
  4. with block শেষ হলে executor shutdown করে এবং worker threads-এর cleanup করে।

submit() এবং Future

from concurrent.futures import ThreadPoolExecutor

def add(a, b):
    return a + b

with ThreadPoolExecutor(max_workers=2) as executor:
    future = executor.submit(add, 10, 20)

    result = future.result()

print(result)  # 30

submit() একটি Future object return করে। Future-এর মাধ্যমে asynchronous task-এর result পরে পাওয়া যায়।

  • future.result() result ready না হলে অপেক্ষা করে।
  • future.done() task শেষ হয়েছে কি না জানায়।
  • future.cancel() task এখনও শুরু না হলে cancel করার চেষ্টা করে।
Interview line: ThreadPoolExecutor is a high-level abstraction for running multiple tasks using a reusable pool of worker threads. It is particularly useful for I/O-bound workloads.
Important: Traditional GIL-enabled CPython-এ ThreadPoolExecutor CPU-bound pure-Python work-এর জন্য সাধারণত multi-core parallelism দেয় না।

সংক্ষিপ্ত উত্তর

Race condition হলো এমন একটি concurrency bug যেখানে program-এর correctness বা result execution-এর timing/interleaving-এর উপর নির্ভর করে। অর্থাৎ multiple threads একই shared state নিয়ে কাজ করার সময় কোন thread আগে কোন operation করছে তার উপর result বদলে যেতে পারে।

সহজ উদাহরণ

counter = 0

def increment():
    global counter
    counter += 1

দেখতে counter += 1 একটি single operation মনে হলেও shared mutable state-এর ক্ষেত্রে এটি conceptually read → calculate → write ধরনের একাধিক step জড়িত operation।

যদি দুইটি thread একই সময়ে একই value read করে এবং পরে দুটিই updated value write করে, তাহলে একটি increment হারিয়ে যেতে পারে।

সমস্যাটি কী?

Expected: 2 threads × 1000 increments = 2000

Possible problem: synchronization না থাকলে actual result নির্ভর করতে পারে thread interleaving-এর উপর।

Solution

Shared critical section-এর access synchronize করতে Lock ব্যবহার করা যায়। 

import threading

counter = 0
lock = threading.Lock()

def increment():
    global counter

    for _ in range(1000):
        with lock:
            counter += 1
Interview line: A race condition occurs when multiple concurrent execution paths access shared state and the final result depends on their timing or ordering.

সংক্ষিপ্ত উত্তর

threading.Lock হলো একটি mutual exclusion synchronization primitive। এক সময়ে একটি thread lock acquire করে critical section-এ ঢুকতে পারে। অন্য thread-গুলোকে lock release হওয়া পর্যন্ত অপেক্ষা করতে হয়।

Critical Section কী?

যে code অংশ shared resource/state access বা modify করে এবং concurrent execution-এর সময় synchronization দরকার, সেটিকে critical section বলা হয়। 

import threading

lock = threading.Lock()
counter = 0

def increment():
    global counter

    with lock:
        counter += 1

with lock কেন ভালো?

with lock: ব্যবহার করলে block-এর শেষে lock automatically release হয়, এমনকি block-এর ভিতরে exception হলেও। ফলে manual acquire()/release() ব্যবহারের তুলনায় resource cleanup safer হয়।

Manual version

lock.acquire()
try:
    # critical section
    counter += 1
finally:
    lock.release()

Lock কী solve করে?

  • Shared mutable state-এর concurrent access synchronize করে।
  • Critical section-এ mutual exclusion দেয়।
  • Race condition prevent করতে সাহায্য করে।
Important: Lock ব্যবহার করলেই সব concurrency problem solve হয় না। ভুল lock ordering বা lock ধরে রেখে অন্য resource-এর জন্য অপেক্ষা করলে deadlock তৈরি হতে পারে।
Interview line: A Lock provides mutual exclusion so that only one thread at a time can execute a protected critical section.

সংক্ষিপ্ত উত্তর

RLock বা Reentrant Lock এমন একটি lock যা একই thread একাধিকবার acquire করতে পারে, যতক্ষণ সেই thread প্রতিটি acquisition-এর জন্য corresponding release করে।

Normal Lock-এর সমস্যা

import threading

lock = threading.Lock()

def outer():
    with lock:
        inner()

def inner():
    with lock:
        print("Hello")

যদি একই thread outer()-এ lock acquire করার পর inner()-এ আবার একই non-reentrant Lock acquire করতে যায়, সেই thread নিজেই নিজের lock-এর জন্য অপেক্ষা করতে পারে।

RLock দিয়ে

import threading

lock = threading.RLock()

def outer():
    with lock:
        inner()

def inner():
    with lock:
        print("Hello")

এখানে একই thread দ্বিতীয়বার lock acquire করতে পারে। RLock internally ownership এবং recursion/acquisition count track করে।

মূল পার্থক্য

  • Lock: সাধারণ mutual exclusion lock; একই thread পুনরায় acquire করলে সমস্যা হতে পারে।
  • RLock: owning thread পুনরায় acquire করতে পারে।
  • RLock: যতবার acquire করা হয়েছে, matching number of release দরকার।
Interview line: RLock is useful when the same thread may need to acquire the same lock recursively, such as nested method calls that use the same synchronization lock.

সংক্ষিপ্ত উত্তর

Semaphore হলো এমন একটি synchronization primitive যা একই সময়ে একটি resource বা critical operation কতগুলো thread ব্যবহার করতে পারবে তার limit নির্ধারণ করে।

Lock বনাম Semaphore

Lock: সাধারণভাবে এক সময়ে ১টি thread critical section-এ প্রবেশ করে।

Semaphore: এক সময়ে নির্দিষ্ট সংখ্যক thread প্রবেশ করতে পারে।

Example

import threading
import time

semaphore = threading.Semaphore(2)

def worker(name):
    with semaphore:
        print(name, "entered")
        time.sleep(2)
        print(name, "leaving")

এখানে semaphore value 2, তাই একই সময়ে সর্বোচ্চ দুইটি thread protected section-এ থাকতে পারে।

কোথায় ব্যবহার করা যায়?

  • Limited number of concurrent network operations
  • Connection/resource pool-এর concurrency limit
  • External service-এর উপর request limit রাখা
  • Limited capacity resource protect করা
Interview line: A semaphore controls the number of threads that can simultaneously access a resource or enter a protected section.

সংক্ষিপ্ত উত্তর

threading.Event হলো thread synchronization-এর একটি signaling mechanism। একটি thread event set করে অন্য thread-গুলোকে signal দিতে পারে যে কোনো condition বা event ঘটেছে।

মূল methods

  • set() → event flag set করে।
  • clear() → event flag unset করে।
  • is_set() → event set আছে কি না check করে।
  • wait() → event set হওয়া পর্যন্ত অপেক্ষা করে।

Example

import threading
import time

event = threading.Event()

def worker():
    print("Waiting for signal...")
    event.wait()
    print("Signal received. Continuing.")

thread = threading.Thread(target=worker)
thread.start()

time.sleep(2)

print("Sending signal...")
event.set()

thread.join()

এখানে কী হচ্ছে?

  1. Worker thread event.wait()-এ অপেক্ষা করে।
  2. Main thread পরে event.set() call করে।
  3. Event set হওয়ায় waiting thread continue করতে পারে।
Interview line: Event is used when one or more threads need to wait for a signal from another thread.

সংক্ষিপ্ত উত্তর

threading.Condition হলো এমন synchronization primitive যা thread-কে কোনো shared state-এর একটি নির্দিষ্ট condition পূরণ না হওয়া পর্যন্ত wait করতে এবং condition পরিবর্তন হলে অন্য thread-কে notify করতে দেয়।

Event-এর সঙ্গে সম্পর্ক

Condition সাধারণত একটি lock-এর সঙ্গে কাজ করে এবং shared state-এর condition নিয়ে synchronization করার জন্য বেশি উপযোগী।

Producer-Consumer example

import threading

condition = threading.Condition()
items = []

def consumer():
    with condition:
        while not items:
            condition.wait()

        item = items.pop(0)
        print("Consumed:", item)

def producer():
    with condition:
        items.append("data")
        condition.notify()

এখানে কী হচ্ছে?

  1. Consumer condition-এর lock acquire করে।
  2. যদি items empty হয়, consumer wait() করে।
  3. wait() করার সময় Condition-এর associated lock release হয়।
  4. Producer item add করে এবং notify() call করে।
  5. Waiting consumer wake up হয়ে lock পুনরায় acquire করার চেষ্টা করে।
  6. তারপর condition আবার check করে এবং কাজ continue করে।

while কেন, if নয়?

Condition wait থেকে ফিরে আসার পর condition সত্যিই পূরণ হয়েছে কি না আবার check করা best practice। কারণ wake-up-এর পর অন্য thread state পরিবর্তন করে দিতে পারে।

Interview line: Condition allows threads to wait for a shared-state condition and allows another thread to notify waiting threads when the state changes.

সংক্ষিপ্ত উত্তর

Deadlock হলো এমন অবস্থা যেখানে দুই বা ততোধিক thread/process একে অপরের held resource release করার জন্য অপেক্ষা করতে থাকে এবং ফলে কেউই আর progress করতে পারে না।

Classic example

import threading

lock_a = threading.Lock()
lock_b = threading.Lock()

def thread_one():
    with lock_a:
        with lock_b:
            print("Thread one")

def thread_two():
    with lock_b:
        with lock_a:
            print("Thread two")

একটি execution scenario-তে Thread One যদি lock_a ধরে lock_b-এর জন্য অপেক্ষা করে এবং Thread Two যদি lock_b ধরে lock_a-এর জন্য অপেক্ষা করে, তাহলে দুই thread একে অপরের জন্য অপেক্ষা করতে পারে।

Deadlock-এর চারটি classic necessary conditions

  1. Mutual Exclusion: Resource একই সময়ে সীমিতভাবে একটি holder-এর জন্য available।
  2. Hold and Wait: একটি thread resource ধরে রেখে অন্য resource-এর জন্য অপেক্ষা করছে।
  3. No Preemption: Resource জোর করে holder-এর কাছ থেকে নেওয়া হচ্ছে না।
  4. Circular Wait: Thread/resource dependency-এর একটি cycle তৈরি হয়েছে।

Deadlock prevent করার উপায়

  • সব জায়গায় locks একই order-এ acquire করা।
  • একসাথে প্রয়োজনীয় locks acquire করার design ব্যবহার করা।
  • Lock ধরে রেখে দীর্ঘ blocking operation না করা।
  • প্রয়োজনে timeout-based acquisition ব্যবহার করা।
  • Lock hierarchy/design স্পষ্ট রাখা।
if lock_a.acquire(timeout=1):
    try:
        if lock_b.acquire(timeout=1):
            try:
                # work
                pass
            finally:
                lock_b.release()
    finally:
        lock_a.release()
Interview line: Deadlock occurs when threads are permanently blocked because each is waiting for a resource held by another.

সংক্ষিপ্ত উত্তর

Thread starvation হলো এমন অবস্থা যেখানে একটি thread দীর্ঘ সময় প্রয়োজনীয় CPU time, lock বা অন্য resource access পায় না, কারণ অন্য thread-গুলো বারবার সেই resource ব্যবহার করে বা scheduling-এর কারণে সেটি পিছিয়ে থাকে।

Deadlock থেকে পার্থক্য

Deadlock: Threads একে অপরের resource-এর জন্য এমনভাবে অপেক্ষা করে যে progress বন্ধ হয়ে যায়।

Starvation: একটি thread দীর্ঘ সময় resource বা execution opportunity না পেলেও অন্য threads progress করতে থাকে।

Lock-related starvation

ধরা যাক একটি shared lock নিয়ে অনেক threads প্রতিযোগিতা করছে। একটি thread বারবার lock পাওয়ার সুযোগ হারালে সেটি দীর্ঘ সময় অপেক্ষা করতে পারে।

Starvation-এর কারণ

  • Unfair resource allocation
  • একটি thread বারবার resource দখল করা
  • অতিরিক্ত contention
  • Priority/scheduling imbalance
  • Long-running critical sections

কীভাবে কমানো যায়?

  • Critical section ছোট রাখা।
  • Lock ধরে রেখে unnecessary I/O না করা।
  • Fairness-sensitive design ব্যবহার করা।
  • Resource acquisition-এর timeout এবং retry strategy carefully design করা।
  • অতিরিক্ত contention কমানো।
Interview line: Starvation means a thread is repeatedly or indefinitely denied the CPU or a needed resource while other threads continue making progress.

সংক্ষিপ্ত উত্তর

asyncio হলো Python-এর asynchronous programming framework, যা async/await এবং event loop ব্যবহার করে cooperative concurrency support করে।

এটি বিশেষভাবে অনেক I/O-bound operation efficiently manage করার জন্য উপযোগী।

Basic example

import asyncio

async def fetch_data(name):
    print(f"Starting {name}")
    await asyncio.sleep(1)
    print(f"Finished {name}")
    return name

async def main():
    results = await asyncio.gather(
        fetch_data("A"),
        fetch_data("B"),
        fetch_data("C"),
    )

    print(results)

asyncio.run(main())

এখানে কী হচ্ছে?

  1. async def একটি coroutine function তৈরি করে।
  2. await asynchronous operation-এর জন্য অপেক্ষা করার সময় event loop-কে অন্য ready task চালানোর সুযোগ দেয়।
  3. asyncio.gather() একাধিক awaitable-এর concurrent execution coordinate করে।
  4. asyncio.run() event loop-এর মাধ্যমে main() coroutine চালায়।

Threading বনাম asyncio

Threading: Multiple OS-level threads ব্যবহার করে; blocking I/O API-এর সঙ্গে কাজ করার সময় সুবিধাজনক হতে পারে।

asyncio: সাধারণত একটি event loop-এর মধ্যে cooperative concurrency ব্যবহার করে; async-compatible I/O library প্রয়োজন।

asyncio কি parallelism?

না, asyncio নিজে CPU-bound Python code-কে multiple CPU core-এ parallelভাবে execute করে না। এটি primarily concurrency model।

একটি coroutine যখন await করে এবং control event loop-এ ফেরত দেয়, তখন event loop অন্য ready coroutine চালাতে পারে।

CPU-bound কাজ asyncio-তে?

CPU-bound কাজ event loop-কে block করলে অন্য async tasks-ও progress করতে পারে না। CPU-heavy কাজের জন্য multiprocessing বা appropriate executor/worker strategy ব্যবহার করা হয়।

asyncio বনাম ThreadPoolExecutor

  • asyncio: async-native I/O workload-এর জন্য efficient concurrency model।
  • ThreadPoolExecutor: blocking/synchronous function-কে worker thread-এ চালানোর জন্য useful।
  • Async application-এ blocking function event loop-এ সরাসরি চালালে event loop block হতে পারে। সেই ক্ষেত্রে thread executor ব্যবহার করা যায়।
import asyncio
from concurrent.futures import ThreadPoolExecutor

def blocking_work():
    # blocking synchronous operation
    return "done"

async def main():
    loop = asyncio.get_running_loop()

    with ThreadPoolExecutor(max_workers=2) as executor:
        result = await loop.run_in_executor(
            executor,
            blocking_work
        )

    print(result)

asyncio.run(main())
Interview line: asyncio provides cooperative concurrency using an event loop and async/await, making it well suited to high-concurrency I/O-bound applications. It does not by itself provide CPU parallelism.
Important: Asyncio works best when the operations being awaited are actually asynchronous/non-blocking. A blocking synchronous call inside an async function can block the event loop.
