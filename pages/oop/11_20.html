Python OOP — Interview Questions 11–20

11What is Method Overriding in Python?

মূল ধারণা

Method Overriding ঘটে যখন subclass তার parent বা base class-এ থাকা method-এর একই নাম দিয়ে নিজের implementation define করে। Subclass-এর object দিয়ে method call করলে Python-এর method lookup order অনুযায়ী subclass-এর implementation আগে পাওয়া যায়। ফলে inherited behavior-এর পরিবর্তে subclass-এর behavior চলে।

কেন প্রয়োজন? Parent class-এ common/default behavior রাখা যায়, আর subclass-এ প্রয়োজন অনুযায়ী সেই behavior customize করা যায়—parent class-এর code edit না করেই।

Code Example

PYTHON 3 · OVERRIDING
class Notification:
    def send(self, message):
        return f"Sending generic notification: {message}"


class EmailNotification(Notification):
    def send(self, message):
        return f"Sending email: {message}"


class SMSNotification(Notification):
    def send(self, message):
        return f"Sending SMS: {message}"


email = EmailNotification()
sms = SMSNotification()

print(email.send("Hello"))
print(sms.send("Hello"))

Internal Working

  1. EmailNotification class Notification-কে inherit করেছে।
  2. EmailNotification-এ send() নিজস্বভাবে define করা আছে।
  3. email.send() call হলে Python instance-এর class থেকে method lookup শুরু করে।
  4. Subclass-এ method পাওয়া যাওয়ায় parent-এর send() call হয় না।

Parent-এর implementation-ও ব্যবহার করা

Override করা method-এর ভেতর super() দিয়ে পরবর্তী implementation call করা যায়। এটি শুধু direct parent-এ থেমে থাকে না; MRO অনুযায়ী next class-এ যায়।

USING super()
class BaseReport:
    def generate(self):
        return "Base report"


class SalesReport(BaseReport):
    def generate(self):
        base_result = super().generate()
        return base_result + " + Sales data"


print(SalesReport().generate())

Overriding vs Overloading

  • Overriding: Subclass parent-এর method-এর implementation replace বা extend করে।
  • Overloading: একই নামের function/method ভিন্ন parameter signature অনুযায়ী আলাদা implementation—এটি Java/C++-এর মতো traditional compile-time method overloading Python সরাসরি support করে না।

Python-এ default argument, *args/**kwargs, অথবা functools.singledispatch দিয়ে কিছু related behavior করা যায়; এগুলো traditional method overloading-এর সঙ্গে এক নয়।

Interview answer: Method overriding হলো subclass-এ inherited method-এর একই নাম দিয়ে নতুন implementation define করা। Subclass object দিয়ে call করলে MRO অনুযায়ী subclass-এর method আগে resolve হয়। Parent implementation দরকার হলে super() ব্যবহার করা যায়।
12What is Multiple Inheritance in Python?

মূল ধারণা

Multiple Inheritance হলো Python-এর এমন capability, যেখানে একটি class একাধিক base class inherit করতে পারে। ফলে subclass একাধিক parent class থেকে method ও attribute পেতে পারে।

PYTHON 3 · MULTIPLE INHERITANCE
class Camera:
    def take_photo(self):
        return "Photo captured"


class Phone:
    def make_call(self):
        return "Calling..."


class SmartPhone(Camera, Phone):
    pass


device = SmartPhone()
print(device.take_photo())
print(device.make_call())

SmartPhone একই সঙ্গে Camera এবং Phone-এর behavior ব্যবহার করতে পারে। এখানে দুই parent-এর method name আলাদা, তাই method lookup নিয়ে conflict হচ্ছে না।

Method name conflict হলে কী হয়?

দুই parent class-এ একই method name থাকলে কোন implementation আগে পাওয়া যাবে তা MRO নির্ধারণ করে। Class declaration-এ base class-এর order গুরুত্বপূর্ণ।

METHOD CONFLICT
class A:
    def show(self):
        return "A"


class B:
    def show(self):
        return "B"


class C(A, B):
    pass


print(C().show())  # A
print(C.mro())

Diamond Problem

Diamond problem হয় যখন দুটি class একই base class inherit করে এবং আরেকটি class ওই দুই class-কে inherit করে। তখন common ancestor-এর method কোন পথে এবং কতবার execute হবে—এ প্রশ্ন আসে। Python MRO এবং cooperative super() call দিয়ে method execution-এর একটি consistent order বজায় রাখে।

DIAMOND SHAPE
        A
       / \
      B   C
       \ /
        D

class A: pass
class B(A): pass
class C(A): pass
class D(B, C): pass

print(D.mro())

Multiple Inheritance-এর সতর্কতা

  • Parent class-গুলোর method name conflict হতে পারে।
  • Cooperative multiple inheritance-এ প্রতিটি class-এর super() ব্যবহার এবং compatible method signature গুরুত্বপূর্ণ।
  • অতিরিক্ত জটিল inheritance chain code বুঝতে কঠিন করতে পারে।
  • অনেক ক্ষেত্রে composition দিয়ে dependency রাখা সহজ হয়।
Interview answer: Multiple inheritance-এ একটি class একাধিক base class inherit করে। Python MRO দিয়ে method lookup order ঠিক করে। Diamond problem সামলাতে cooperative super() ও consistent method signature গুরুত্বপূর্ণ।
13What is MRO (Method Resolution Order)?

মূল ধারণা

MRO-এর পূর্ণরূপ Method Resolution Order। কোনো object-এর method বা attribute খোঁজার সময় Python class hierarchy-র কোন order অনুসরণ করবে, সেটিই MRO নির্ধারণ করে। Single inheritance-এ order সহজ; multiple inheritance-এ ambiguity এড়াতে MRO বিশেষ গুরুত্বপূর্ণ।

Simple Example

PYTHON 3 · MRO
class A:
    def show(self):
        return "A"


class B(A):
    def show(self):
        return "B"


class C(B):
    pass


print(C.mro())
print(C().show())  # B

C-তে show() নেই, তাই Python MRO অনুসরণ করে B-তে খুঁজে পায়।

Python কীভাবে MRO calculate করে?

Python multiple inheritance-এর MRO বের করতে C3 Linearization algorithm ব্যবহার করে। এর গুরুত্বপূর্ণ বৈশিষ্ট্য:

  • Local precedence order: Class declaration-এ base class-গুলোর order সম্মান করা হয়। যেমন class D(B, C)-তে B, C-এর আগে আসে।
  • Monotonicity: কোনো subclass-এর MRO-তে base class-গুলোর আগে থেকে নির্ধারিত relative order অকারণে উল্টে যায় না।
  • একবারের linear order: Diamond hierarchy-তে shared ancestor MRO list-এ একবারই থাকে।

Diamond Example ও MRO

C3 LINEARIZATION EXAMPLE
class A: pass
class B(A): pass
class C(A): pass
class D(B, C): pass

print([cls.__name__ for cls in D.mro()])
# ['D', 'B', 'C', 'A', 'object']

এই output-এর অর্থ: প্রথমে D, এরপর B, তারপর C, এরপর common base A, সবশেষে root class object lookup order-এ থাকে।

Inconsistent MRO

যদি base class-গুলোর order এমন হয় যে C3 algorithm consistent linear order তৈরি করতে না পারে, Python class definition-এর সময় TypeError: Cannot create a consistent method resolution order (MRO) raise করে।

MRO দেখার উপায়

  • MyClass.mro() — class list return করে।
  • MyClass.__mro__ — MRO tuple হিসেবে পাওয়া যায়।
  • help(MyClass) — class help output-এ MRO দেখা যায়।
Interview answer: MRO হলো Python-এর method lookup order। Multiple inheritance-এ Python C3 Linearization algorithm দিয়ে MRO তৈরি করে। ClassName.mro() বা ClassName.__mro__ দিয়ে এটি দেখা যায়।
14What is super() in Python?

মূল ধারণা

super() Python-এর built-in function, যা current class-এর MRO অনুযায়ী পরবর্তী class-এর method বা attribute access করতে সাহায্য করে। এটি parent class-কে hardcode করে call করার চেয়ে flexible, বিশেষ করে multiple inheritance-এ।

Single Inheritance Example

PYTHON 3 · super()
class Person:
    def __init__(self, name):
        self.name = name


class Developer(Person):
    def __init__(self, name, language):
        super().__init__(name)
        self.language = language


dev = Developer("Anik", "Python")
print(dev.name)
print(dev.language)

Developer-এর initializer প্রথমে super().__init__(name) call করে। ফলে MRO অনুযায়ী পরবর্তী class-এর initializer চলে এবং name set হয়। তারপর subclass তার নিজস্ব language set করে।

super() কি সরাসরি parent class call করে?

সবসময় নয়। এটি current class-এর পরে MRO-তে যে class আসে, তার method lookup করে। Simple single inheritance-এ সেটি সাধারণত parent class। Multiple inheritance-এ next class অন্য branch-এর class-ও হতে পারে।

Cooperative Multiple Inheritance

COOPERATIVE super() CHAIN
class A:
    def process(self):
        print("A")
        super().process()


class B(A):
    def process(self):
        print("B")
        super().process()


class C:
    def process(self):
        print("C")
        super().process()


class D(B, C):
    def process(self):
        print("D")
        super().process()


D().process()

এই উদাহরণে D → B → A → C → object MRO তৈরি হয় না; প্রকৃত MRO হলো D → B → A → C → object কেবল তখনই, যদি A-এর base C হয়। উপরকার class definition-এ A এবং C দুইটিই independent base হওয়ায় D(B, C)-এর MRO হবে D, B, A, C, object। কিন্তু A.process() থেকে super().process() call করলে পরবর্তী class C-এর method চলে। C-এর পর object-এ process নেই, তাই chain-এর শেষ call-এ AttributeError হবে। এটি দেখায় কেন cooperative chain-এ root termination design করতে হয়।

নিচের safer version-এ root class chain শেষ করে:

SAFE COOPERATIVE PATTERN
class Root:
    def process(self):
        pass


class A(Root):
    def process(self):
        print("A")
        super().process()


class B(A):
    def process(self):
        print("B")
        super().process()


class C(Root):
    def process(self):
        print("C")
        super().process()


class D(B, C):
    def process(self):
        print("D")
        super().process()


D().process()  # D, B, A, C

এখানে MRO হলো D → B → A → C → Root → object। প্রতিটি implementation একবার করে chain-এ অংশ নেয়।

super() ব্যবহারের নিয়ম

  • একটি inheritance hierarchy-তে cooperative behavior চাইলে method-গুলোতে consistentভাবে super() ব্যবহার করতে হয়।
  • Multiple inheritance-এ method signature compatible রাখা জরুরি; প্রয়োজন হলে *args/**kwargs দিয়ে arguments forward করা যায়।
  • Parent class-কে সরাসরি Parent.method(self) দিয়ে call করলে MRO-based cooperation bypass হতে পারে।
Interview answer: super() MRO অনুযায়ী current class-এর পরবর্তী class-এর implementation access করে। এটি single inheritance-এ parent method call করতে এবং multiple inheritance-এ cooperative method chain তৈরি করতে ব্যবহৃত হয়।
15What are Magic / Dunder Methods in Python?

মূল ধারণা

Magic methods বা dunder methods হলো Python-এর special method, যাদের নামের শুরু ও শেষে double underscore থাকে—যেমন __init__, __str__, __len__। এগুলো Python-এর built-in syntax ও operation-এর সঙ্গে custom object-এর behavior যুক্ত করে। “Dunder” এসেছে “double underscore” থেকে।

কিছু গুরুত্বপূর্ণ Dunder Method

  • __new__ — নতুন instance তৈরি করে।
  • __init__ — তৈরি হওয়া instance initialize করে।
  • __str__ — user-friendly string representation দেয়।
  • __repr__ — developer/debugging-oriented representation দেয়।
  • __len__ — len(obj) operation support করে।
  • __eq__ — == comparison-এর behavior define করে।
  • __lt__ — < comparison-এর behavior define করে।
  • __add__ — + operation-এর behavior define করে।
  • __iter__ ও __next__ — iteration protocol implement করে।
  • __enter__ ও __exit__ — context manager protocol implement করে।
  • __getitem__ — obj[key] indexing behavior define করে।
  • __call__ — object-কে function-এর মতো call করার সুযোগ দেয়।

Example: len(), + এবং callable object

PYTHON 3 · SPECIAL METHODS
class Cart:
    def __init__(self, items):
        self.items = items

    def __len__(self):
        return len(self.items)

    def __add__(self, other):
        if not isinstance(other, Cart):
            return NotImplemented
        return Cart(self.items + other.items)


cart1 = Cart(["Book", "Pen"])
cart2 = Cart(["Laptop"])

print(len(cart1))       # 2
combined = cart1 + cart2
print(combined.items)   # ['Book', 'Pen', 'Laptop']

Python syntax-এর সঙ্গে সম্পর্ক

len(cart1) call করলে Python length protocol ব্যবহার করে, যেখানে __len__() method কাজ করে। একইভাবে cart1 + cart2 expression addition protocol ব্যবহার করে এবং উপযুক্ত ক্ষেত্রে __add__() invoke করে। Special method সাধারণত সরাসরি call করার বদলে সংশ্লিষ্ট built-in syntax ব্যবহার করাই ভালো।

গুরুত্বপূর্ণ সতর্কতা

  • __len__() non-negative integer return করবে; ভুল return type হলে TypeError হতে পারে।
  • __bool__() define না থাকলে truth testing-এ Python __len__() ব্যবহার করতে পারে।
  • সব dunder method implement করা জরুরি নয়; প্রয়োজনীয় protocol-ই implement করা উচিত।
  • Special method lookup-এর কিছু অংশ type/class level-এ হয়; instance-এ একই নামে attribute বসালেই সব special syntax সেটি ব্যবহার করবে—এমন নয়।
Interview answer: Dunder methods হলো Python-এর special protocol methods, যা custom object-কে built-in operation ও syntax-এর সঙ্গে কাজ করতে দেয়। যেমন __len__ দিয়ে len(), __add__ দিয়ে +, এবং __iter__ দিয়ে iteration support করা যায়।
16__str__ vs __repr__ — পার্থক্য কী?

মূল ধারণা

__str__() object-এর readable বা user-friendly string representation তৈরি করে। __repr__() debugging এবং developer inspection-এর জন্য unambiguous representation দেওয়ার চেষ্টা করে। সম্ভব হলে repr(obj) এমন string দেবে, যা object-টি পুনরায় তৈরি করতে পারে—তবে এটি সব class-এর জন্য সম্ভব বা বাধ্যতামূলক নয়।

Code Example

PYTHON 3 · STR VS REPR
class User:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def __str__(self):
        return f"{self.name} ({self.age} years old)"

    def __repr__(self):
        return f"User(name={self.name!r}, age={self.age!r})"


user = User("Anik", 27)

print(str(user))
print(repr(user))
print(user)

কোন built-in কোথায় কোনটি ব্যবহার করে?

  • str(obj) সাধারণত obj.__str__() ব্যবহার করে।
  • repr(obj) obj.__repr__() ব্যবহার করে।
  • print(obj) string conversion করে, তাই সাধারণত __str__() ব্যবহার হয়।
  • Interactive interpreter-এ expression evaluate করে result display করার সময় সাধারণত repr() ব্যবহার হয়।
  • List বা dict-এর মতো container-এর representation তৈরি করার সময় element-গুলোর জন্য সাধারণত repr() ব্যবহার হয়।

শুধু __repr__ থাকলে?

Class-এ __str__() define না থাকলে str(obj) fallback হিসেবে __repr__() ব্যবহার করে। তাই অনেক class-এ ভালো __repr__() থাকাই useful baseline।

REPR FALLBACK
class Product:
    def __repr__(self):
        return "Product()"

product = Product()
print(str(product))   # Product()
print(repr(product))  # Product()
Security note: __repr__()-এ password, API token বা sensitive data রাখা উচিত নয়। Debugging output log-এ চলে যেতে পারে।
Interview answer: __str__ user-friendly display-এর জন্য, আর __repr__ developer-facing, debugging-oriented representation-এর জন্য। __str__ না থাকলে str() সাধারণত __repr__-এ fallback করে।
17What are Properties in Python?

মূল ধারণা

Python property হলো এমন একটি mechanism, যার মাধ্যমে method-কে attribute-এর মতো access করা যায়। এর সাহায্যে attribute read, write বা delete করার সময় custom logic চালানো যায়—কিন্তু caller-এর syntax attribute access-এর মতোই থাকে। Property descriptor protocol-এর উপর ভিত্তি করে কাজ করে।

কেন Property দরকার?

ধরা যাক প্রথমে class-এ age একটি normal public attribute। পরে age-এর value validate করা দরকার হলো। সব caller-এর code-এ set_age() call যোগ না করেও property দিয়ে existing attribute-style API বজায় রেখে validation যোগ করা যায়।

PYTHON 3 · PROPERTY
class Person:
    def __init__(self, age):
        self.age = age

    @property
    def age(self):
        return self._age

    @age.setter
    def age(self, value):
        if value < 0:
            raise ValueError("Age cannot be negative")
        self._age = value

    @age.deleter
    def age(self):
        del self._age


person = Person(25)
print(person.age)  # getter
person.age = 26     # setter
del person.age     # deleter

Getter, Setter, Deleter

  • Getter: person.age read করলে age() getter execute হয়।
  • Setter: person.age = 26 করলে setter execute হয়।
  • Deleter: del person.age করলে deleter execute হয়।

Property-এর সুবিধা

  • Validation এক জায়গায় রাখা যায়।
  • Read-only বা computed attribute তৈরি করা যায়।
  • Public API attribute-style রাখা যায়, কিন্তু internal logic method-এ থাকে।
  • পরে implementation পরিবর্তন করলেও caller-এর access syntax একই রাখা যায়।
Common mistake: Getter-এর ভেতরে return self.age লিখলে property নিজেকেই আবার call করবে এবং recursion হতে পারে। তাই internal storage হিসেবে self._age ব্যবহার করা হয়েছে।
Interview answer: Property method-কে attribute-style interface দেয়। @property, @name.setter এবং @name.deleter দিয়ে read, write ও delete operation-এর custom logic define করা যায়।
18What is @property in Python?

মূল ধারণা

@property হলো built-in property descriptor তৈরি করার decorator syntax। এটি কোনো method-কে এমন attribute-এ পরিণত করে, যেটি read করার সময় method-এর code execute করে। Method call-এর জন্য parentheses লাগে না।

Basic Example: Computed Attribute

PYTHON 3 · @property
class Rectangle:
    def __init__(self, width, height):
        self.width = width
        self.height = height

    @property
    def area(self):
        return self.width * self.height


rectangle = Rectangle(10, 5)
print(rectangle.area)  # 50

area কোনো stored instance variable নয়। এটি width ও height থেকে calculate করা হচ্ছে। তবুও ব্যবহার হচ্ছে rectangle.area—rectangle.area() নয়।

Read-only Property

শুধু @property define করলে এবং setter না দিলে property সাধারণত read-only থাকে। Attribute-এ assign করার চেষ্টা করলে AttributeError হবে।

READ-ONLY PROPERTY
class Circle:
    def __init__(self, radius):
        self.radius = radius

    @property
    def diameter(self):
        return self.radius * 2


circle = Circle(5)
print(circle.diameter)  # 10
# circle.diameter = 20  # AttributeError

@property internalভাবে কী?

Python-এ property একটি built-in descriptor type। Class body-তে @property ব্যবহার করলে function-টি property object দিয়ে replace হয়। Instance থেকে attribute read করার সময় descriptor protocol-এর মাধ্যমে getter execute হয়। Setter যোগ করলে property object-এর write behavior-ও define হয়।

@property বনাম normal method

  • obj.calculate_total() — operation/function call বোঝায়।
  • obj.total — attribute access বোঝায়; value calculate হলেও access syntax attribute-এর মতো।

Property-তে খুব expensive কাজ, database query বা network request লুকিয়ে রাখা ভালো design নয়। Attribute access সাধারণত lightweight ও predictable হওয়া উচিত।

Interview answer: @property method-কে attribute-এর মতো access করতে দেয়। এটি computed value, validation এবং read-only interface তৈরিতে useful। এটি Python-এর descriptor mechanism-এর উপর কাজ করে।
19What are Abstract Base Classes (ABC) in Python?

মূল ধারণা

Abstract Base Class (ABC) হলো এমন base class, যা subclass-গুলোর জন্য common interface বা contract define করতে পারে। abc module-এর ABC এবং @abstractmethod দিয়ে abstract method define করা যায়। Abstract method implement না করা concrete subclass instantiate করা যায় না।

Code Example

PYTHON 3 · ABC
from abc import ABC, abstractmethod


class Storage(ABC):
    @abstractmethod
    def save(self, data):
        pass

    @abstractmethod
    def load(self, key):
        pass


class FileStorage(Storage):
    def save(self, data):
        return "Saved to file"

    def load(self, key):
        return f"Loaded {key} from file"


storage = FileStorage()
print(storage.save("hello"))

কেন ABC দরকার?

  • একাধিক implementation-এর জন্য একই interface enforce করতে।
  • Incomplete subclass যেন ভুল করে instantiate না হয়, তা আটকাতে।
  • High-level code-কে concrete implementation-এর বদলে abstraction-এর উপর নির্ভর করাতে।
  • Team/project-এ class contract readable ও enforceable রাখতে।

Abstract method-এর implementation-ও থাকতে পারে?

হ্যাঁ। Abstract method-এর body থাকতে পারে। Subclass-কে method override করতে হয়, তবে override করা method-এর ভেতর super() দিয়ে abstract base method-এর implementation reuse করা যায়।

ABC vs Duck Typing

  • ABC: Explicit inheritance বা virtual subclass registration-এর মাধ্যমে type relationship declare করা যায় এবং abstract method implementation-এর নিয়ম enforce করা যায়।
  • Duck Typing: Object প্রয়োজনীয় operation support করলেই ব্যবহার করা হয়; নির্দিষ্ট base class inherit করা আবশ্যক নয়।

ABC vs Protocol

typing.Protocol structural typing-এর জন্য ব্যবহৃত হয়। কোনো class Protocol inherit না করেও প্রয়োজনীয় method/attribute implement করলে static type checker সেটিকে compatible ধরতে পারে। ABC সাধারণত explicit runtime class hierarchy এবং abstract method enforcement-এর জন্য; Protocol static structural contract প্রকাশে useful। Python-এ @runtime_checkable Protocol-এর কিছু runtime check support করে, তবে সেটি পূর্ণ static type checking-এর বিকল্প নয়।

Interview answer: ABC হলো abc module দিয়ে তৈরি abstract base class, যা subclass-এর জন্য interface/contract define করে। @abstractmethod implement না করলে concrete subclass instantiate করা যায় না। ABC explicit contract enforcement-এ useful।
20What are SOLID Principles in Python?

মূল ধারণা

SOLID হলো object-oriented software design-এর পাঁচটি principle-এর acronym। এগুলোর লক্ষ্য code-কে maintainable, extensible এবং change-friendly রাখা। SOLID কোনো Python-only feature নয়; Python-সহ বিভিন্ন OOP language-এ design guideline হিসেবে ব্যবহার করা যায়।

S — Single Responsibility Principle
একটি class/module-এর change করার একটি প্রধান কারণ থাকা উচিত। অর্থাৎ একটি class-এ একাধিক unrelated responsibility জমা করা উচিত নয়।

S — Single Responsibility Principle (SRP)

ধরা যাক Invoice class invoice calculation, PDF generation এবং email sending—সব কাজ করছে। PDF format বা email provider change হলেও class edit করতে হচ্ছে। আলাদা responsibility আলাদা class-এ রাখলে change-এর impact কমে।

SRP EXAMPLE
class Invoice:
    def total(self, items):
        return sum(items)


class InvoicePrinter:
    def print_invoice(self, invoice):
        print(f"Total: {invoice}")


class InvoiceRepository:
    def save(self, invoice):
        print("Invoice saved")
O — Open/Closed Principle
Software entity extension-এর জন্য open, কিন্তু existing tested code modification-এর প্রয়োজন কম—এমন design হওয়া উচিত। নতুন behavior যোগ করতে গিয়ে বারবার পুরনো code edit না করে abstraction বা polymorphism ব্যবহার করা যায়।

O — Open/Closed Principle (OCP)

নতুন discount type যোগ করতে প্রতিবার বড় if/elif block edit করার বদলে common interface ও আলাদা strategy class ব্যবহার করা যায়।

OCP · STRATEGY STYLE
from abc import ABC, abstractmethod


class Discount(ABC):
    @abstractmethod
    def apply(self, price):
        pass


class NoDiscount(Discount):
    def apply(self, price):
        return price


class TenPercentDiscount(Discount):
    def apply(self, price):
        return price * 0.90


class Checkout:
    def __init__(self, discount):
        self.discount = discount

    def total(self, price):
        return self.discount.apply(price)


checkout = Checkout(TenPercentDiscount())
print(checkout.total(1000))  # 900.0
L — Liskov Substitution Principle
যে জায়গায় base class-এর object ব্যবহার করা যায়, সেখানে তার subtype object বসালেও program-এর expected behavior ভেঙে যাওয়া উচিত নয়। Subclass-কে base class-এর contract মানতে হবে।

L — Liskov Substitution Principle (LSP)

যদি Bird class-এ সব bird-এর জন্য fly() বাধ্যতামূলক করা হয়, তাহলে Penguin-এর মতো উড়তে না-পারা bird subclass design-এ সমস্যা তৈরি করবে। Base abstraction ভুলভাবে তৈরি হয়েছে।

LSP-FRIENDLY DESIGN
class Bird:
    def move(self):
        raise NotImplementedError


class FlyingBird(Bird):
    def fly(self):
        return "Flying"


class Sparrow(FlyingBird):
    def move(self):
        return self.fly()


class Penguin(Bird):
    def move(self):
        return "Swimming or walking"

এখানে সব Bird-এর common behavior move() রাখা হয়েছে; শুধু flying capability যাদের আছে তারা FlyingBird inherit করে। বাস্তব design-এ capability-based interface বা composition আরও উপযুক্ত হতে পারে।

I — Interface Segregation Principle
Client-কে এমন method-এর উপর depend করানো উচিত নয়, যেগুলো তার প্রয়োজন নেই। একটি বড় interface-এর বদলে ছোট ও focused interface ভালো।

I — Interface Segregation Principle (ISP)

একটি interface-এ print(), scan(), fax() সব বাধ্যতামূলক থাকলে শুধু print করতে পারে এমন device-কে অপ্রয়োজনীয় method implement করতে হবে। ছোট interface করলে এই সমস্যা এড়ানো যায়।

ISP EXAMPLE
from abc import ABC, abstractmethod


class Printer(ABC):
    @abstractmethod
    def print_document(self, document):
        pass


class Scanner(ABC):
    @abstractmethod
    def scan(self):
        pass


class BasicPrinter(Printer):
    def print_document(self, document):
        return "Printing document"
D — Dependency Inversion Principle
High-level module যেন low-level concrete implementation-এর উপর সরাসরি depend না করে। দুটিই abstraction-এর উপর depend করবে। Abstraction যেন detail-এর উপর depend না করে; detail abstraction-এর উপর depend করবে।

D — Dependency Inversion Principle (DIP)

Checkout class যদি সরাসরি StripePayment instantiate করে, তাহলে payment provider change করতে Checkout code edit করতে হবে। এর বদলে payment interface-এর উপর depend করালে constructor দিয়ে dependency inject করা যায়।

DIP · DEPENDENCY INJECTION
from abc import ABC, abstractmethod


class PaymentProcessor(ABC):
    @abstractmethod
    def pay(self, amount):
        pass


class CardPayment(PaymentProcessor):
    def pay(self, amount):
        return f"Card payment: {amount}"


class MobilePayment(PaymentProcessor):
    def pay(self, amount):
        return f"Mobile payment: {amount}"


class Checkout:
    def __init__(self, processor: PaymentProcessor):
        self.processor = processor

    def complete(self, amount):
        return self.processor.pay(amount)


checkout = Checkout(CardPayment())
print(checkout.complete(1500))

SOLID একসঙ্গে কীভাবে কাজ করে?

  • SRP class-এর responsibility সীমিত রাখে।
  • OCP নতুন behavior যোগ করার সময় existing code change কমায়।
  • LSP subtype যেন base contract ভঙ্গ না করে তা নিশ্চিত করে।
  • ISP ছোট ও focused interface তৈরি করে।
  • DIP concrete class-এর বদলে abstraction-এর উপর dependency তৈরি করে।

Python-এ SOLID প্রয়োগের সময় মনে রাখার বিষয়

Python dynamic language; সব জায়গায় ABC বা বড় class hierarchy দরকার হয় না। Duck typing, Protocol, functions, composition এবং dependency injection দিয়েও SOLID-এর লক্ষ্য অর্জন করা যায়। SOLID checklist হিসেবে ব্যবহার করা উচিত, অকারণে abstraction বা class বাড়ানোর নিয়ম হিসেবে নয়।

Interview answer: SOLID হলো পাঁচটি OOP design principle: Single Responsibility, Open/Closed, Liskov Substitution, Interface Segregation এবং Dependency Inversion। এগুলো class-এর responsibility, extension, substitutability, interface size এবং dependency design উন্নত করতে সাহায্য করে।
