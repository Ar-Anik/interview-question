11What is Method Overriding in Python?

1. Concept — Method Overriding কী?

Method Overriding ঘটে যখন একটি subclass, তার parent/base class-এ থাকা কোনো instance method-এর একই নাম ব্যবহার করে নিজের implementation define করে। Subclass-এর object দিয়ে method call করলে Python-এর attribute lookup subclass থেকে শুরু হয়। তাই subclass-এ method পাওয়া গেলে সেটিই execute হয়।

কেন দরকার?
Parent class-এ common/default behavior রাখা যায়। কিন্তু child class-এর behavior আলাদা হলে child class-এ method override করা যায়। এতে parent class-এর code পরিবর্তন না করেই subclass-specific behavior পাওয়া যায়।

2. Practical Example

একটি notification system-এ সব notification-এর কাজ হলো message পাঠানো। কিন্তু Email এবং SMS পাঠানোর process এক নয়। তাই parent class-এ generic send() এবং child class-এ আলাদা implementation রাখা যায়।

PYTHON 3 · METHOD OVERRIDING 
class Notification:
    def send(self, message):
        return f"Generic notification: {message}"


class EmailNotification(Notification):
    def send(self, message):
        return f"Email sent: {message}"


class SMSNotification(Notification):
    def send(self, message):
        return f"SMS sent: {message}"


email = EmailNotification()
sms = SMSNotification()

print(email.send("Hello"))
print(sms.send("Hello"))

3. Internal Working — call হলে কী ঘটে?

  1. EmailNotification class Notification inherit করেছে।
  2. EmailNotification-এর ভেতরে নিজস্ব send() method আছে।
  3. email.send("Hello") call হলে Python প্রথমে EmailNotification-এ send খোঁজে।
  4. Method পাওয়া যায়, তাই parent class-এর send() আর খোঁজা হয় না।
  5. ফলে Email-এর implementation execute হয়।
email.send()→EmailNotification.send()→Return

4. Parent method-ও ব্যবহার করতে হলে

Subclass-এর implementation-এর পাশাপাশি পরবর্তী implementation-ও call করতে super() ব্যবহার করা যায়।

OVERRIDE + super() 
class BaseReport:
    def generate(self):
        return "Base report"


class SalesReport(BaseReport):
    def generate(self):
        base_result = super().generate()
        return base_result + " + Sales data"


print(SalesReport().generate())
# Base report + Sales data

5. Overriding vs Overloading

OverridingOverloading
Subclass parent method-এর implementation নতুন করে define করে।একই নামের method ভিন্ন parameter signature অনুযায়ী একাধিক implementation দেয়।
Inheritance-এর সঙ্গে সম্পর্কিত।Traditional compile-time method overloading Python সরাসরি Java/C++-এর মতো support করে না।

Python-এ default arguments, *args/**kwargs বা functools.singledispatch দিয়ে related behavior করা যায়; এগুলো traditional method overloading-এর সমান নয়।

Interview Answer: Method overriding হলো subclass-এ parent class-এর inherited method-এর একই নাম দিয়ে নতুন implementation define করা। Subclass object দিয়ে call করলে method lookup subclass থেকে শুরু হয়। Parent implementation reuse করতে super() ব্যবহার করা যায়।
12What is Multiple Inheritance in Python?

1. Concept — Multiple Inheritance কী?

Multiple Inheritance হলো এমন একটি OOP feature যেখানে একটি class একাধিক base class inherit করতে পারে। ফলে child class একাধিক parent class-এর method এবং attribute access করতে পারে। Python সরাসরি এই feature support করে।

2. Practical Example

একটি smartphone-এ phone-এর calling feature এবং camera-এর photo capture feature—দুটিই আছে। আলাদা class-এ behavior রেখে Smartphone class-এ দুইটিই inherit করা যায়।

PYTHON 3 · MULTIPLE INHERITANCE 
class Camera:
    def take_photo(self):
        return "Photo captured"


class Phone:
    def make_call(self):
        return "Calling..."


class SmartPhone(Camera, Phone):
    pass


device = SmartPhone()
print(device.take_photo())
print(device.make_call())

SmartPhone(Camera, Phone) লেখার অর্থ SmartPhone দুইটি base class inherit করছে। এখানে pass মানে class body-তে নতুন কোনো statement নেই; inherited method-গুলো তবুও ব্যবহার করা যাবে।

3. Same method name থাকলে কী হয়?

দুই parent class-এ একই method থাকলে Python class definition-এ দেওয়া base class order এবং MRO অনুসারে method খুঁজবে।

METHOD NAME CONFLICT 
class A:
    def show(self):
        return "A"


class B:
    def show(self):
        return "B"


class C(A, B):
    pass


print(C().show())  # A
print(C.mro())

C(A, B)-তে MRO অনুযায়ী A, B-এর আগে। তাই C().show() call-এ A-এর method পাওয়া যায়। এটি “সবসময় প্রথম parent-ই call হবে” এমন আলাদা rule নয়; এটি MRO lookup-এর Result।

4. Diamond Problem

Diamond problem হয় যখন দুটি intermediate class একই base class inherit করে, তারপর আরেকটি class ওই দুই intermediate class inherit করে।

A↙↘BC↘↙D
DIAMOND INHERITANCE 
class A: pass
class B(A): pass
class C(A): pass
class D(B, C): pass

print([cls.__name__ for cls in D.mro()])
# ['D', 'B', 'C', 'A', 'object']

Python-এর C3 MRO shared ancestor A-কে lookup order-এ একবার রাখে। তবে method chain-এ প্রতিটি class-এর implementation execute হবে কি না, তা method-গুলো super() call করছে কি না তার উপর নির্ভর করে।

5. কখন সতর্ক থাকতে হবে?

  • একই method name থাকলে lookup order বুঝতে হবে।
  • Cooperative multiple inheritance-এ method signature compatible রাখা জরুরি।
  • প্রতিটি participating method-এ consistent super() chain দরকার হতে পারে।
  • Inheritance graph অতিরিক্ত জটিল হলে composition বেশি সহজ হতে পারে।
Interview Answer: Multiple inheritance-এ একটি class একাধিক base class inherit করে। Python MRO দিয়ে method lookup-এর order ঠিক করে। Diamond hierarchy-তে C3 Linearization consistent lookup order তৈরি করে; cooperative super() method chain চালাতে সাহায্য করে।
13What is MRO (Method Resolution Order)?

1. Concept — MRO কী?

MRO-এর পূর্ণরূপ Method Resolution Order। কোনো class-এর object দিয়ে method বা attribute access করলে Python কোন order-এ class hierarchy-তে সেটি খুঁজবে, সেই নির্ধারিত order-ই MRO। Single inheritance-এ lookup সাধারণত child থেকে parent-এর দিকে যায়। Multiple inheritance-এ একাধিক সম্ভাব্য path থাকায় MRO খুব গুরুত্বপূর্ণ।

2. Simple Example

MRO · SINGLE INHERITANCE 
class A:
    def show(self):
        return "A"


class B(A):
    def show(self):
        return "B"


class C(B):
    pass


print([cls.__name__ for cls in C.mro()])
# ['C', 'B', 'A', 'object']
print(C().show())  # B

C-তে show() নেই। Python প্রথমে C-তে খুঁজে পায় না, এরপর B-তে পায়। তাই B-এর method execute হয়। A-তে একই নামের method থাকলেও lookup B-তে method পাওয়ার পর আর A পর্যন্ত যায় না।

3. Multiple Inheritance-এ MRO

C3 LINEARIZATION EXAMPLE 
class A: pass
class B(A): pass
class C(A): pass
class D(B, C): pass

print([cls.__name__ for cls in D.mro()])
# ['D', 'B', 'C', 'A', 'object']

Lookup order:

D→B→C→A→object

অর্থাৎ method খোঁজার সময় Python প্রথমে D, তারপর B, এরপর C, তারপর shared base A এবং শেষে object class check করে। যে class-এ attribute প্রথম পাওয়া যায়, lookup সেখানেই থামে।

4. Python কীভাবে MRO তৈরি করে?

Python multiple inheritance-এর জন্য C3 Linearization algorithm ব্যবহার করে। এটি এমন একটি order তৈরি করে, যা inheritance hierarchy-এর base class ordering বজায় রাখে এবং consistent lookup নিশ্চিত করে।

  • Local precedence order: class D(B, C) হলে B, C-এর আগে থাকবে।
  • Monotonicity: কোনো class-এর existing relative order subclass-এর MRO-তে অকারণে উল্টে যায় না।
  • Shared ancestor once: Diamond hierarchy-তে common ancestor MRO list-এ একবার থাকে।

5. Inconsistent MRO

Base class-গুলোর inheritance order যদি পরস্পরবিরোধী হয় এবং C3 algorithm valid linear order তৈরি করতে না পারে, Python class তৈরি করার সময় TypeError raise করে।

6. MRO দেখার উপায়

INSPECT MRO 
MyClass.mro()       # list return করে
MyClass.__mro__     # tuple return করে
help(MyClass)       # help output-এ MRO দেখায়
Interview Answer: MRO হলো Python-এর method lookup order। Multiple inheritance-এ Python C3 Linearization algorithm দিয়ে MRO calculate করে। ClassName.mro() অথবা ClassName.__mro__ দিয়ে order দেখা যায়।
14What is super() in Python?

1. Concept — super() কী?

super() হলো Python-এর built-in function। এটি current class-এর context থেকে MRO-তে পরবর্তী class-এর method বা attribute access করতে সাহায্য করে। Single inheritance-এ পরবর্তী class সাধারণত parent class হয়। Multiple inheritance-এ সেটি অন্য branch-এর class-ও হতে পারে।

খুব গুরুত্বপূর্ণ: super() মানেই “সরাসরি parent class” নয়। সঠিক ধারণা হলো: current class-এর পর MRO-তে যে class আসে, super() সেখান থেকে lookup শুরু করে।

2. Single Inheritance Example

PYTHON 3 · super() 
class Person:
    def __init__(self, name):
        self.name = name


class Developer(Person):
    def __init__(self, name, language):
        super().__init__(name)
        self.language = language


dev = Developer("Anik", "Python")
print(dev.name)      # Anik
print(dev.language)  # Python

3. Execution Flow

  1. Developer(...) call হলে Developer-এর __init__() execute হয়।
  2. super().__init__(name) MRO-তে Developer-এর পরের class Person-এর initializer call করে।
  3. Person-এর initializer self.name set করে।
  4. Control Developer-এর initializer-এ ফিরে আসে এবং self.language set হয়।
Developer.__init__→Person.__init__→Developer continues

4. Multiple Inheritance-এ super() chain

এখানে একটি Root class chain-এর শেষ ধাপ। A, B, C এবং D প্রত্যেকেই super() call করছে। ফলে MRO অনুযায়ী প্রতিটি implementation একবার করে execute হয়।

COOPERATIVE MULTIPLE INHERITANCE 
class Root:
    def process(self):
        pass


class A(Root):
    def process(self):
        print("A")
        super().process()


class B(A):
    def process(self):
        print("B")
        super().process()


class C(Root):
    def process(self):
        print("C")
        super().process()


class D(B, C):
    def process(self):
        print("D")
        super().process()


print([cls.__name__ for cls in D.mro()])
D().process()
# MRO: D -> B -> A -> C -> Root -> object
# Output: D, B, A, C

কেন এই order? D-এর MRO হলো D, B, A, C, Root, object। D-এর super() B-তে যায়; B-এর super() A-তে; A-এর super() C-তে; C-এর super() Root-এ যায়। Root chain শেষ করে।

5. Cooperative super() ব্যবহারের শর্ত

  • যে method chain-এর অংশ, সেগুলোতে consistentভাবে super() ব্যবহার করতে হবে।
  • একই chain-এর method signature compatible হতে হবে; arguments forward করার জন্য *args/**kwargs ব্যবহার করা যেতে পারে।
  • Chain-এর শেষ কোথায় হবে তা design করতে হবে।
  • Parent.method(self) দিয়ে direct parent call করলে cooperative MRO chain bypass হতে পারে।
Interview Answer: super() current class-এর পর MRO-তে থাকা পরবর্তী class-এর implementation access করে। Single inheritance-এ parent method call করতে এবং multiple inheritance-এ cooperative method chain তৈরি করতে এটি ব্যবহৃত হয়।
15What are Magic / Dunder Methods in Python?

1. Concept — Dunder Method কী?

Dunder methods হলো Python-এর special methods, যাদের নামের শুরুতে ও শেষে double underscore থাকে। যেমন __init__, __str__, __len__। “Dunder” শব্দটি এসেছে “double underscore” থেকে। এই method-গুলো custom object-কে Python-এর built-in syntax এবং protocol-এর সঙ্গে কাজ করতে দেয়।

কেন দরকার?
নিজস্ব class-এর object-কে list-এর মতো iterate করা, len() দিয়ে length বের করা, + দিয়ে combine করা, অথবা with statement-এ ব্যবহার করার behavior define করা যায়।

2. Important Dunder Methods

MethodকাজRelated syntax
__new__নতুন instance তৈরি করেObject creation
__init__তৈরি instance initialize করেClass()
__str__User-friendly string দেয়str(obj)
__repr__Developer-oriented representation দেয়repr(obj)
__len__Length return করেlen(obj)
__eq__Equality comparison define করেa == b
__lt__Less-than comparison define করেa < b
__add__Addition behavior define করেa + b
__iter__, __next__Iteration protocol implement করেfor
__enter__, __exit__Context manager protocol implement করেwith
__getitem__Index/key access define করেobj[key]
__call__Object-কে callable করেobj()

3. Practical Example — len() এবং +

CUSTOM OBJECT PROTOCOL 
class Cart:
    def __init__(self, items):
        self.items = items

    def __len__(self):
        return len(self.items)

    def __add__(self, other):
        if not isinstance(other, Cart):
            return NotImplemented
        return Cart(self.items + other.items)


cart1 = Cart(["Book", "Pen"])
cart2 = Cart(["Laptop"])

print(len(cart1))       # 2
combined = cart1 + cart2
print(combined.items)   # ['Book', 'Pen', 'Laptop']

4. Internal Working

  • len(cart1) call করলে Python length protocol ব্যবহার করে এবং Cart.__len__() invoke করে।
  • cart1 + cart2 expression addition protocol ব্যবহার করে এবং উপযুক্ত ক্ষেত্রে Cart.__add__() invoke করে।
  • __add__()-এ unsupported operand পেলে NotImplemented return করা যায়। এটি Python-কে অন্য operand-এর reflected operation try করার সুযোগ দেয়।

5. Common Mistakes

  • __len__() non-negative integer return করতে হবে।
  • __bool__() define না থাকলে truth testing-এর জন্য Python __len__() ব্যবহার করতে পারে।
  • সব dunder method implement করার প্রয়োজন নেই; প্রয়োজনীয় protocol implement করাই ভালো।
  • Special method lookup সাধারণ attribute lookup-এর মতো সবসময় instance dictionary থেকে হয় না; অনেক special operation type/class level-এ method খোঁজে।
Interview Answer: Dunder methods হলো Python-এর special methods, যা custom object-কে built-in syntax ও protocol-এর সঙ্গে কাজ করতে দেয়। যেমন __len__ দিয়ে len(), __add__ দিয়ে + এবং __iter__ দিয়ে iteration support করা যায়।
16__str__ vs __repr__ — What is the Difference?

1. Concept — দুটির উদ্দেশ্য আলাদা

__str__() object-এর readable বা user-friendly string representation তৈরি করে। অন্যদিকে __repr__() debugging এবং developer inspection-এর জন্য useful, ideally unambiguous representation দেওয়ার চেষ্টা করে।

__str____repr__
User-facing readable outputDeveloper/debugging-oriented output
কীভাবে object-টি সহজে পড়া যায় সেটি গুরুত্ব পায়Object-টিকে কীভাবে identify বা inspect করা যায় সেটি গুরুত্ব পায়
সবসময় recreate করা সম্ভব এমন output হওয়া জরুরি নয়সম্ভব হলে এমন string দেওয়া ভালো যা object recreate করতে পারে; তবে এটি সব class-এর জন্য সম্ভব বা বাধ্যতামূলক নয়

2. Practical Example

STR VS REPR 
class User:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def __str__(self):
        return f"{self.name} ({self.age} years old)"

    def __repr__(self):
        return f"User(name={self.name!r}, age={self.age!r})"


user = User("Anik", 27)

print(str(user))
print(repr(user))
print(user)

Expected output:

OUTPUT
Anik (27 years old)
User(name='Anik', age=27)
Anik (27 years old)

3. কোন operation কোন method ব্যবহার করে?

  • str(obj) সাধারণত obj.__str__() ব্যবহার করে।
  • repr(obj) obj.__repr__() ব্যবহার করে।
  • print(obj) string conversion করে, তাই সাধারণত __str__() ব্যবহার হয়।
  • Interactive interpreter-এ expression result display করার সময় সাধারণত repr() ব্যবহার হয়।
  • List বা dict-এর মতো container-এর representation তৈরি করার সময় element-গুলোর জন্য সাধারণত repr() ব্যবহার হয়।

4. শুধু __repr__ থাকলে কী হবে?

Class-এ __str__() define না থাকলে str(obj) fallback হিসেবে __repr__() ব্যবহার করে। তাই অনেক class-এ ভালো __repr__() একটি useful baseline।

REPR FALLBACK 
class Product:
    def __repr__(self):
        return "Product()"


product = Product()
print(str(product))   # Product()
print(repr(product))  # Product()
Security: __repr__()-এ password, API token বা অন্য sensitive value রাখা উচিত নয়। Debugging output log-এ চলে যেতে পারে।
Interview Answer: __str__ user-friendly display-এর জন্য এবং __repr__ developer-facing debugging representation-এর জন্য। __str__ না থাকলে str() সাধারণত __repr__-এ fallback করে।
17What are Properties in Python?

1. Concept — Property কী?

Python property এমন একটি mechanism, যার মাধ্যমে method-কে attribute-এর মতো access করা যায়। কোনো attribute read, write বা delete করার সময় custom logic চালানো সম্ভব, কিন্তু ব্যবহারকারীর কাছে syntax থাকে attribute access-এর মতো। Python-এর descriptor protocol-এর উপর property কাজ করে।

2. Property কেন প্রয়োজন?

ধরা যাক প্রথমে age একটি normal public attribute। পরে requirement এলো age negative হতে পারবে না। যদি setter method আলাদাভাবে যোগ করা হয়, তাহলে caller-দের code-ও পরিবর্তন করতে হতে পারে। Property ব্যবহার করলে person.age এবং person.age = 26 syntax বজায় রেখেই validation যোগ করা যায়।

3. Getter, Setter এবং Deleter Example

PROPERTY · GETTER / SETTER / DELETER 
class Person:
    def __init__(self, age):
        self.age = age

    @property
    def age(self):
        return self._age

    @age.setter
    def age(self, value):
        if value < 0:
            raise ValueError("Age cannot be negative")
        self._age = value

    @age.deleter
    def age(self):
        del self._age


person = Person(25)
print(person.age)  # getter runs
person.age = 26     # setter runs
del person.age     # deleter runs

4. Internal Working — কোন syntax-এ কী হয়?

  • Getter: person.age read করলে property-এর getter execute হয় এবং self._age return করে।
  • Setter: person.age = 26 করলে setter execute হয়। Validation pass করলে internal attribute _age set হয়।
  • Deleter: del person.age করলে deleter execute হয় এবং _age delete হয়।
person.age→Getter→_age
person.age = 26→Setter→Validation→_age = 26

5. Common Mistake — Recursion

Getter-এর ভেতরে return self.age লিখলে একই property আবার call হবে এবং recursion তৈরি হবে। তাই internal storage হিসেবে self._age ব্যবহার করা হয়েছে।

Interview Answer: Property method-কে attribute-style interface দেয়। @property, @name.setter এবং @name.deleter দিয়ে read, write ও delete operation-এর custom logic define করা যায়।
18What is @property in Python?

1. Concept — @property কী?

@property হলো built-in property descriptor তৈরির decorator syntax। এটি কোনো method-কে এমন attribute হিসেবে access করতে দেয়, যার value read করার সময় method-এর code execute হয়। তাই method call-এর মতো parentheses লাগে না।

Question 17 ও 18-এর পার্থক্য:
Question 17-এ Property mechanism-এর overall ধারণা, getter/setter/deleter এবং use case আলোচনা করা হয়েছে। Question 18-এ বিশেষভাবে @property decorator কীভাবে কাজ করে, computed attribute এবং read-only property কীভাবে তৈরি হয়—সেগুলো দেখা হচ্ছে।

2. Computed Attribute Example

Rectangle-এর area আলাদা করে store না করে width ও height থেকে calculate করা যায়। কিন্তু ব্যবহারকারী rectangle.area হিসেবে access করতে পারবে।

COMPUTED PROPERTY 
class Rectangle:
    def __init__(self, width, height):
        self.width = width
        self.height = height

    @property
    def area(self):
        return self.width * self.height


rectangle = Rectangle(10, 5)
print(rectangle.area)  # 50

area কোনো stored instance variable নয়। এটি width ও height থেকে calculate হচ্ছে। Syntax হলো rectangle.area, not rectangle.area()।

3. Read-only Property

শুধু @property define করে setter না দিলে property-তে সাধারণ assignment করা যায় না। ফলে read-only interface তৈরি হয়।

READ-ONLY PROPERTY 
class Circle:
    def __init__(self, radius):
        self.radius = radius

    @property
    def diameter(self):
        return self.radius * 2


circle = Circle(5)
print(circle.diameter)  # 10
# circle.diameter = 20  # AttributeError

4. Internal Working — descriptor হিসেবে @property

  1. Class body-তে @property কোনো function-এর উপর apply হয়।
  2. Decorator function-টিকে একটি property object দিয়ে replace করে।
  3. Instance থেকে ওই attribute read করলে descriptor protocol-এর মাধ্যমে getter execute হয়।
  4. Setter define করা থাকলে assignment-এর সময় setter execute হয়; না থাকলে assignment সাধারণত reject হয়।

5. @property vs Normal Method

Normal methodProperty
obj.calculate_total()obj.total
Method call syntax ব্যবহার করেAttribute access syntax ব্যবহার করে
কোনো operation বা action বোঝাতে ভালোComputed বা managed attribute বোঝাতে ভালো
Design advice: Property-এর ভেতরে expensive database query, network request বা বড় side effect লুকিয়ে রাখা ভালো design নয়। Attribute access সাধারণত lightweight ও predictable হওয়া উচিত।
Interview Answer: @property method-কে attribute-এর মতো access করতে দেয়। Computed value, validation এবং read-only interface তৈরিতে এটি useful। এটি Python-এর descriptor mechanism-এর উপর কাজ করে।
19What are Abstract Base Classes (ABC) in Python?

1. Concept — ABC কী?

Abstract Base Class (ABC) হলো এমন base class, যা subclass-গুলোর জন্য common interface বা contract define করতে পারে। Python-এর abc module-এর ABC এবং @abstractmethod ব্যবহার করে abstract method define করা যায়। Abstract method implement না করা concrete subclass instantiate করা যায় না।

কেন দরকার?
একই interface follow করে একাধিক implementation তৈরি করতে এবং incomplete subclass ভুল করে instantiate হওয়া আটকাতে ABC ব্যবহার করা যায়।

2. Practical Example — Storage System

ধরা যাক application-এ data save/load করার জন্য FileStorage, DatabaseStorage বা CloudStorage থাকতে পারে। প্রতিটি implementation-এ save() এবং load() থাকা দরকার। ABC এই contract define করতে পারে।

PYTHON 3 · ABSTRACT BASE CLASS 
from abc import ABC, abstractmethod


class Storage(ABC):
    @abstractmethod
    def save(self, data):
        pass

    @abstractmethod
    def load(self, key):
        pass


class FileStorage(Storage):
    def save(self, data):
        return "Saved to file"

    def load(self, key):
        return f"Loaded {key} from file"


storage = FileStorage()
print(storage.save("hello"))

3. Abstract method implement না করলে?

নিচের IncompleteStorage class-এ load() implement করা হয়নি। তাই class-টি abstract অবস্থায় থাকবে এবং এর object তৈরি করতে গেলে TypeError হবে।

INCOMPLETE SUBCLASS 
class IncompleteStorage(Storage):
    def save(self, data):
        return "Saved"


# IncompleteStorage()  # TypeError

4. Abstract method-এর body থাকতে পারে?

হ্যাঁ। Abstract method-এর body থাকতে পারে। Subclass-কে abstract method override করতে হবে; override করা method-এর ভেতর super() দিয়ে base method-এর implementation reuse করা সম্ভব।

5. ABC vs Duck Typing vs Protocol

ABCDuck TypingProtocol
Explicit inheritance/registration দিয়ে runtime contract তৈরি করা যায়। Abstract method অসম্পূর্ণ থাকলে instantiate আটকায়।Object প্রয়োজনীয় operation support করলেই ব্যবহার করা হয়; নির্দিষ্ট base class inherit করা আবশ্যক নয়।typing.Protocol structural typing-এর contract প্রকাশ করে; static type checker method/attribute মিলিয়ে compatibility যাচাই করতে পারে।

@runtime_checkable Protocol-এর কিছু runtime check support করে, তবে সেটি পূর্ণ static type checking-এর বিকল্প নয়। ABC explicit runtime class hierarchy ও abstract method enforcement-এ useful; Protocol structural typing-এ useful।

Interview Answer: ABC হলো abc module দিয়ে তৈরি abstract base class, যা subclass-এর জন্য interface/contract define করে। @abstractmethod implement না করলে subclass instantiate করা যায় না। এটি explicit contract enforcement-এর জন্য useful।
20What are SOLID Principles in Python?

1. Concept — SOLID কী?

SOLID হলো object-oriented software design-এর পাঁচটি principle-এর acronym। এগুলোর লক্ষ্য software-কে maintainable, extensible এবং change-friendly রাখা। SOLID Python-specific feature নয়; বিভিন্ন OOP language-এ design guideline হিসেবে ব্যবহার করা যায়।

S · Single ResponsibilityO · Open/ClosedL · Liskov SubstitutionI · Interface SegregationD · Dependency Inversion

2. S — Single Responsibility Principle (SRP)

একটি class/module-এর change করার একটি প্রধান কারণ থাকা উচিত। অর্থাৎ unrelated responsibility একই class-এ জমা না করাই ভালো।

Problem: Invoice class যদি invoice calculation, PDF generation এবং email sending—সব করে, তাহলে PDF format বা email provider change হলেও Invoice class edit করতে হবে।

SRP · SEPARATE RESPONSIBILITIES 
class Invoice:
    def total(self, items):
        return sum(items)


class InvoicePrinter:
    def print_invoice(self, invoice_total):
        print(f"Total: {invoice_total}")


class InvoiceRepository:
    def save(self, invoice):
        print("Invoice saved")

এখানে calculation, printing এবং persistence আলাদা responsibility-তে রাখা হয়েছে।

3. O — Open/Closed Principle (OCP)

Software entity extension-এর জন্য open, কিন্তু existing tested code modification-এর প্রয়োজন যতটা সম্ভব কম—এমন design হওয়া উচিত। নতুন behavior যোগ করতে গিয়ে বারবার পুরনো code edit না করে abstraction ও polymorphism ব্যবহার করা যায়।

OCP · STRATEGY PATTERN STYLE 
from abc import ABC, abstractmethod


class Discount(ABC):
    @abstractmethod
    def apply(self, price):
        pass


class NoDiscount(Discount):
    def apply(self, price):
        return price


class TenPercentDiscount(Discount):
    def apply(self, price):
        return price * 0.90


class Checkout:
    def __init__(self, discount):
        self.discount = discount

    def total(self, price):
        return self.discount.apply(price)


checkout = Checkout(TenPercentDiscount())
print(checkout.total(1000))  # 900.0

নতুন discount type যোগ করতে নতুন class তৈরি করা যায়। Checkout-এর calculation flow নতুন discount-এর জন্য rewrite করতে হয় না।

4. L — Liskov Substitution Principle (LSP)

যে জায়গায় base class-এর object ব্যবহার করা যায়, সেখানে তার subtype object বসালেও program-এর expected behavior ভেঙে যাওয়া উচিত নয়। Subclass-কে base class-এর contract মানতে হবে।

Problem: যদি Bird class-এ সব bird-এর জন্য fly() বাধ্যতামূলক করা হয়, তাহলে Penguin-এর মতো উড়তে না-পারা bird subclass design-এ সমস্যা তৈরি করবে।

LSP · BETTER ABSTRACTION 
class Bird:
    def move(self):
        raise NotImplementedError


class FlyingBird(Bird):
    def fly(self):
        return "Flying"


class Sparrow(FlyingBird):
    def move(self):
        return self.fly()


class Penguin(Bird):
    def move(self):
        return "Swimming or walking"

সব Bird-এর common contract হলো move করা। Flying capability আলাদা subclass-এ রাখা হয়েছে। বাস্তব design-এ capability-based interface বা composition আরও উপযুক্ত হতে পারে।

5. I — Interface Segregation Principle (ISP)

Client-কে এমন method-এর উপর depend করানো উচিত নয়, যেগুলো তার প্রয়োজন নেই। একটি বড় interface-এর বদলে ছোট ও focused interface ভালো।

Example: শুধু print করতে পারে এমন device-কে যদি print, scan ও fax—সব method implement করতে বাধ্য করা হয়, তাহলে অপ্রয়োজনীয় dependency তৈরি হয়।

ISP · SMALL INTERFACES 
from abc import ABC, abstractmethod


class Printer(ABC):
    @abstractmethod
    def print_document(self, document):
        pass


class Scanner(ABC):
    @abstractmethod
    def scan(self):
        pass


class BasicPrinter(Printer):
    def print_document(self, document):
        return "Printing document"

BasicPrinter শুধু Printer interface implement করছে; Scanner-এর method implement করার দরকার নেই।

6. D — Dependency Inversion Principle (DIP)

High-level module যেন low-level concrete implementation-এর উপর সরাসরি depend না করে। দুটিই abstraction-এর উপর depend করবে। Abstraction যেন detail-এর উপর depend না করে; detail abstraction-এর উপর depend করবে।

Example: Checkout class যদি সরাসরি StripePayment তৈরি করে, তাহলে provider change করতে Checkout edit করতে হবে। এর বদলে PaymentProcessor abstraction-এর উপর depend করানো যায়।

DIP · DEPENDENCY INJECTION 
from abc import ABC, abstractmethod


class PaymentProcessor(ABC):
    @abstractmethod
    def pay(self, amount):
        pass


class CardPayment(PaymentProcessor):
    def pay(self, amount):
        return f"Card payment: {amount}"


class MobilePayment(PaymentProcessor):
    def pay(self, amount):
        return f"Mobile payment: {amount}"


class Checkout:
    def __init__(self, processor: PaymentProcessor):
        self.processor = processor

    def complete(self, amount):
        return self.processor.pay(amount)


checkout = Checkout(CardPayment())
print(checkout.complete(1500))

এখানে constructor দিয়ে dependency পাঠানো হয়েছে। এই technique-কে Dependency Injection বলা হয়। DIP হলো design principle; Dependency Injection হলো সেটি implement করার একটি common technique।

7. SOLID একসঙ্গে কীভাবে কাজ করে?

  • SRP: Class-এর responsibility সীমিত রাখে।
  • OCP: Existing code বারবার edit না করে নতুন behavior যোগ করতে সাহায্য করে।
  • LSP: Subclass যেন base class-এর contract ভঙ্গ না করে তা নিশ্চিত করে।
  • ISP: ছোট ও focused interface তৈরি করে।
  • DIP: Concrete class-এর বদলে abstraction-এর উপর dependency তৈরি করে।

8. Python-এ SOLID ব্যবহারের সময়

Python dynamic language। সব জায়গায় ABC বা বড় class hierarchy দরকার হয় না। Duck typing, Protocol, functions, composition এবং dependency injection দিয়েও SOLID-এর লক্ষ্য অর্জন করা যায়। SOLID checklist হিসেবে ব্যবহার করা ভালো—অকারণে abstraction বা class বাড়ানোর নিয়ম হিসেবে নয়।

Interview Answer: SOLID হলো পাঁচটি OOP design principle: Single Responsibility, Open/Closed, Liskov Substitution, Interface Segregation এবং Dependency Inversion। এগুলো responsibility, extension, substitutability, interface design এবং dependency management উন্নত করতে সাহায্য করে।
