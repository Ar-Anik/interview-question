21What is the Descriptor Protocol in Python?

মূল ধারণা

Descriptor হলো এমন একটি Python object, যার class-এ __get__(), __set__() অথবা __delete__() special method-এর অন্তত একটি define করা থাকে। Descriptor-কে অন্য class-এর class attribute হিসেবে রাখলে সেই attribute access-এর সময় Python descriptor protocol ব্যবহার করে।

Descriptor মূলত attribute access-এর behavior control করে। Validation, lazy loading, ORM field, reusable property logic এবং framework-level API তৈরিতে এটি কাজে লাগে। @property নিজেও descriptor protocol-এর উপর তৈরি।

এক লাইনে: Descriptor এমন object, যা অন্য object-এর attribute read, write বা delete কীভাবে হবে তা নিয়ন্ত্রণ করতে পারে।

Descriptor protocol-এর method

  • __get__(self, instance, owner): attribute read হলে call হয়। instance হলো যে object থেকে access হচ্ছে; class দিয়ে access করলে এটি None হয়। owner হলো owning class।
  • __set__(self, instance, value): attribute assign হলে call হয়।
  • __delete__(self, instance): attribute delete হলে call হয়।
  • __set_name__(self, owner, name): class তৈরির সময় descriptor-কে তার owner class ও attribute name জানায়। এটি descriptor protocol-এর বাধ্যতামূলক method নয়, তবে reusable descriptor বানাতে খুব কাজে লাগে।

Practical Example: reusable validation

একই validation logic অনেক model/class-এ ব্যবহার করা যায়। নিচের PositiveNumber descriptor negative value reject করে এবং প্রতিটি instance-এর value তার নিজের __dict__-এ রাখে।

PYTHON 3 · CUSTOM DATA DESCRIPTOR
class PositiveNumber:
    def __set_name__(self, owner, name):
        self.storage_name = f"_{name}"

    def __get__(self, instance, owner=None):
        if instance is None:
            return self
        return instance.__dict__.get(self.storage_name)

    def __set__(self, instance, value):
        if value <= 0:
            raise ValueError("Value must be positive")
        instance.__dict__[self.storage_name] = value


class Product:
    price = PositiveNumber()

    def __init__(self, price):
        self.price = price


first = Product(1200)
second = Product(800)
print(first.price)
print(second.price)
first.price = 1500
print(first.price)
EXPECTED OUTPUT
1200 800 1500

Product.price class attribute হিসেবে একটি descriptor object। কিন্তু first.price = 1500 করলে Python সরাসরি instance-এর price key-তে value না রেখে descriptor-এর __set__() call করে। Descriptor নিজে _price নামে storage key ব্যবহার করছে। ফলে first ও second-এর value আলাদা থাকে।

Data descriptor vs Non-data descriptor

  • Data descriptor: __set__() অথবা __delete__() define করে।
  • Non-data descriptor: শুধু __get__() define করে; __set__()/__delete__() নেই।

একটি গুরুত্বপূর্ণ lookup rule: instance attribute lookup-এ সাধারণত data descriptor আগে, তারপর instance __dict__, এরপর non-data descriptor/class attribute খোঁজা হয়। তাই data descriptor instance-এর একই নামের attribute-কে override করতে পারে; non-data descriptor-এর ক্ষেত্রে instance dictionary value অগ্রাধিকার পেতে পারে।

DATA DESCRIPTOR PRECEDENCE
class DataDescriptor:
    def __get__(self, instance, owner):
        return "descriptor value"

    def __set__(self, instance, value):
        instance.__dict__["item"] = value


class Example:
    item = DataDescriptor()


obj = Example()
obj.__dict__["item"] = "instance value"
print(obj.item)
EXPECTED OUTPUT
descriptor value

Internal working: attribute read

  1. obj.attribute access হলে Python-এর attribute lookup mechanism কাজ করে।
  2. Class-এর MRO ধরে attribute খোঁজা হয়। পাওয়া object descriptor হলে তার type-এ __get__ আছে কি না দেখা হয়।
  3. Data descriptor থাকলে সেটি instance dictionary-এর আগে priority পায়।
  4. অন্যথায় instance dictionary দেখা হয়; এরপর non-data descriptor বা সাধারণ class attribute পাওয়া যেতে পারে।
  5. Descriptor-এর __get__ থাকলে প্রয়োজন অনুযায়ী সেটি call হয়।

Common confusion ও caveat

  • @property descriptor-এর একটি built-in ব্যবহার; custom descriptor তার চেয়ে বেশি reusable এবং configurable হতে পারে।
  • Descriptor class-এর attribute হিসেবে থাকতে হয়। শুধু instance-এর attribute হিসেবে descriptor object রাখলে সেই object সাধারণত descriptor protocol দিয়ে পরিচালিত হয় না।
  • __set_name__ class creation-এর সময় স্বয়ংক্রিয়ভাবে call হয়। Class তৈরি হওয়ার পরে descriptor attribute হিসেবে assign করলে Python নিজে থেকে __set_name__ call করে না; প্রয়োজন হলে manually call করতে হয়।
  • Descriptor-এর state-এ instance-specific value রাখলে একাধিক instance-এর value ভুল করে shared হয়ে যেতে পারে। তাই সাধারণত instance storage ব্যবহার করা হয়। এই example-এর storage instance.__dict__-এর উপর নির্ভরশীল; target class-এ __slots__ দিয়ে __dict__ বাদ থাকলে আলাদা storage strategy লাগবে।
Interview-ready answer: Descriptor হলো এমন object যার class-এ __get__, __set__ বা __delete__ থাকে। অন্য class-এর attribute হিসেবে ব্যবহৃত হলে এটি attribute access control করে। Data descriptor instance dictionary-এর আগে priority পায়, আর property descriptor protocol-এর উপর তৈরি।
22What is the difference between __new__() and __init__()?

মূল ধারণা

__new__() এবং __init__() দুটোই object creation-এর সাথে যুক্ত, কিন্তু কাজ এক নয়। __new__() নতুন instance তৈরি করে এবং instance return করে। __init__() তৈরি হওয়া instance initialize করে; এটি নতুন instance return করে না।

মনে রাখার সহজ নিয়ম: __new__ = instance তৈরি/return, __init__ = তৈরি হওয়া instance-এর initial state set করা।

Execution order

  1. MyClass(...) call হলে class-এর __new__(cls, ...) execute হয়।
  2. __new__ instance return করলে এবং সেটি cls বা তার subclass-এর instance হলে সেই instance-এর __init__(...) call হয়।
  3. __new__ যদি unrelated type-এর object return করে, তাহলে ওই object-এর জন্য cls.__init__ call হয় না।

Practical Example

OBJECT CREATION ORDER
class Account:
    def __new__(cls, owner):
        print("1. __new__ creates the instance")
        instance = super().__new__(cls)
        return instance

    def __init__(self, owner):
        print("2. __init__ initializes the instance")
        self.owner = owner


account = Account("Anik")
print(account.owner)
EXPECTED OUTPUT
1. __new__ creates the instance 2. __init__ initializes the instance Anik

super().__new__(cls) এখানে base object-এর allocation behavior ব্যবহার করে instance তৈরি করছে। __new__ সাধারণত override করার প্রয়োজন হয় না; custom object creation behavior দরকার হলেই এটি ব্যবহার করা হয়।

Immutable type subclassing-এ __new__ কেন দরকার?

str, int, tuple-এর মতো immutable type-এর মূল value instance initialization-এর সময় পরিবর্তন করা যায় না। তাই subclass-এর value customize করতে __new__-এর সময় value তৈরি করতে হয়।

SUBCLASSING AN IMMUTABLE TYPE
class UpperString(str):
    def __new__(cls, value):
        normalized = value.upper()
        return super().__new__(cls, normalized)


word = UpperString("python")
print(word)
print(type(word).__name__)
print(isinstance(word, str))
EXPECTED OUTPUT
PYTHON UpperString True

এখানে str immutable হওয়ায় __new__ uppercase value দিয়ে UpperString instance তৈরি করছে। __init__ দিয়ে পরে string-এর মূল content পরিবর্তন করা সম্ভব নয়।

__new__ এবং __init__-এর পার্থক্য

  • প্রধান দায়িত্ব: __new__ instance return করে; __init__ state initialize করে।
  • প্রথম argument: __new__-এর প্রথম argument class (cls); __init__-এর প্রথম argument instance (self)।
  • Return: __new__ instance return করে; __init__ অবশ্যই None return করবে। অন্য value return করলে TypeError হয়।
  • Use case: __new__ immutable subclassing, controlled instance creation বা caching-এর মতো advanced ক্ষেত্রে; __init__ সাধারণ object initialization-এ।
Common confusion: __new__ static-method-এর মতো class-কে প্রথম argument হিসেবে পায়; আলাদা করে @staticmethod লিখতে হয় না। আর __init__ object allocate করে না।
Interview-ready answer: __new__ class call-এর সময় instance তৈরি করে return করে, আর __init__ সেই instance initialize করে। Immutable built-in type subclass করলে initial value নির্ধারণের জন্য __new__ দরকার হতে পারে।
23What is a Metaclass, and when should it be used?

মূল ধারণা

Metaclass হলো class তৈরির নিয়ম নিয়ন্ত্রণকারী class। সাধারণত object-এর class নির্ধারণ করে object কী ধরনের; একইভাবে কোনো class-এর metaclass নির্ধারণ করে class object কীভাবে তৈরি হবে। Python-এ default metaclass হলো type।

CLASS, INSTANCE AND METACLASS
class Employee:
    pass

employee = Employee()

print(type(employee) is Employee)
print(type(Employee) is type)
print(type(type) is type)
EXPECTED OUTPUT
True True True

employee হলো Employee class-এর instance। Employee নিজেই একটি object, এবং defaultভাবে সেটি type-এর instance। type নিজেও নিজের metaclass হিসেবে কাজ করে।

Class statement internally কী করে?

class Employee: শুধু runtime-এ একটি নাম bind করে না; Python class object তৈরি করার জন্য একটি class-creation process চালায়। High-level flow:

  1. Metaclass নির্ধারণ হয়। Explicit metaclass=... না থাকলে base class-গুলোর metaclass বিবেচনা করে default type নেওয়া হয়।
  2. Class body execute হয়ে একটি namespace তৈরি করে। Custom metaclass চাইলে __prepare__ দিয়ে namespace তৈরির পদ্ধতি customize করতে পারে।
  3. Metaclass-কে class name, bases এবং namespace দেওয়া হয়।
  4. Metaclass class object তৈরি করে; সাধারণ custom metaclass type inherit করে এবং __new__/__init__ override করতে পারে।
  5. Class object তৈরি হওয়ার সময় descriptor-এর __set_name__ এবং parent class-এর __init_subclass__ hook-ও class creation lifecycle-এর অংশ হিসেবে কাজ করতে পারে।

Practical Example: automatic class registry

ধরা যাক, plugin system-এ প্রতিটি concrete plugin class তৈরি হওয়ার সাথে সাথে registry-তে রাখতে হবে। Metaclass দিয়ে class creation-এর সময় এই কাজ করা যায়।

CUSTOM METACLASS
class RegistryMeta(type):
    registry = {}

    def __new__(mcls, name, bases, namespace, **kwargs):
        cls = super().__new__(mcls, name, bases, namespace, **kwargs)
        if not namespace.get("ABSTRACT", False):
            mcls.registry[name] = cls
        return cls


class Plugin(metaclass=RegistryMeta):
    ABSTRACT = True


class JsonPlugin(Plugin):
    pass


class CsvPlugin(Plugin):
    pass


print(sorted(RegistryMeta.registry))
print(RegistryMeta.registry["JsonPlugin"] is JsonPlugin)
EXPECTED OUTPUT
['CsvPlugin', 'JsonPlugin'] True

Metaclass-এর __new__ class object তৈরি হওয়ার সময় call হয়। এখানে base Plugin-কে ABSTRACT = True দিয়ে registry থেকে বাদ রাখা হয়েছে; পরের concrete subclass-গুলো registry-তে যোগ হয়েছে।

কখন Metaclass ব্যবহার করা যুক্তিযুক্ত?

  • একাধিক class তৈরির সময় একই ধরনের structural rule enforce করতে হলে।
  • Class registration, class-level API generation বা framework-এর declarative syntax implement করতে হলে।
  • Class তৈরি হওয়ার আগেই namespace/base class inspect বা transform করার প্রয়োজন হলে।

কখন এড়িয়ে চলা ভালো?

শুধু subclass validation বা registration দরকার হলে __init_subclass__, class decorator বা ordinary helper অনেক সময় সহজ। Metaclass inheritance-এ metaclass conflict তৈরি হতে পারে—বিশেষ করে ভিন্ন metaclass ব্যবহার করা একাধিক base class inherit করলে। তাই প্রয়োজন প্রমাণিত না হলে metaclass ব্যবহার না করাই ভালো।

Common confusion: Metaclass প্রতিটি instance তৈরির সময় চলে না। এটি class object তৈরির সময় কাজ করে। Instance তৈরি হয় পরে, যেমন JsonPlugin()।
Interview-ready answer: Metaclass হলো class-এর class। Python-এর default metaclass type। Custom metaclass class creation process customize করতে পারে—যেমন class registration বা structural validation। তবে সাধারণ subclass hook-এর কাজ হলে __init_subclass__ বেশি সহজ হতে পারে।
24What is __init_subclass__(), and how is it different from a metaclass?

মূল ধারণা

__init_subclass__() হলো base class-এর একটি class creation hook। কোনো class থেকে নতুন subclass তৈরি হলে parent class-এর এই hook স্বয়ংক্রিয়ভাবে call হয়। Subclass register করা, class-level configuration নেওয়া বা subclass-এর rule validate করার জন্য এটি ব্যবহার করা যায়।

এটি metaclass নয়; ordinary base class method হিসেবেই define করা যায়। তাই metaclass-এর তুলনায় অনেক সাধারণ class customization সহজে করা সম্ভব।

Practical Example: plugin registration ও keyword configuration

INIT_SUBCLASS HOOK
class Plugin:
    registry = {}

    def __init_subclass__(cls, *, plugin_name=None, **kwargs):
        super().__init_subclass__(**kwargs)
        if plugin_name is None:
            raise TypeError("plugin_name is required")
        cls.plugin_name = plugin_name
        Plugin.registry[plugin_name] = cls


class JsonPlugin(Plugin, plugin_name="json"):
    pass


class CsvPlugin(Plugin, plugin_name="csv"):
    pass


print(sorted(Plugin.registry))
print(JsonPlugin.plugin_name)
EXPECTED OUTPUT
['csv', 'json'] json

Subclass statement-এ দেওয়া plugin_name="json" class-creation keyword হিসেবে parent-এর __init_subclass__-এ পৌঁছায়। Hook সেটি consume করে; বাকি keyword থাকলে super().__init_subclass__(**kwargs) দিয়ে cooperative chain-এ পাঠানো হয়। এখানে object.__init_subclass__ শেষ পর্যন্ত আর অতিরিক্ত keyword না পেয়ে কাজ শেষ করে।

কেন super() call গুরুত্বপূর্ণ?

একাধিক base class-এর প্রত্যেকটিতে __init_subclass__ থাকতে পারে। সব hook যদি cooperativeভাবে super() call করে, MRO অনুযায়ী chain চলতে পারে। কোনো hook chain বন্ধ করে দিলে পরের base class-এর hook execute নাও হতে পারে।

Subclass validation-এর আরেকটি pattern

VALIDATE A SUBCLASS AT CREATION TIME
class Serializer:
    format_name = None

    def __init_subclass__(cls, **kwargs):
        super().__init_subclass__(**kwargs)
        if cls is not Serializer and not cls.__dict__.get("format_name"):
            raise TypeError("Concrete serializer must define format_name")


class JsonSerializer(Serializer):
    format_name = "json"


print(JsonSerializer.format_name)
EXPECTED OUTPUT
json

এই উদাহরণে subclass class object তৈরি হওয়ার সময় cls.__dict__ দেখে class-টি নিজে format_name define করেছে কি না check করা হচ্ছে। শুধু inherited value থাকলে সেটি যথেষ্ট নয়। ফলে invalid subclass তৈরির সময়ই error পাওয়া যায়; instance তৈরি হওয়া পর্যন্ত অপেক্ষা করতে হয় না।

__init_subclass__ vs Metaclass

  • __init_subclass__: Parent class থেকে subclass তৈরি হলে hook চালায়; registration/configuration/validation-এর common কাজের জন্য সহজ।
  • Metaclass: Class object তৈরির আরও নিচের level-এর process নিয়ন্ত্রণ করতে পারে; namespace preparation বা class construction customize করার মতো কাজেও ব্যবহার হয়।
  • Complexity: সাধারণত hook দিয়ে কাজ হলে metaclass দরকার নেই।
Common confusion: __init_subclass__ instance initialization hook নয়। obj = MyClass() হলে এটি চলে না; class Child(Parent): class তৈরির সময় চলে।
Interview-ready answer: __init_subclass__ হলো base class-এর hook, যা subclass তৈরি হওয়ার সময় call হয়। এটি class registration, keyword configuration ও validation-এর জন্য ব্যবহার করা যায়। Multiple inheritance-এ cooperative behavior রাখতে super().__init_subclass__(**kwargs) call করা জরুরি।
25Composition vs Inheritance: what is the difference?

মূল ধারণা

Inheritance দিয়ে একটি class অন্য class-এর behavior inherit করে—সাধারণত is-a relationship বোঝাতে। Composition-এ একটি object তার কাজের জন্য অন্য object-কে নিজের member হিসেবে রাখে—সাধারণত has-a relationship বোঝাতে। Delegation হলো নিজের কোনো কাজ অন্য object-কে দিয়ে করানো।

উদাহরণ: Car is a Vehicle inheritance-এর সম্ভাব্য সম্পর্ক; কিন্তু Car has an Engine composition-এর সম্পর্ক।

মূল পার্থক্য: Inheritance behavior reuse করে subtype relationship-এর মাধ্যমে; composition object-কে collaborator হিসেবে ব্যবহার করে behavior assemble করে।

Practical Example: composition + delegation

একটি ride service fare calculate করার জন্য আলাদা calculator object ব্যবহার করতে পারে। Service নিজে fare formula implement না করে collaborator-এর কাছে calculation delegate করে।

COMPOSITION AND DELEGATION
class StandardFareCalculator:
    def calculate(self, distance_km):
        return 50 + distance_km * 20


class PremiumFareCalculator:
    def calculate(self, distance_km):
        return 100 + distance_km * 30


class RideService:
    def __init__(self, fare_calculator):
        self.fare_calculator = fare_calculator

    def quote(self, distance_km):
        return self.fare_calculator.calculate(distance_km)


standard_service = RideService(StandardFareCalculator())
premium_service = RideService(PremiumFareCalculator())

print(standard_service.quote(5))
print(premium_service.quote(5))
EXPECTED OUTPUT
150 250

RideService calculator-এর concrete implementation-এর উত্তরাধিকার নিচ্ছে না। বরং calculator object ধরে রেখেছে এবং quote() call হলে calculate()-এ delegation করছে। তাই calculator implementation আলাদা object দিয়ে replace করা যায়। এখানে composition শব্দটি object composition অর্থে ব্যবহৃত; Python নিজে UML-style exclusive ownership বা collaborator-এর lifetime enforce করে না।

Composition-এর সুবিধা

  • Runtime-এ collaborator replace করা যায়; behavior পরিবর্তনের জন্য subclass তৈরি করা সবসময় লাগে না।
  • দুটি class-এর মধ্যে tight inheritance dependency কমে।
  • একই collaborator একাধিক class reuse করতে পারে।
  • Unit test-এ fake/mock collaborator inject করে class আলাদাভাবে test করা যায়।
  • একটি class একাধিক independent capability collaborator-এর মাধ্যমে পেতে পারে; inheritance tree জটিল হয় না।

তাহলে Inheritance কখন ব্যবহার করা উচিত?

  • যখন সত্যিকারের subtype relationship আছে এবং subclass base class-এর contract ঠিকভাবে maintain করে।
  • যখন polymorphism-এর জন্য common interface/base behavior দরকার।
  • যখন shared behavior inheritance hierarchy-তে natural ও stable।

Common confusion

  • Composition মানে inheritance সম্পূর্ণ নিষিদ্ধ নয়। একই design-এ inheritance ও composition একসাথে থাকতে পারে।
  • শুধু code reuse-এর জন্য inheritance ব্যবহার করলে fragile base-class dependency তৈরি হতে পারে।
  • Composition ব্যবহার করলেই automatic loose coupling হয় না; collaborator-এর interface ও dependency direction-ও গুরুত্বপূর্ণ।
  • Delegation আর composition একই শব্দ নয়: composition object ownership/containment সম্পর্ক বোঝায়; delegation কাজ অন্য object-কে দিয়ে করানো বোঝায়।
Interview-ready answer: Inheritance হলো is-a relationship এবং subclass base class-এর behavior inherit করে। Composition হলো has-a relationship, যেখানে একটি object অন্য object-কে collaborator হিসেবে ধরে। Delegation-এর মাধ্যমে সেই collaborator-এর কাছে কাজ পাঠানো হয়। Flexible ও testable design-এর জন্য composition অনেক ক্ষেত্রে ভালো পছন্দ।
26What is a Callable Object in Python?

মূল ধারণা

কোনো object-এর class-এ __call__() define থাকলে সেই object-কে function-এর মতো call করা যায়। একে callable instance বা callable object বলা হয়। Syntax হলো obj(arguments)।

সাধারণ function-এর মতো input নেওয়ার পাশাপাশি callable object নিজের instance state ধরে রাখতে পারে। তাই configurable strategy, callback, policy object বা stateful operation তৈরি করতে এটি কাজে লাগে।

Practical Example: stateful calculator

IMPLEMENTING __call__
class TaxCalculator:
    def __init__(self, rate):
        self.rate = rate

    def __call__(self, amount):
        return round(amount * self.rate, 2)


vat_calculator = TaxCalculator(0.15)
income_tax_calculator = TaxCalculator(0.10)

print(vat_calculator(1000))
print(income_tax_calculator(1000))
print(callable(vat_calculator))
EXPECTED OUTPUT
150.0 100.0 True

vat_calculator একটি object, যার rate state আছে। vat_calculator(1000) syntax-এ Python class-এর __call__ method invoke করে। একই class থেকে আলাদা rate-এর callable object তৈরি করা যায়।

Internal working

High-levelভাবে obj(...) call করার সময় Python object-এর type-এ callable behavior খোঁজে এবং __call__ execute করে। Special method lookup সাধারণত instance-এর arbitrary attribute assignment-এর উপর নির্ভর করে না; class-level special method গুরুত্বপূর্ণ।

Function vs Callable object

  • Function: সাধারণত function object; closure বা default argument দিয়ে state ধরে রাখতে পারে।
  • Callable object: class instance; state, configuration এবং একাধিক related method একসাথে রাখতে পারে।
  • উভয়ই: call করা যায় এবং callback হিসেবে pass করা যায়, যদি প্রয়োজনীয় calling contract মিলে।

Common confusion ও caveat

  • callable(obj) True হলে object-কে call করার মতো interface আছে; কিন্তু নির্দিষ্ট argument দিয়ে call অবশ্যই সফল হবে—এমন guarantee নয়। Signature mismatch বা method-এর ভেতরের exception হতে পারে।
  • obj.__call__ = another_function দিয়ে একটি instance-এর special call behavior সাধারণত replace করা যায় না; special method lookup class level-এ হয়।
  • শুধু function হলেই সবসময় callable object-এর চেয়ে ভালো বা উল্টোটা নয়। State/configuration object-এর সাথে থাকা দরকার কি না, সেটিই design decision।
Interview-ready answer: কোনো class-এ __call__ define থাকলে তার instance-কে function-এর মতো call করা যায়। Callable object নিজের state/configuration ধরে রাখতে পারে, তাই strategy বা callback pattern-এ উপকারী। callable() callability check করে, কিন্তু argument compatibility guarantee করে না।
27How do class-based Context Managers work?

মূল ধারণা

Context Manager এমন object, যা কোনো operation-এর আগে setup এবং operation শেষে cleanup পরিচালনা করে। Python-এর with statement context manager ব্যবহার করে। Class-based context manager তৈরি করতে সাধারণত __enter__() এবং __exit__() implement করা হয়।

File, lock, database transaction, temporary resource বা অন্য কোনো resource-এর lifecycle নিরাপদে manage করতে এটি ব্যবহার করা হয়।

দুটি method কী করে?

  • __enter__(): with block শুরু হওয়ার সময় call হয়। এর return value as-এর variable-এ bind হয়।
  • __exit__(exc_type, exc_value, traceback): block শেষ হলে—normal exit বা exception—call হয়। Exception না থাকলে তিনটি argument-ই None।
  • __exit__ truthy value return করলে block-এর exception suppress হয়। False বা None return করলে exception propagate করে।

Practical Example: cleanup নিশ্চিত করা

CLASS-BASED CONTEXT MANAGER
class ManagedResource:
    def __enter__(self):
        print("Resource acquired")
        return self

    def work(self):
        print("Working with resource")

    def __exit__(self, exc_type, exc_value, traceback):
        if exc_type is None:
            print("Block finished normally")
        else:
            print(f"Handling cleanup for {exc_type.__name__}")
        print("Resource released")
        return False


try:
    with ManagedResource() as resource:
        resource.work()
        raise ValueError("Something went wrong")
except ValueError:
    print("Exception propagated")
EXPECTED OUTPUT
Resource acquired Working with resource Handling cleanup for ValueError Resource released Exception propagated

__exit__ exception-এর type পেয়ে cleanup চালায়, কিন্তু False return করায় ValueError suppress হয় না। তাই with block-এর বাইরে except সেটি catch করে।

Exception suppress করা

কিছু context manager নির্দিষ্ট exception ইচ্ছাকৃতভাবে handle করে suppress করতে পারে। তবে indiscriminately সব exception suppress করা বিপজ্জনক, কারণ এতে bug লুকিয়ে যেতে পারে।

SUPPRESS ONLY A SPECIFIC EXCEPTION
class IgnoreValueError:
    def __enter__(self):
        return self

    def __exit__(self, exc_type, exc_value, traceback):
        return exc_type is ValueError


with IgnoreValueError():
    raise ValueError("This one is suppressed")

print("Program continues")
EXPECTED OUTPUT
Program continues

Internal flow এবং গুরুত্বপূর্ণ caveat

  1. Python __enter__() call করে।
  2. এর return value as-এর target-এ bind হয়।
  3. এরপর block execute হয়।
  4. Block normal শেষ হলে __exit__(None, None, None) call হয়। Exception হলে exception details দিয়ে __exit__ call হয়।
  5. __exit__ truthy return করলে exception suppress হয়; অন্যথায় propagate করে।
  • __enter__ নিজেই exception raise করলে সাধারণত ওই context manager-এর __exit__ call হয় না, কারণ context successfully entered হয়নি।
  • একাধিক context manager nested হলে exit/cleanup reverse order-এ হয়।
  • Context manager cleanup-এর জন্য; এটি নিজে transaction rollback বা resource safety guarantee করে না—সেই behavior __exit__-এ implement করতে হয়।
  • Generator-based context manager বানাতে contextlib.contextmanager ব্যবহার করা যায়; সেটি class-based protocol-এর alternative।
Interview-ready answer: Class-based context manager-এ __enter__ setup করে এবং __exit__ cleanup করে। with block exception হলেও __exit__ call করে। __exit__ truthy return করলে exception suppress হয়; সাধারণত False/None return করলে exception propagate করে।
28What are the advanced features of Python dataclasses?

মূল ধারণা

dataclasses module-এর @dataclass decorator data-focused class-এর জন্য repetitive method generate করে। Default configuration-এ এটি সাধারণত __init__, __repr__ এবং __eq__ তৈরি করে। Field declaration type annotation দিয়ে করা হয়।

Advanced usage-এ field(default_factory=...), __post_init__, frozen=True, slots=True এবং kw_only=True গুরুত্বপূর্ণ। এই page-এর dataclass example-গুলো Python 3.10+ target করে; slots=True ও kw_only=True Python 3.10-এ যুক্ত হয়েছে।

Mutable default-এর সমস্যা: default_factory

List/dict-এর মতো mutable default সরাসরি field-এ দেওয়া উচিত নয়। default_factory প্রতিটি instance-এর জন্য আলাদা value তৈরি করে।

DEFAULT_FACTORY AND POST_INIT
from dataclasses import dataclass, field


@dataclass
class Order:
    order_id: int
    items: list[str] = field(default_factory=list)

    def __post_init__(self):
        if self.order_id <= 0:
            raise ValueError("order_id must be positive")


first = Order(101)
second = Order(102)
first.items.append("Keyboard")

print(first.items)
print(second.items)
print(first == second)
EXPECTED OUTPUT
['Keyboard'] [] False

default_factory=list প্রতিটি নতুন Order-এর জন্য নতুন list তৈরি করে। Generated __init__ শেষ হওয়ার পরে __post_init__ call হয়; validation বা derived field setup সেখানে করা যায়। এখানে order_id আলাদা হওয়ায় generated equality result False।

frozen এবং slots

FROZEN + SLOTS
from dataclasses import dataclass, field, FrozenInstanceError


@dataclass(frozen=True, slots=True)
class Product:
    name: str
    tags: list[str] = field(default_factory=list)


product = Product("Keyboard")
product.tags.append("office")
print(product.tags)

try:
    product.name = "Mouse"
except FrozenInstanceError:
    print("name cannot be reassigned")
EXPECTED OUTPUT
['office'] name cannot be reassigned
  • frozen=True field reassignment আটকায় এবং generated frozen dataclass-এ assignment করলে FrozenInstanceError হয়।
  • frozen=True deep immutability দেয় না। উপরের উদাহরণে product.tags.append(...) কাজ করে, কারণ list object নিজে mutable।
  • slots=True instance-এর জন্য slot-based attribute storage তৈরি করে; সাধারণত arbitrary নতুন instance attribute যোগ করা যায় না এবং memory usage কমতে পারে।
  • slots=True ব্যবহার করলে dataclass decorator original class-এর বদলে নতুন class return করে। Inheritance, weak reference এবং super()-এর কিছু caveat থাকতে পারে; Python version ও base class design অনুযায়ী যাচাই জরুরি।

আরও দরকারি dataclass options

  • kw_only=True: field-গুলোকে keyword-only constructor argument করে; positional argument ভুল কমায়।
  • compare=False: generated equality/order comparison থেকে field বাদ দেয়।
  • repr=False: generated repr-এ field বাদ দেয়।
  • init=False: generated constructor-এ field include করে না।
  • order=True: comparison methods (__lt__, __le__, __gt__, __ge__) generate করে; field order অনুযায়ী comparison হয়।

Hashing-এর গুরুত্বপূর্ণ নিয়ম

Default eq=True এবং frozen=False হলে dataclass সাধারণত __hash__ = None করে, ফলে instance unhashable হয়। eq=True এবং frozen=True হলে সাধারণত hash generate হয়। eq=False হলে dataclass নিজে equality/hash behavior replace করে না। Hashable object-এর hash নির্ধারণে ব্যবহৃত state object-এর lifetime-এ পরিবর্তিত হওয়া উচিত নয়।

Common confusion: Dataclass field annotation নিজে runtime type validation করে না। price: float লিখলেই runtime-এ অন্য type assign করা বন্ধ হয় না। Validation আলাদাভাবে implement করতে হয়।
Interview-ready answer: @dataclass data container class-এর boilerplate method generate করে। Mutable default-এর জন্য default_factory, post-construction validation-এর জন্য __post_init__, assignment restriction-এর জন্য frozen=True এবং slot-based storage-এর জন্য slots=True ব্যবহার করা যায়। Type annotation নিজে runtime validation নয়।
29How do __eq__() and __hash__() work together?

মূল ধারণা

Python-এ == value equality check করে; custom class-এ সাধারণত __eq__() method দিয়ে এই behavior define করা হয়। is object identity check করে—দুটি reference একই object-কে নির্দেশ করছে কি না।

dict key এবং set element হিসেবে ব্যবহারযোগ্য object-এর equality ও hashing-এর মধ্যে একটি contract থাকতে হয়।

Equality vs Identity

== VS is
class User:
    def __init__(self, user_id):
        self.user_id = user_id

    def __eq__(self, other):
        if not isinstance(other, User):
            return NotImplemented
        return self.user_id == other.user_id


first = User(7)
second = User(7)

print(first == second)
print(first is second)
EXPECTED OUTPUT
True False

দুটি আলাদা instance-এর user_id সমান বলে == True; কিন্তু memory identity এক নয় বলে is False। Unsupported type-এর সাথে comparison হলে NotImplemented return করা Python-এর comparison protocol-এর সঠিক pattern; এতে Python অন্য operand-এর reflected comparison চেষ্টা করার সুযোগ পায়।

Hash contract

  • যদি a == b হয়, তাহলে অবশ্যই hash(a) == hash(b) হতে হবে।
  • উল্টো নিয়ম বাধ্যতামূলক নয়: hash সমান হলেই object equal হবে এমন নয়। একে hash collision বলা হয়।
  • একটি object hashable হতে হলে তার hash value object-এর lifetime-এ স্থির থাকতে হবে এবং equality behavior-এর সাথে consistent হতে হবে।
  • Mutable field-এর উপর equality/hash নির্ভর করলে object dict/set-এ রাখার পর সেই field mutate করা বিপজ্জনক।

Custom __eq__ লিখলে __hash__ কী হয়?

একটি class __eq__ define করে কিন্তু __hash__ define না করলে Python সাধারণত class-টিকে unhashable করে—class-এর __hash__ হয় None। কারণ mutable বা equality-based object-এর জন্য identity-based default hash রেখে দিলে contract ভেঙে যেতে পারে।

DEFINE A CONSISTENT HASH
class UserKey:
    def __init__(self, user_id):
        self.user_id = user_id

    def __eq__(self, other):
        if not isinstance(other, UserKey):
            return NotImplemented
        return self.user_id == other.user_id

    def __hash__(self):
        return hash(self.user_id)


first = UserKey(7)
second = UserKey(7)

print(first == second)
print(hash(first) == hash(second))
print(len({first, second}))
EXPECTED OUTPUT
True True 1

দুটি object-এর equality ও hash দুটোই user_id-এর উপর নির্ভর করছে। তাই একই ID হলে set তাদের একই logical key হিসেবে ধরে। এই class-এ user_id mutable রাখা হয়েছে শুধু caveat বোঝাতে: set-এ insert করার পর user_id বদলালে object-টি ভুল hash bucket-এ থেকে যেতে পারে। Production design-এ hash/equality-তে ব্যবহৃত state immutable রাখা উচিত।

Practical rules

  • Identity দরকার হলে is; logical value comparison দরকার হলে ==।
  • Custom __eq__ লিখলে hashability দরকার কি না নির্ধারণ করতে হবে। Hashable হলে একই logical fields দিয়ে __eq__ ও __hash__ implement করতে হবে।
  • Hashable object-এর equality/hash-এ ব্যবহৃত state mutate করা যাবে না—অন্তত dict/set-এ থাকা অবস্থায় নয়।
  • Immutable value object-এর জন্য @dataclass(frozen=True) উপযোগী হতে পারে; dataclass-এর hash-generation rules বুঝে ব্যবহার করতে হবে।
Common confusion: hash(a) == hash(b) থেকে a == b conclude করা যায় না। শুধু equal object-এর hash equal হওয়া বাধ্যতামূলক; unequal object-এর hash আলাদা হওয়া বাধ্যতামূলক নয়।
Interview-ready answer: __eq__ logical equality define করে এবং __hash__ hash-based collection-এ object-এর অবস্থান নির্ধারণে ব্যবহৃত হয়। Contract হলো equal object-এর hash অবশ্যই equal হবে। Custom __eq__ লিখে __hash__ না দিলে Python সাধারণত object-কে unhashable করে।
30What is the difference between Shallow Copy and Deep Copy?

মূল ধারণা

Python-এ assignment, shallow copy এবং deep copy এক জিনিস নয়। Assignment নতুন object তৈরি করে না; শুধু আরেকটি name একই object-কে reference করে। copy.copy() outer object-এর shallow copy করে। copy.deepcopy() nested object-সহ recursive copy করার চেষ্টা করে।

Assignment vs Shallow Copy vs Deep Copy

COPY BEHAVIOR
import copy

original = {"items": [{"name": "Book", "qty": 1}]}
alias = original
shallow = copy.copy(original)
deep = copy.deepcopy(original)

shallow["items"][0]["qty"] = 5

print(alias is original)
print(shallow is original)
print(shallow["items"] is original["items"])
print(deep["items"] is original["items"])
print(original["items"][0]["qty"])
print(deep["items"][0]["qty"])
EXPECTED OUTPUT
True False True False 5 1

alias একই dictionary-র আরেকটি reference। shallow নতুন outer dictionary, কিন্তু nested items list একই object। তাই shallow copy-এর nested dictionary mutate করলে original-এও পরিবর্তন দেখা যায়। deep-এর nested list আলাদা, তাই সেখানে original-এর nested value বদলায়নি।

Internal working

  • Assignment: reference copy হয়; object copy হয় না।
  • Shallow copy: নতুন outer container তৈরি হয়, কিন্তু তার ভেতরের referenced object-গুলো সাধারণত shared থাকে।
  • Deep copy: nested object recursively copy করার চেষ্টা করে। Cycle এবং shared-reference structure সামলাতে internal memo dictionary ব্যবহার করে, যাতে একই object বারবার copy না হয় এবং recursive cycle-এ infinite recursion না হয়।

Custom copy behavior

কোনো custom class-এর copy behavior নিয়ন্ত্রণ করতে __copy__() এবং __deepcopy__(memo) implement করা যায়। নিচের উদাহরণে deep copy-এর সময় nested items আলাদা করে copy করা হয়েছে।

CUSTOM __deepcopy__
import copy


class Cart:
    def __init__(self, items):
        self.items = items

    def __deepcopy__(self, memo):
        cls = type(self)
        copied = cls.__new__(cls)
        memo[id(self)] = copied
        copied.items = copy.deepcopy(self.items, memo)
        return copied


cart = Cart([{"sku": "A1"}])
cloned = copy.deepcopy(cart)
cloned.items[0]["sku"] = "B2"

print(cart.items[0]["sku"])
print(cloned.items[0]["sku"])
print(cart is cloned)
EXPECTED OUTPUT
A1 B2 False

memo[id(self)] = copied recursive copy শুরু করার আগেই destination object memo-তে রাখে। এটি cycle থাকলে recursion থামাতে এবং shared reference preserve করতে গুরুত্বপূর্ণ। __deepcopy__-তে nested value copy করার সময় একই memo pass করা উচিত।

কোন ক্ষেত্রে deep copy পুরোপুরি deep নয়?

  • সব Python object copy করা যায় না। File handle, socket, thread lock-এর মতো resource-এর copy অর্থপূর্ণ নাও হতে পারে বা operation fail করতে পারে।
  • কিছু immutable/atomic object copy না করে একই object reuse করা হতে পারে।
  • Class নিজে __copy__/__deepcopy__ define করে copy behavior customize করতে পারে।
  • Deep copy বড় object graph-এ expensive হতে পারে এবং external resource-এর lifecycle ভুলভাবে duplicate করার ঝুঁকি থাকে।
  • Copy করার বদলে immutable object, factory method বা explicit clone method design অনেক সময় বেশি নিরাপদ।
Common confusion: new_obj = old_obj কোনো copy নয়। আর shallow copy outer object আলাদা করলেও nested mutable object আলাদা করে না।
Interview-ready answer: Assignment একই object-এর আরেকটি reference তৈরি করে। Shallow copy outer object copy করে কিন্তু nested reference share করতে পারে। Deep copy nested object recursively copy করার চেষ্টা করে এবং cycle/shared reference handle করতে memo ব্যবহার করে। Custom behavior-এর জন্য __copy__ ও __deepcopy__ implement করা যায়।
