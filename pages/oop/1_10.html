01Class vs Object — Class এবং Object-এর পার্থক্য কী?

মূল ধারণা

Class হলো Python-এর একটি user-defined type। এতে object-এর কী কী attribute (data/state) এবং method (behavior) থাকবে, তা define করা হয়। Object হলো সেই class থেকে তৈরি নির্দিষ্ট instance।

সহজ উদাহরণ: একটি বাড়ির architectural plan-এ room, door ও window কোথায় থাকবে তা নির্ধারিত থাকে। Plan নিজে বাড়ি নয়। Plan অনুসারে তৈরি প্রতিটি বাড়ি আলাদা object। একইভাবে Car class হলো structure, আর Toyota বা Honda-এর নির্দিষ্ট car object হলো instance।

Code Example

PYTHON 3 · CLASS AND OBJECT
class Car:
    def __init__(self, brand, color):
        self.brand = brand
        self.color = color

    def start(self):
        return f"{self.brand} is starting"


car_one = Car("Toyota", "Black")
car_two = Car("Honda", "White")

print(car_one.brand)   # Toyota
print(car_two.brand)   # Honda
print(car_one.start())

কী ঘটছে?

  1. class Car: execute হলে Python একটি class object তৈরি করে এবং Car নামটি সেই class object-কে refer করে।
  2. Car("Toyota", "Black") call করলে Python class-এর instance তৈরির process চালায়। সাধারণ ক্ষেত্রে __new__() instance তৈরি করে এবং __init__() সেটিকে initialize করে।
  3. car_one ও car_two একই class-এর instance, কিন্তু তাদের brand ও color আলাদা।
  4. দুই object-ই class-এ define করা start() method ব্যবহার করতে পারে।

গুরুত্বপূর্ণ পার্থক্য

  • Class attribute ও method define করে; object নিজের instance state ধরে রাখে।
  • একটি class থেকে অনেক object তৈরি করা যায়।
  • Python-এ class নিজেও object। Class-এর type সাধারণত type।
Common confusion: Class-কে শুধু “blueprint” বললে প্রাথমিক ধারণা পাওয়া যায়, কিন্তু Python-এ class আরও বেশি কিছু: এটি runtime object এবং একটি type, যার attribute lookup ও inheritance behavior আছে।
Interview answer: Class হলো user-defined type, যেখানে attribute ও method define করা হয়। Object হলো সেই class-এর নির্দিষ্ট instance, যার নিজস্ব state থাকে এবং class-এর behavior ব্যবহার করতে পারে।
02What is __init__() in Python?

মূল ধারণা

__init__() হলো একটি special instance method, যা নতুন instance তৈরি হওয়ার পর তার initial state set করে। সাধারণত instance attribute-এর initial value এখানে assign করা হয়। একে কথাবার্তায় constructor বলা হয়, তবে technical distinction জানা জরুরি: __new__() instance creation/allocation-এর সঙ্গে যুক্ত; __init__() তৈরি হওয়া instance initialize করে।

Code Example

PYTHON 3 · INITIALIZATION
class Employee:
    def __init__(self, name, salary):
        self.name = name
        self.salary = salary


employee = Employee("Anik", 50000)

print(employee.name)    # Anik
print(employee.salary)  # 50000

Object তৈরির সময় ধাপে ধাপে

  1. Employee("Anik", 50000) call হয়।
  2. Python class-এর instance creation process চালায়; সাধারণত __new__() নতুন instance তৈরি করে।
  3. তৈরি হওয়া instance-টি first argument হিসেবে দিয়ে __init__() call হয়।
  4. self.name ও self.salary assignment instance-এর attribute set করে।

গুরুত্বপূর্ণ নিয়ম

  • __init__() অবশ্যই None return করবে। Explicit return না থাকলে Python implicitভাবে None দেয়। অন্য value return করলে TypeError হয়।
  • একই class body-তে একই নামে একাধিক __init__ define করলে শেষ definition-টি আগেরটিকে replace করে; Python automatic method overloading করে না।
  • Subclass-এর initializer-এ parent initialization দরকার হলে super().__init__(...) ব্যবহার করা যায়।
INHERITANCE · SUPER()
class Person:
    def __init__(self, name):
        self.name = name


class Developer(Person):
    def __init__(self, name, language):
        super().__init__(name)
        self.language = language


developer = Developer("Anik", "Python")
Common confusion: __init__() নিজে object allocate করে না। Object creation-এর সঙ্গে __new__() যুক্ত; __init__() object-এর initial state প্রস্তুত করে।
Interview answer: __init__() হলো initializer method। নতুন instance তৈরি হওয়ার পর এটি call হয় এবং instance attribute initialize করে। __new__() instance তৈরি করে, আর __init__() সেটিকে initialize করে।
03What is self in Python?

মূল ধারণা

self হলো instance method-এর প্রচলিত first parameter name। কোনো instance দিয়ে instance method call করলে Python সেই instance-টিকে method-এর first argument হিসেবে automatically pass করে। তাই method বুঝতে পারে কোন object-এর state access বা update করতে হবে।

একটি সহজভাবে মনে রাখার বিষয়: একই Student class থেকে দুইটি student object তৈরি হলে self call অনুযায়ী কখনো প্রথম object-কে, কখনো দ্বিতীয় object-কে refer করবে। এটি স্থায়ীভাবে কোনো একটি object-কে refer করে না।

Code Example

PYTHON 3 · SELF
class Student:
    def __init__(self, name):
        self.name = name

    def introduce(self):
        return f"My name is {self.name}"


student_one = Student("Anik")
student_two = Student("Rahim")

print(student_one.introduce())  # My name is Anik
print(student_two.introduce())  # My name is Rahim

# Equivalent unbound call:
print(Student.introduce(student_one))

Internal Working: method binding

Class-এর function-কে instance-এর মাধ্যমে access করলে Python-এর descriptor mechanism একটি bound method তৈরি করে। Bound method-এর মধ্যে instance-টির reference থাকে। তাই student_one.introduce() call কার্যত Student.introduce(student_one)-এর সমতুল্য।

self কি Python keyword?

না। self reserved keyword নয়; এটি community convention। Technically অন্য parameter name ব্যবহার করা সম্ভব, কিন্তু standard code-এ self ব্যবহার করাই উচিত।

Common confusion: self আলাদা করে pass করতে হয় না যখন instance দিয়ে method call হয়। তবে class দিয়ে সরাসরি function call করলে instance argument নিজে pass করতে হয়।
Interview answer: self instance method-এর conventional first parameter, যা current instance-কে refer করে। Instance দিয়ে method call হলে Python instance-টিকে automatically pass করে। self keyword নয়, naming convention।
04Instance Variables vs Class Variables

মূল ধারণা

Instance variable একটি নির্দিষ্ট object-এর state রাখে। সাধারণত self.name-এর মতো assignment দিয়ে তৈরি হয়। Class variable class body-তে define করা হয় এবং class-এর attribute হিসেবে থাকে। Instance থেকে read করলে instance-এ একই নামের attribute না থাকলে class variable পাওয়া যায়।

Code Example

PYTHON 3 · INSTANCE VS CLASS
class Employee:
    company = "Divine IT"  # Class variable

    def __init__(self, name, salary):
        self.name = name          # Instance variable
        self.salary = salary      # Instance variable


emp_one = Employee("Rahim", 40000)
emp_two = Employee("Karim", 50000)

print(emp_one.company)  # Divine IT
print(emp_two.company)  # Divine IT

emp_one.salary = 45000
Employee.company = "Example Ltd"

print(emp_one.salary)   # 45000
print(emp_two.salary)   # 50000
print(emp_one.company)  # Example Ltd

Attribute lookup কীভাবে হয়?

সাধারণ instance attribute read করার সময় Python প্রথমে instance-এর attribute storage-এ খোঁজে। সেখানে না পেলে class এবং inheritance lookup chain-এ খোঁজে। তাই emp_one.company = "My Company" লিখলে class variable পরিবর্তন হয় না; emp_one-এর জন্য একই নামের নতুন instance attribute তৈরি হয়। একে shadowing বলা হয়।

SHADOWING EXAMPLE
class Employee:
    company = "Divine IT"

emp = Employee()
emp.company = "Personal Value"

print(emp.company)        # Personal Value
print(Employee.company)  # Divine IT

Mutable class variable-এর সতর্কতা

Class variable হিসেবে list বা dictionary রাখলে সব instance একই mutable object access করতে পারে। কোনো instance সেই list mutate করলে অন্য instance-ও পরিবর্তনটি দেখতে পারে। প্রতিটি object-এর আলাদা list প্রয়োজন হলে __init__()-এ list তৈরি করতে হবে।

SAFE PER-INSTANCE LIST
class Team:
    def __init__(self):
        self.members = []  # প্রতিটি instance-এর আলাদা list
Interview answer: Instance variable প্রতিটি object-এর নিজস্ব state রাখে। Class variable class namespace-এ থাকে এবং instance-গুলো সেটি sharedভাবে access করতে পারে। Instance-এ একই নামে assignment করলে class variable বদলায় না; instance-level attribute তৈরি হয়।
05Instance Method vs Class Method vs Static Method

তিন ধরনের method-এর মূল পার্থক্য

পার্থক্যটি হলো method call-এর সময় Python automaticভাবে কোন argument bind করে এবং method কোন state নিয়ে কাজ করার জন্য design করা হয়েছে।

MethodDecoratorপ্রথম automatic argumentসাধারণ ব্যবহার
Instance methodকোনো decorator লাগে নাself — instanceএকটি object-এর state read/update
Class method@classmethodcls — calling classClass-level operation, alternative constructor
Static method@staticmethodকোনোটিই নয়Related utility logic

একটি class-এ তিনটির example

PYTHON 3 · THREE METHOD TYPES
class Employee:
    company = "Divine IT"

    def __init__(self, name):
        self.name = name

    # Instance method
    def get_name(self):
        return self.name

    # Class method
    @classmethod
    def change_company(cls, new_name):
        cls.company = new_name

    # Static method
    @staticmethod
    def is_valid_name(name):
        return isinstance(name, str) and bool(name.strip())


employee = Employee("Anik")
print(employee.get_name())  # Anik

Employee.change_company("Example Ltd")
print(Employee.company)     # Example Ltd

print(Employee.is_valid_name("Anik"))  # True

Class method as alternative constructor

Class method-এর একটি common use হলো অন্য format-এর input থেকে object তৈরি করা। cls ব্যবহার করার কারণে inherited class method subclass দিয়ে call হলে সাধারণত সেই subclass-ই instantiate হয়।

ALTERNATIVE CONSTRUCTOR
class Employee:
    def __init__(self, name, salary):
        self.name = name
        self.salary = salary

    @classmethod
    def from_string(cls, value):
        name, salary = value.split(",")
        return cls(name, int(salary))


emp = Employee.from_string("Anik,50000")

কখন কোনটি ব্যবহার করা উচিত?

  • Instance-এর data প্রয়োজন হলে: instance method।
  • Calling class-এর identity বা class-level behavior প্রয়োজন হলে: class method।
  • Instance বা class state প্রয়োজন নেই, কিন্তু function-টি class-এর concept-এর সঙ্গে logically related হলে: static method।
Common confusion: Static method class-এর ভেতরে আছে বলেই সেটি class method নয়। Static method-এ Python automaticভাবে self বা cls pass করে না।
Interview answer: Instance method automaticভাবে instance পায়, class method cls হিসেবে calling class পায়, আর static method কোনো automatic receiver পায় না। কোন method ব্যবহার হবে তা নির্ভর করে instance state, class state, নাকি শুধু related utility logic প্রয়োজন তার উপর।
06What is Encapsulation in Python?

মূল ধারণা

Encapsulation হলো data এবং সেই data-র উপর কাজ করা method-কে একটি class-এর মধ্যে রাখা, পাশাপাশি object-এর state কীভাবে read বা modify হবে তার একটি controlled interface design করা। এর উদ্দেশ্য হলো invalid state তৈরি হওয়ার ঝুঁকি কমানো এবং implementation detail-এর উপর বাইরের code-এর direct dependency কমানো।

বাস্তব উদাহরণ: Bank account-এর balance যেকোনো arbitrary value দিয়ে পরিবর্তন করা উচিত নয়। Deposit ও withdrawal-এর নিয়ম enforce করার জন্য method রাখা যায়। এভাবে balance update করার আগে validation করা সম্ভব।

Python-এ naming convention

  • name: public attribute; সাধারণভাবে বাইরে থেকে access করার জন্য।
  • _name: single leading underscore; non-public/internal ব্যবহারের convention। এটি strict access restriction নয়।
  • __name: double leading underscore; class-এর ভেতরে name mangling হয়, যেমন _Account__balance। এটি private security boundary নয়; accidental name collision কমায়।

@property দিয়ে controlled access

PYTHON 3 · ENCAPSULATION
class BankAccount:
    def __init__(self, initial_balance):
        self._balance = 0
        self.deposit(initial_balance)

    @property
    def balance(self):
        return self._balance

    def deposit(self, amount):
        if amount <= 0:
            raise ValueError("Amount must be positive")
        self._balance += amount

    def withdraw(self, amount):
        if amount <= 0:
            raise ValueError("Amount must be positive")
        if amount > self._balance:
            raise ValueError("Insufficient balance")
        self._balance -= amount


account = BankAccount(1000)
account.deposit(500)
account.withdraw(200)

print(account.balance)  # 1300

এখানে control কীভাবে হচ্ছে?

  1. _balance internal-use convention অনুসরণ করছে।
  2. balance property balance read করার interface দেয়। এখানে setter নেই, তাই account.balance = ... করা যাবে না।
  3. Balance change করার public operation হলো deposit() ও withdraw()।
  4. দুই method-ই amount validate করে; invalid operation হলে ValueError raise করে।
Common confusion: Python Java/C++-এর মতো সাধারণ private field enforcement করে না। account._balance technically access করা সম্ভব। তাই Python encapsulation মূলত API design, convention এবং validation-এর সমন্বয়; security mechanism নয়।
Interview answer: Encapsulation data ও behavior-কে class-এর মধ্যে organize করে এবং controlled interface দিয়ে state access বা modify করতে উৎসাহিত করে। Python-এ underscore convention, name mangling এবং @property ব্যবহার করা হয়; এগুলো strict privacy/security guarantee নয়।
07What is Inheritance in Python?

মূল ধারণা

Inheritance এমন mechanism, যেখানে একটি class অন্য class-এর attribute ও method inherit করে। যে class inherit করে সেটি subclass/child class; যেখান থেকে inherit করে সেটি base class/parent class। এটি shared behavior reuse এবং সত্যিকারের subtype relationship প্রকাশ করতে পারে।

Basic example

PYTHON 3 · INHERITANCE
class Animal:
    def eat(self):
        return "Eating"


class Dog(Animal):
    def bark(self):
        return "Woof!"


dog = Dog()
print(dog.eat())   # inherited method
print(dog.bark())  # Dog-এর নিজস্ব method

Dog(Animal) লেখার অর্থ Dog হলো Animal-এর subclass। তাই Dog-এর object eat() ব্যবহার করতে পারে, যদিও method-টি Animal-এ define করা হয়েছে।

Method overriding

Subclass parent-এর method-এর একই নাম দিয়ে নিজের implementation define করলে subclass-এর implementation method lookup-এ অগ্রাধিকার পায়। একে method overriding বলে।

METHOD OVERRIDING
class Animal:
    def speak(self):
        return "Some sound"


class Dog(Animal):
    def speak(self):
        return "Bark"


print(Dog().speak())  # Bark

Inheritance-এর প্রচলিত ধরন

  • Single: একটি subclass একটি base class inherit করে।
  • Multiple: একটি subclass একাধিক base class inherit করে।
  • Multilevel: A থেকে B, B থেকে C — এমন inheritance chain।
  • Hierarchical: একাধিক subclass একই base class inherit করে।
  • Hybrid: একাধিক pattern একসঙ্গে ব্যবহৃত হয়।

super() এবং MRO

super() সবসময় সরাসরি parent class-কে call করে—এমন নয়। এটি Method Resolution Order (MRO) অনুযায়ী current class-এর পরের class-এ method lookup চালায়। Multiple inheritance-এ cooperative design-এর জন্য প্রতিটি class-এ compatible signature-সহ super() ব্যবহার গুরুত্বপূর্ণ।

MRO INSPECTION
class A:
    pass

class B(A):
    pass

class C(B):
    pass


print(C.mro())

C.mro() class C-এর method lookup order list আকারে দেখায়।

Design caution: শুধু code reuse-এর জন্য inheritance ব্যবহার করা ঠিক নয়। Subclass-কে base class-এর expected behavior ও contract বজায় রাখতে হবে। “is-a” relationship না থাকলে composition ভালো হতে পারে।
Interview answer: Inheritance subclass-কে base class-এর attribute ও behavior reuse বা override করতে দেয়। Python method lookup-এর জন্য MRO ব্যবহার করে, আর super() সেই MRO-র পরবর্তী implementation access করতে সাহায্য করে।
08What is Polymorphism in Python?

মূল ধারণা

Polymorphism অর্থ একই interface বা operation বিভিন্ন type-এর object-এর ক্ষেত্রে ভিন্ন behavior দিতে পারে। Caller নির্দিষ্ট class-এর internal implementation না জেনেও common operation call করতে পারে।

Method-এর একই নাম, behavior আলাদা

PYTHON 3 · POLYMORPHISM
class Dog:
    def speak(self):
        return "Bark"


class Cat:
    def speak(self):
        return "Meow"


def make_speak(animal):
    print(animal.speak())


make_speak(Dog())  # Bark
make_speak(Cat())  # Meow

make_speak() Dog না Cat—তা check করছে না। এটি শুধু speak() operation call করছে। যে object এই operation support করে, সেটির সঙ্গে function-টি কাজ করতে পারে।

Duck typing

Python-এ অনেক ক্ষেত্রে object-এর exact class/type-এর চেয়ে object প্রয়োজনীয় operation support করে কি না, সেটি গুরুত্বপূর্ণ। একে duck typing বলে। প্রচলিত ব্যাখ্যা: “If it walks like a duck and quacks like a duck, treat it like a duck.” অর্থাৎ প্রয়োজনীয় behavior থাকলে object-টি ব্যবহার করা যায়।

Operator overloading

Special method implement করে built-in operator-এর behavior custom করা যায়। যেমন __add__() implement করলে + operator custom object-এর জন্য নির্দিষ্ট behavior পেতে পারে।

OPERATOR OVERLOADING
class Money:
    def __init__(self, amount):
        self.amount = amount

    def __add__(self, other):
        if not isinstance(other, Money):
            return NotImplemented
        return Money(self.amount + other.amount)


total = Money(100) + Money(50)
print(total.amount)  # 150

এখানে Money + Money expression-এর জন্য Python __add__() ব্যবহার করে। Unsupported operand পেলে NotImplemented return করা Python-এর operator protocol-এর সঠিক pattern।

Polymorphism কি inheritance-এর সমান?

না। Inheritance হলো class relationship ও reuse mechanism। Polymorphism হলো common interface-এর মাধ্যমে বিভিন্ন implementation ব্যবহার করার capability। Inheritance polymorphism-এর একটি উপায়, কিন্তু Python-এ duck typing এবং Protocol-এর মতো structural typing approach দিয়েও polymorphic design করা যায়।

Interview answer: Polymorphism একই interface দিয়ে বিভিন্ন object-এর নিজস্ব implementation ব্যবহার করতে দেয়। Python-এ method overriding, duck typing এবং operator overloading এর পরিচিত উদাহরণ।
09What is Abstraction in Python?

মূল ধারণা

Abstraction হলো caller-এর সামনে প্রয়োজনীয় operation বা contract expose করা, কিন্তু operation-এর internal implementation detail ব্যবহারকারীর কাছ থেকে আলাদা রাখা। Caller জানে কী করা যাবে; প্রতিটি implementation কীভাবে কাজ করে তা জানার প্রয়োজন হয় না।

উদাহরণ: Payment system-এ business logic শুধু payment initiate করার operation ব্যবহার করতে পারে। Payment Stripe দিয়ে হচ্ছে, নাকি bKash দিয়ে হচ্ছে—সেটি business logic-এর জানা বাধ্যতামূলক নয়।

ABC দিয়ে abstraction

Python-এর abc module-এর ABC এবং @abstractmethod ব্যবহার করে Abstract Base Class তৈরি করা যায়। Abstract method implement না করা concrete subclass সাধারণত instantiate করা যায় না।

PYTHON 3 · ABSTRACT BASE CLASS
from abc import ABC, abstractmethod


class PaymentGateway(ABC):
    @abstractmethod
    def pay(self, amount):
        pass


class StripeGateway(PaymentGateway):
    def pay(self, amount):
        return f"Paid {amount} using Stripe"


class BkashGateway(PaymentGateway):
    def pay(self, amount):
        return f"Paid {amount} using bKash"


gateway = StripeGateway()
print(gateway.pay(1000))

Code-এ কী enforce হচ্ছে?

  • PaymentGateway একটি contract define করেছে: concrete implementation-এ pay() থাকতে হবে।
  • StripeGateway ও BkashGateway নিজ নিজ pay() implementation দেয়।
  • Abstract method implement না করা subclass-কে সাধারণত instantiate করা যায় না।
  • ABC-তে abstract method ছাড়াও normal method, attribute ও shared implementation থাকতে পারে।

Abstraction vs Encapsulation

AbstractionEncapsulation
কোন operation/contract expose হবে—সেটিতে focus করে।Data ও behavior কীভাবে class-এ organize হবে এবং state কীভাবে control হবে—সেটিতে focus করে।
Caller-এর কাছে implementation detail অপ্রয়োজনীয় করে।Controlled interface ও validation-এর মাধ্যমে state management সহজ করে।
Common confusion: ABC ব্যবহার করলেই implementation detail secure বা automatically hidden হয়ে যায় না। ABC মূলত interface contract enforce করতে সাহায্য করে; এটি security mechanism নয়।
Interview answer: Abstraction essential operation বা contract expose করে এবং implementation detail caller থেকে আলাদা রাখে। Python-এ abc.ABC ও @abstractmethod দিয়ে abstract contract define করা যায়।
10Composition vs Inheritance — কোনটি কখন ব্যবহার করা উচিত?

মূল ধারণা

Inheritance সাধারণত is-a relationship প্রকাশ করে: Dog is an Animal। Composition সাধারণত has-a বা uses-a relationship প্রকাশ করে: Car has an Engine। Composition-এ একটি object অন্য object-কে নিজের attribute হিসেবে ধরে এবং তার behavior ব্যবহার করে।

Inheritance example

INHERITANCE · IS-A
class Animal:
    def move(self):
        return "Moving"


class Dog(Animal):
    pass


dog = Dog()
print(dog.move())  # Moving

Dog সত্যিই Animal-এর একটি subtype, তাই inheritance এখানে natural fit।

Composition example

COMPOSITION · HAS-A
class Engine:
    def start(self):
        return "Engine started"


class Car:
    def __init__(self, engine):
        self.engine = engine

    def start(self):
        return self.engine.start()


engine = Engine()
car = Car(engine)

print(car.start())  # Engine started

Car নিজে Engine নয়; Car-এর একটি Engine আছে। তাই Car-কে Engine-এর subclass না করে Engine object-কে dependency হিসেবে দেওয়া হয়েছে। Car তার start() operation-এর জন্য Engine-এর method call করছে। একে delegation-ও বলা হয়।

দুইটির comparison

বিষয়InheritanceComposition
Relationshipis-ahas-a / uses-a
ReuseBase class-এর behavior inherit করেঅন্য object-এর behavior ব্যবহার/delegate করে
CouplingSubclass base class-এর design-এর সঙ্গে tightly coupled হতে পারেDependency আলাদা রাখা যায়; replacement সহজ হতে পারে
FlexibilityClass hierarchy compile/design structure-এর অংশConstructor বা setter দিয়ে collaborator দেওয়া/পরিবর্তন করা যায়, design support করলে
PolymorphismSubtype relationship-এর মাধ্যমেCommon interface বা duck typing-এর মাধ্যমে

কখন কোনটি বেছে নেওয়া উচিত?

  • একটি class সত্যিই অন্য class-এর subtype হলে এবং base class-এর contract ঠিকভাবে মানলে inheritance উপযুক্ত।
  • একটি class অন্য component-এর service ব্যবহার করলে composition উপযুক্ত।
  • Dependency replaceable বা test-এ mock/fake object দিয়ে substitute করা দরকার হলে composition সুবিধা দেয়।
  • শুধু code reuse-এর জন্য deep inheritance hierarchy তৈরি না করে composition বিবেচনা করা উচিত।
Common confusion: Composition সবসময় inheritance-এর চেয়ে ভালো—এমন universal rule নেই। সঠিক subtype relationship থাকলে inheritance পরিষ্কার design দেয়। তবে flexible dependency design-এর ক্ষেত্রে composition প্রায়ই ভালো default choice।
Interview answer: Inheritance “is-a” relationship ও subtype behavior প্রকাশ করে। Composition “has-a/uses-a” relationship-এ অন্য object-এর functionality ব্যবহার করে। সত্যিকারের subtype হলে inheritance; replaceable collaborator বা flexible dependency দরকার হলে composition বেছে নেওয়া যায়।
Quick Revision — ১০টি প্রশ্নের সারাংশ
  • Class: user-defined type; Object: class-এর instance।
  • __init__(): instance initialize করে; __new__(): instance creation-এর সঙ্গে যুক্ত।
  • self: instance method-এর conventional first parameter; keyword নয়।
  • Instance variable: object-specific; Class variable: class namespace-এ থাকে।
  • Instance method: self; Class method: cls; Static method: automatic receiver নেই।
  • Encapsulation: data ও behavior organize এবং controlled interface design।
  • Inheritance: base/subclass relationship; super() MRO follow করে।
  • Polymorphism: একই interface, বিভিন্ন implementation; duck typing গুরুত্বপূর্ণ।
  • Abstraction: contract expose, implementation detail আলাদা রাখা।
  • Composition: has-a/uses-a; Inheritance: is-a।
