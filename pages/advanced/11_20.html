01Generator expression কী? List comprehension থেকে পার্থক্য কী?⌄

Concept

Generator expression হলো এমন expression, যা একবারে পুরো collection তৈরি না করে প্রয়োজন অনুযায়ী একটির পর একটি value produce করে। Syntax দেখতে List comprehension-এর মতো, তবে square bracket []-এর বদলে parentheses () ব্যবহার হয়। এর Result হলো generator iterator।

Python example
numbers = (x * x for x in range(5))

print(numbers)       # generator object
print(next(numbers)) # 0
print(next(numbers)) # 1

for value in numbers:
    print(value)     # 4, 9, 16

কেন প্রয়োজন?

বড় dataset নিয়ে কাজ করার সময় সব value একসাথে memory-তে তৈরি করা ব্যয়বহুল হতে পারে। Generator expression lazy evaluation ব্যবহার করে: iteration-এ যখন পরের value দরকার হয়, তখন সেটি calculate করে। ফলে peak memory usage কমতে পারে।

Internal working

  • Expression evaluate করলে generator object তৈরি হয়; তখন সব item calculate হয় না।
  • next() বা for loop পরের item চাইলে generator execution চালু বা resume হয়।
  • প্রতিটি item yield করার পর execution state সংরক্ষিত থাকে।
  • সব item শেষ হলে StopIteration দিয়ে iteration শেষ হয়।
List comprehension বনাম generator expression
# List comprehension: সব value তৈরি করে list-এ রাখে
squares_list = [x * x for x in range(1_000_000)]

# Generator expression: প্রয়োজনমতো value তৈরি করে
squares_gen = (x * x for x in range(1_000_000))

Common confusion: Generator expression নিজে সবসময় দ্রুততর নয়। ছোট collection-এ list comprehension বেশি সুবিধাজনকও হতে পারে। Generator-এর বড় সুবিধা হলো lazy processing ও কম memory requirement; repeated iteration বা random access দরকার হলে list উপযুক্ত।
Interview answer: Generator expression হলো lazy iterator তৈরির compact syntax। এটি একসাথে সব item materialize না করে demand অনুযায়ী value produce করে, তাই বড় বা streaming dataset-এ memory-efficient processing সম্ভব হয়।
02Generator-এর send() method কীভাবে কাজ করে?⌄

Concept

Generator-এর send(value) method generator-কে resume করার পাশাপাশি suspended yield expression-এর Result হিসেবে একটি value পাঠায়। অর্থাৎ next() মূলত generator-কে পরের yield পর্যন্ত চালায়, আর send(value) value-টিও generator-এর ভিতরে পাঠাতে পারে।

Basic example

Python example
def receiver():
    received = yield "Ready"
    print("Received:", received)
    yield "Done"

gen = receiver()

print(next(gen))       # Ready
print(gen.send("Hello"))  # Received: Hello, then Done

এখানে execution কীভাবে হলো?

  • gen = receiver() generator object তৈরি করে; function body তখনও execute হয় না।
  • next(gen) function চালিয়ে yield "Ready"-তে pause করে।
  • gen.send("Hello") generator resume করে এবং suspended yield expression-এর value হিসেবে "Hello" বসায়।
  • তাই received-এর value হয় "Hello"; এরপর পরের yield "Done" থেকে control ফেরত আসে।

কেন প্রথমে next() লাগে?

নতুন generator এখনো কোনো yield point-এ pause করেনি। তাই প্রথমবার non-None value দিয়ে send() করা যায় না। আগে next(gen) অথবা gen.send(None) দিয়ে generator-কে প্রথম yield পর্যন্ত চালু করতে হয়।

সঠিক sequence
gen = receiver()
first = next(gen)          # অথবা gen.send(None)
second = gen.send("Data")

Real-world use

Coroutine-style workflow-এ generator-এর ভিতরে data পাঠাতে send() ব্যবহার করা যায়। তবে modern asynchronous programming-এ সাধারণত async/await বেশি ব্যবহৃত হয়।

Common confusion: send() generator থেকে value বের করার method মাত্র নয়; এটি generator-এর ভিতরেও value পাঠায়। yield expression-এর value হলো পরবর্তী send(value)-এর পাঠানো value।
Interview answer: send(value) একটি generator-কে resume করে এবং suspended yield expression-এ value inject করে। নতুন generator-এ non-None value পাঠানোর আগে সেটিকে প্রথম yield পর্যন্ত advance করতে হয়।
03yield from কী? সাধারণ yield থেকে পার্থক্য কী?⌄

Concept

yield from iterable একটি sub-iterator বা iterable-এর item-গুলোকে current generator থেকে সরাসরি delegate করে। এটি nested generator-এর value একে একে forward করার concise উপায়।

সাধারণ yield দিয়ে
def combined():
    for item in [1, 2, 3]:
        yield item
    for item in [4, 5]:
        yield item
yield from দিয়ে
def combined():
    yield from [1, 2, 3]
    yield from [4, 5]

print(list(combined()))  # [1, 2, 3, 4, 5]

Internal working

yield from sub_iterable শুধু syntactic shortcut নয়। এটি sub-iterator-এর সঙ্গে delegation protocol পরিচালনা করে। Sub-iterator-এর item caller-এর কাছে yield হয়; উপযুক্ত ক্ষেত্রে caller-এর send(), throw() এবং generator close করার প্রভাবও delegate-এর কাছে forward হয়। Sub-generator return করলে তার return value yield from expression-এর value হয়।

Sub-generator-এর return value
def child():
    yield 10
    yield 20
    return "child finished"

def parent():
    result = yield from child()
    print(result)  # child finished
    yield 30

print(list(parent()))  # [10, 20, 30]

yield বনাম yield from

yield itemyield from iterable
একটি object yield করে।Iterable-এর item-গুলো delegate করে।
Nested generator হলে সেটি একটি yielded value হতে পারে।Nested generator-এর output stream forward করে।
Delegation নিজে manually লিখতে হয়।Delegation protocol handle করে।
Common confusion: yield from [1, 2, 3] list-টিকে একবারে yield করে না; list-এর item-গুলো একে একে yield করে। কিন্তু yield [1, 2, 3] পুরো list-টিকে একটি value হিসেবে yield করে।
Interview answer: yield from sub-iterator-এর কাছে iteration control delegate করে। এটি nested generator composition সহজ করে এবং send/throw/close delegation ও sub-generator-এর return value handle করতে পারে।
04Python Descriptor কী? __get__, __set__, __delete__ কী করে?⌄

Concept

Descriptor হলো এমন object, যার type-এ নিচের এক বা একাধিক special method define করা থাকে: __get__(), __set__(), __delete__()। কোনো class-এর attribute হিসেবে descriptor instance ব্যবহার করলে attribute access, assignment বা deletion-এর behavior customize করা যায়।

Descriptor methods

  • __get__(self, instance, owner): attribute read হলে call হয়। Class থেকে access করলে instance সাধারণত None থাকে।
  • __set__(self, instance, value): attribute-এ value assign হলে call হয়।
  • __delete__(self, instance): attribute delete হলে call হয়।

একটি validation descriptor

Python example
class PositiveNumber:
    def __set_name__(self, owner, name):
        self.name = name

    def __get__(self, instance, owner):
        if instance is None:
            return self
        return instance.__dict__[self.name]

    def __set__(self, instance, value):
        if value <= 0:
            raise ValueError("Value must be positive")
        instance.__dict__[self.name] = value


class Product:
    price = PositiveNumber()

p = Product()
p.price = 100
print(p.price)  # 100
# p.price = -5   # ValueError

এই code-এর flow

  • Class তৈরির সময় Python descriptor-এর __set_name__ call করে attribute name জানায়।
  • p.price = 100 হলে descriptor-এর __set__ call হয়; validation শেষে instance dictionary-তে value রাখা হয়।
  • p.price read করলে __get__ call হয়ে stored value ফেরত আসে।

Data descriptor বনাম Non-data descriptor

__set__ অথবা __delete__ থাকা descriptor হলো data descriptor। শুধু __get__ থাকলে সেটি non-data descriptor। সাধারণ instance attribute lookup-এ data descriptor instance-এর একই নামের entry-র চেয়ে অগ্রাধিকার পায়; non-data descriptor-এর ক্ষেত্রে instance dictionary entry অগ্রাধিকার পেতে পারে।

Python-এর কোথায় ব্যবহৃত?

property, bound methods, classmethod এবং staticmethod descriptor protocol-এর উপর ভিত্তি করে কাজ করে। Django ORM-এর model fields-ও descriptor behavior ব্যবহার করে model attribute access পরিচালনা করে।

Common confusion: Descriptor নিজে decorator নয়। এটি protocol implement করা object। property descriptor-এর একটি built-in ব্যবহার।
Interview answer: Descriptor protocol Python-এর attribute access customize করার mechanism। __get__, __set__, __delete__ implement করে reusable validation, computed attributes এবং framework-level field behavior তৈরি করা যায়।
05Metaclass কী? Python class কীভাবে তৈরি হয়?⌄

Concept

Metaclass হলো class তৈরির class। সাধারণ object-এর type যেমন তার class, তেমনি সাধারণ class object-এর type হলো metaclass। Python-এ default metaclass হলো type।

Class এবং type relationship
class User:
    pass

user = User()

print(type(user))  # <class '__main__.User'>
print(type(User))  # <class 'type'>

Class creation-এর ধারণা

class User: statement execute হলে Python class body execute করে namespace তৈরি করে; তারপর metaclass সেই namespace ব্যবহার করে class object তৈরি করে। সাধারণ ক্ষেত্রে metaclass হলো type। Class body execution-এর আগে base class ও metaclass selection-সহ আরও কিছু preparation step হয়।

Custom metaclass example

Python example
class RequireTableName(type):
    def __new__(mcls, name, bases, namespace):
        if name != "BaseModel" and "table_name" not in namespace:
            raise TypeError("table_name is required")

        return super().__new__(mcls, name, bases, namespace)


class BaseModel(metaclass=RequireTableName):
    pass


class User(BaseModel):
    table_name = "users"


# class Product(BaseModel):
#     pass  # TypeError: table_name is required

__new__-এর arguments কী?

  • mcls: যে metaclass class তৈরি করছে।
  • name: তৈরি হতে থাকা class-এর নাম।
  • bases: parent/base class-এর tuple।
  • namespace: class body থেকে পাওয়া attribute ও method-এর mapping।

কখন ব্যবহার করা উচিত?

যখন class definition-এর সময় central rule enforce, automatic registration, class attribute validation বা API generation দরকার হয়, তখন metaclass কাজে আসতে পারে। তবে সাধারণত class decorator, __init_subclass__ বা composition দিয়ে কাজটি সহজে করা গেলে metaclass এড়িয়ে যাওয়া ভালো।

Common confusion: Metaclass object তৈরি করে না; এটি class object তৈরি করে। Metaclass দিয়ে তৈরি class থেকে পরে ordinary instance তৈরি হয়।
Interview answer: Metaclass হলো class-এর type এবং class creation customize করার mechanism। Python-এর default metaclass type; custom metaclass দিয়ে class তৈরি হওয়ার সময় validation বা registration করা যায়।
06__new__ vs __init__ — পার্থক্য কী?⌄

Concept

__new__ instance তৈরি করে এবং instance return করে। __init__ তৈরি হওয়া instance initialize করে; এটি নতুন instance return করে না। তাই __new__ হলো object creation stage, আর __init__ হলো initialization stage।

Execution order

Python example
class Person:
    def __new__(cls, name):
        print("__new__: creating instance")
        instance = super().__new__(cls)
        return instance

    def __init__(self, name):
        print("__init__: initializing instance")
        self.name = name


person = Person("Anik")

Output:

__new__: creating instance
__init__: initializing instance

Internal working

  • Person("Anik") call হলে metaclass type.__call__ সাধারণ object instantiation flow পরিচালনা করে।
  • প্রথমে Person.__new__ call হয়। এটি Person instance return করলে সেই instance-এ __init__ call হয়।
  • __new__ যদি Person-এর instance return না করে, তাহলে সাধারণত __init__ call হয় না।
  • __init__ অবশ্যই None return করবে; অন্য কিছু return করলে TypeError হয়।

কখন __new__ override করা হয়?

Immutable type subclass করার সময় value তৈরির পর্যায়ে control দরকার হতে পারে। এছাড়া singleton-like object creation বা specialized object construction-এও ব্যবহার হতে পারে, যদিও singleton pattern-এর জন্য এটি সবসময় সেরা design নয়।

Immutable type subclass example
class UppercaseString(str):
    def __new__(cls, value):
        return super().__new__(cls, value.upper())

name = UppercaseString("anik")
print(name)  # ANIK
__new____init__
Instance তৈরি করে।তৈরি instance initialize করে।
একটি instance return করে।কোনো value return করে না; implicit return None।
Static method-এর মতো class-level creation hook।Instance method; self পায়।
Immutable subclassing-এ গুরুত্বপূর্ণ।Mutable state assign করতে বেশি ব্যবহৃত।
Common confusion: __init__ object তৈরি করে না। Object তৈরির দায়িত্ব __new__-এর। অধিকাংশ application code-এ __init__ override করাই যথেষ্ট।
Interview answer: __new__ class-এর instance allocate/create করে এবং instance return করে; __init__ সেই instance initialize করে। Python সাধারণত __new__ থেকে একই class-এর instance ফেরত এলে __init__ চালায়।
07Dataclasses কী? কেন ব্যবহার করা হয়?⌄

Concept

dataclasses হলো Python standard library-এর module, যা মূলত data রাখার class-এর জন্য boilerplate method automatic generate করে। @dataclass decorator field declaration দেখে সাধারণত __init__, __repr__ এবং __eq__ তৈরি করে।

Without dataclass
class Product:
    def __init__(self, name, price):
        self.name = name
        self.price = price
With dataclass
from dataclasses import dataclass

@dataclass
class Product:
    name: str
    price: float

p1 = Product("Keyboard", 1200.0)
p2 = Product("Keyboard", 1200.0)

print(p1)        # Product(name='Keyboard', price=1200.0)
print(p1 == p2)  # True

Field default এবং mutable default

একই mutable object একাধিক instance-এর মধ্যে share হয়ে যাওয়ার ঝুঁকি এড়াতে default_factory ব্যবহার করা হয়।

Correct mutable default
from dataclasses import dataclass, field

@dataclass
class Team:
    name: str
    members: list[str] = field(default_factory=list)

a = Team("A")
b = Team("B")
a.members.append("Rafi")

print(a.members)  # ['Rafi']
print(b.members)  # []

গুরুত্বপূর্ণ options

  • frozen=True: field assignment বন্ধ করে; shallow immutability, nested mutable object নিজে থেকে immutable হয় না।
  • order=True: field order অনুযায়ী comparison methods generate করে।
  • slots=True: slots-enabled class তৈরি করে; Python 3.10+ এ সমর্থিত।
  • kw_only=True: generated initializer-এর field-গুলো keyword-only করে।
  • field(repr=False): repr output-এ field বাদ দেয়।

Dataclass বনাম Pydantic model

Dataclass মূলত Python object data structure এবং generated methods-এর সুবিধা দেয়; সাধারণ dataclass runtime-এ type annotation validate করে না। Pydantic model parsing ও runtime validation-এর জন্য তৈরি।

Common confusion: name: str লেখা মানেই runtime-এ string ছাড়া অন্য value assign আটকাবে না। Dataclass annotation নিজে runtime type enforcement করে না।
Interview answer: Dataclass data-centric class-এর boilerplate কমায়। Field annotation থেকে initializer, representation এবং equality-এর মতো method generate করে। Mutable default-এর জন্য field(default_factory=...) ব্যবহার করা উচিত।
08Python __slots__ কী? এর সুবিধা ও সীমাবদ্ধতা কী?⌄

Concept

__slots__ class-level declaration, যা instance-এর জন্য নির্দিষ্ট attribute storage slot নির্ধারণ করে। সাধারণ class instance-এর __dict__ থাকে; __slots__ ব্যবহার করলে সাধারণত instance dictionary তৈরি হয় না, যদি না inheritance বা explicit declaration-এর কারণে তা থাকে।

Example
class Point:
    __slots__ = ("x", "y")

    def __init__(self, x, y):
        self.x = x
        self.y = y

point = Point(10, 20)
print(point.x)  # 10

# point.z = 30  # AttributeError
# print(point.__dict__)  # AttributeError

কেন ব্যবহার করা হয়?

  • প্রতি instance-এর dynamic attribute dictionary বাদ দিতে পারে।
  • অনেক instance তৈরি হলে memory usage কমাতে পারে।
  • অনুমোদিত attribute সীমিত করে accidental extra attribute assignment আটকায়।

গুরুত্বপূর্ণ সীমাবদ্ধতা

  • নতুন arbitrary attribute assign করা যায় না।
  • Parent class-এর slots এবং child class-এর slots inheritance-এ সঠিকভাবে বিবেচনা করতে হয়।
  • Parent class-এর __dict__ থাকলে child-এ slots দিলেও inherited dictionary থাকতে পারে।
  • __weakref__ slot না থাকলে weak reference সমর্থিত নাও হতে পারে।
  • একাধিক inheritance-এ slot layout conflict হতে পারে।

Slots মানেই সবসময় দ্রুত?

না। কিছু workload-এ memory কমে, attribute access-এও সুবিধা হতে পারে; কিন্তু performance gain ধরে নেওয়া ঠিক নয়। বাস্তব workload-এ benchmark করা উচিত।

Common confusion: __slots__ object-কে সম্পূর্ণ immutable করে না। Declared slot-এর value পরিবর্তন করা যায়; শুধু arbitrary নতুন attribute যোগ করা সীমিত হয়।
Interview answer: __slots__ নির্দিষ্ট instance attribute storage declare করে এবং সাধারণত per-instance __dict__ বাদ দেয়। এটি অনেক instance-এর memory footprint কমাতে পারে, তবে dynamic attributes ও কিছু inheritance pattern সীমিত করে।
09Python Type Hints কী? এগুলো কি runtime-এ type check করে?⌄

Concept

Type hints হলো variable, function parameter এবং return value-এর expected type প্রকাশ করার annotation। এগুলো code readability, IDE autocomplete, static analysis এবং refactoring-এ সাহায্য করে।

Basic example
def calculate_total(price: float, quantity: int) -> float:
    return price * quantity

username: str = "Anik"

Runtime behavior

Python সাধারণভাবে type hints enforce করে না। অর্থাৎ function-এ ভুল type পাঠালেই Python স্বয়ংক্রিয়ভাবে TypeError দেবে—এমন নয়। Type checker যেমন mypy বা Pyright static analysis করে সম্ভাব্য mismatch ধরতে পারে। Runtime validation প্রয়োজন হলে আলাদা validation logic বা Pydantic-এর মতো library ব্যবহার করা যায়।

Type hint enforcement নয়
def greet(name: str) -> str:
    return "Hello " + name

print(greet(123))  # Runtime-এ TypeError হবে concatenation-এর কারণে,
                   # type hint enforce করার কারণে নয়

Common typing forms

from typing import Optional

def find_user(user_id: int) -> str | None:
    ...

def average(values: list[float]) -> float:
    ...

def get_config() -> dict[str, str]:
    ...

def process(value: int | str) -> None:
    ...

Python 3.10+ এ A | B union syntax ব্যবহার করা যায়। পুরোনো version support করতে Union[A, B] লাগতে পারে। Optional[T] অর্থ T | None।

Any বনাম object

  • Any static type checker-কে অনেক ক্ষেত্রে type checking এড়িয়ে যেতে বলে; এটি type safety কমিয়ে দিতে পারে।
  • object হলো Python-এর সব object-এর base type। এর উপর operation করার আগে type narrow বা validate করতে হয়।

Type hints কোথায় দেখা যায়?

__annotations__ attribute-এ annotation রাখা হতে পারে; function-এর জন্য function.__annotations__ দিয়ে দেখা যায়। Annotation evaluation-এর নিয়ম Python version ও from __future__ import annotations-এর উপর নির্ভর করতে পারে।

Common confusion: Type hints runtime validation নয়। Static checker, IDE এবং developer tooling এগুলো ব্যবহার করে; runtime enforcement আলাদা concern।
Interview answer: Type hints expected types document করে এবং mypy/Pyright-এর মতো static type checker-কে সম্ভাব্য bug ধরতে সাহায্য করে। Python নিজে সাধারণত annotation enforce করে না।
10Protocol কী? Duck Typing ও ABC-এর সঙ্গে পার্থক্য কী?⌄

Concept

typing.Protocol structural subtyping-এর interface define করতে ব্যবহার হয়। কোনো class Protocol inherit না করেও যদি প্রয়োজনীয় attribute ও method-এর shape পূরণ করে, static type checker সেটিকে ওই Protocol-এর উপযুক্ত type হিসেবে গ্রহণ করতে পারে।

Example

Protocol definition
from typing import Protocol

class Notifier(Protocol):
    def send(self, message: str) -> None:
        ...


class EmailNotifier:
    def send(self, message: str) -> None:
        print(f"Email: {message}")


class SMSNotifier:
    def send(self, message: str) -> None:
        print(f"SMS: {message}")


def alert(notifier: Notifier) -> None:
    notifier.send("Server is down")


alert(EmailNotifier())
alert(SMSNotifier())

এখানে কী হচ্ছে?

  • Notifier বলে দেয়, compatible object-এর send(message: str) -> None method থাকতে হবে।
  • EmailNotifier এবং SMSNotifier Protocol inherit করেনি।
  • তবুও তাদের method signature contract-এর সঙ্গে মিলে যাওয়ায় static type checker এগুলোকে Notifier হিসেবে গ্রহণ করতে পারে।
  • alert() concrete implementation না জেনে interface অনুযায়ী কাজ করে।

Protocol বনাম ABC বনাম Duck Typing

পদ্ধতিমূল ধারণাকীভাবে compatibility বোঝে
Duck Typingপ্রয়োজনীয় behavior থাকলে ব্যবহার করা যায়।সাধারণত runtime-এ method call করে; explicit interface declaration বাধ্যতামূলক নয়।
ABCAbstract base class contract ও shared implementation দিতে পারে।সাধারণত inheritance বা virtual subclass registration; abstract method implement না করলে instantiate করা যায় না।
ProtocolStructural interface contract।মূলত static type checker member structure দেখে compatibility নির্ধারণ করে।

@runtime_checkable কী করে?

@runtime_checkable decorator দিলে Protocol-এর বিরুদ্ধে isinstance() check করা যায়। তবে runtime check মূলত member presence দেখে; full signature ও type compatibility validate করে না। তাই এটিকে পূর্ণ runtime type validator মনে করা যাবে না।

Runtime-checkable Protocol
from typing import Protocol, runtime_checkable

@runtime_checkable
class Closable(Protocol):
    def close(self) -> None:
        ...

class FileLike:
    def close(self) -> None:
        print("closed")

print(isinstance(FileLike(), Closable))  # True

কখন Protocol ব্যবহার করা ভালো?

একাধিক unrelated class-এর একই behavior দরকার হলে, library বা application code-কে concrete class-এর উপর tightly coupled না রেখে dependency-এর expected interface type দিয়ে প্রকাশ করতে Protocol উপকারী।

Common confusion: Protocol ব্যবহার করতে class-কে অবশ্যই Protocol inherit করতে হবে না। এটিই structural typing-এর মূল সুবিধা। তবে runtime enforcement বা validation দরকার হলে আলাদা mechanism প্রয়োজন।
Interview answer: Protocol structural subtyping support করে। কোনো class explicit inheritance ছাড়াই Protocol-এর required members implement করলে static type checker সেটিকে compatible হিসেবে বিবেচনা করতে পারে। এটি flexible interface typing-এর জন্য উপযোগী।
