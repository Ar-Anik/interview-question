21Generic Types কী? TypeVar, Generic এবং Type Parameters কীভাবে কাজ করে?⌄

Concept — Generic Type কী?

Generic Type এমন class, function বা data structure define করতে সাহায্য করে, যা একাধিক data type-এর সঙ্গে কাজ করতে পারে; একই সঙ্গে type relationship ধরে রাখে। একই logic-এর জন্য int, str বা অন্য type অনুযায়ী আলাদা class/function লিখতে হয় না।

মূল সুবিধা শুধু “যেকোনো type গ্রহণ” নয়। Generic type input ও output-এর type-এর মধ্যে সম্পর্ক প্রকাশ করে, যাতে Static Type Checker ভুল usage ধরতে পারে।

Generic ছাড়া — type relationship হারিয়ে যেতে পারে
def first_item(items: list) -> object:
    return items[0]

# এখানে input list-এর element type এবং return type-এর
# সম্পর্ক type checker-এর কাছে নির্দিষ্ট নয়।
Generic type variable ব্যবহার করে
from typing import TypeVar

T = TypeVar("T")

def first_item(items: list[T]) -> T:
    return items[0]

name = first_item(["Anik", "Rafi"])  # inferred: str
age = first_item([25, 30])           # inferred: int

TypeVar কী করে?

TypeVar একটি type variable তৈরি করে। Generic function call-এর সময় type checker argument দেখে T-এর উপযুক্ত type infer করার চেষ্টা করে। উপরের example-এ string list পাঠালে return type str, integer list পাঠালে return type int হিসেবে infer হয়।

Generic class

Python 3.9+ compatible typing style
from typing import Generic, TypeVar

T = TypeVar("T")

class Box(Generic[T]):
    def __init__(self, value: T) -> None:
        self.value = value

    def get(self) -> T:
        return self.value

int_box = Box[int](100)
str_box = Box[str]("Python")

number = int_box.get()  # inferred: int
text = str_box.get()    # inferred: str

Generic[T] class-টিকে generic হিসেবে declare করে। Box[int] এবং Box[str] হলো type-checking-এর জন্য আলাদা parameterized type expression। সাধারণ Python runtime-এ এগুলো আলাদা generated class তৈরি করে না।

Python 3.12-এর নতুন generic syntax

PEP 695 syntax — Python 3.12+
def first_item[T](items: list[T]) -> T:
    return items[0]

class Box[T]:
    def __init__(self, value: T) -> None:
        self.value = value

    def get(self) -> T:
        return self.value

Python 3.12 থেকে type parameter সরাসরি def বা class declaration-এ লেখা যায়। পুরোনো TypeVar ও Generic syntax এখনও প্রচলিত এবং supported। Project-এর minimum Python version অনুযায়ী syntax বেছে নিতে হয়।

Bound ও constrained TypeVar

Bound: একটি base type বা তার subtype
from typing import TypeVar

Number = TypeVar("Number", bound=float)

def normalize(value: Number) -> Number:
    return value

bound=float হলে type variable-টি float বা তার subtype-এ সীমাবদ্ধ থাকে। এটি exact float only বোঝায় না।

Constraints: নির্দিষ্ট কয়েকটি type-এর একটি
TextOrBytes = TypeVar("TextOrBytes", str, bytes)

def duplicate(value: TextOrBytes) -> TextOrBytes:
    return value + value

Constrained TypeVar-এর ক্ষেত্রে type checker constraint list-এর উপযুক্ত type বেছে নেয়। Bound ও constraints এক জিনিস নয়: bound একটি upper bound/subtype relationship, আর constraints হলো নির্দিষ্ট বিকল্প type-এর set।

কেন দরকার এবং কখন ব্যবহার হয়?

  • Reusable collection, repository, cache, API response wrapper এবং utility function type-safe করতে।
  • একটি function-এর input type ও output type-এর সম্পর্ক ধরে রাখতে।
  • Library/API design-এ consumer-কে type information দিতে।
Common confusion: Generic annotation runtime validation করে না। Box[int]("hello") লিখলে Python নিজে থেকেই সাধারণত runtime-এ type mismatch reject করে না। Static type checker এটি ধরতে পারে। Runtime validation আলাদা করে implement করতে হয়।
Interview answer: Generics একই implementation-কে বিভিন্ন type-এর জন্য reusable করে এবং type variable-এর মাধ্যমে input-output relationship ধরে রাখে। Python-এ TypeVar/Generic বা Python 3.12+ type parameter syntax ব্যবহার করা যায়। Type hints মূলত static analysis-এর জন্য; এগুলো স্বয়ংক্রিয় runtime validation নয়।
22Structural Typing কী? Nominal Typing ও Protocol-এর সঙ্গে সম্পর্ক কী?⌄

Concept — Structural Typing

Structural Typing-এ কোনো object কোন class থেকে তৈরি হয়েছে, সেটি প্রধান বিষয় নয়। বরং object-টির প্রয়োজনীয় attribute ও method আছে কি না, সেটি দেখে compatibility বিচার করা হয়। অর্থাৎ object-এর structure বা capability গুরুত্বপূর্ণ।

এটি Duck Typing-এর ধারণার সঙ্গে সম্পর্কিত। Python-এর static typing system-এ typing.Protocol structural interface প্রকাশ করার একটি উপায়।

Structural বনাম Nominal Typing

Nominal TypingStructural Typing
Declared inheritance বা type identity গুরুত্বপূর্ণ।Required members-এর structure গুরুত্বপূর্ণ।
একটি type compatible হতে নির্দিষ্ট base class inherit করতে হতে পারে।Explicit inheritance ছাড়াও structure মিলে গেলে compatible হতে পারে।
ABC সাধারণত এই style-এর উদাহরণ।Protocol static structural typing-এর উদাহরণ।

Protocol দিয়ে practical example

Python example
from typing import Protocol

class PaymentGateway(Protocol):
    def charge(self, amount: float) -> bool:
        ...

class StripeGateway:
    def charge(self, amount: float) -> bool:
        print(f"Stripe charged: {amount}")
        return True

class MockGateway:
    def charge(self, amount: float) -> bool:
        print(f"Mock charge: {amount}")
        return True

def checkout(
    gateway: PaymentGateway,
    amount: float
) -> bool:
    return gateway.charge(amount)

checkout(StripeGateway(), 500.0)
checkout(MockGateway(), 500.0)

কেন দুইটি class compatible?

  1. PaymentGateway একটি required method declare করেছে: charge(amount: float) -> bool।
  2. StripeGateway ও MockGateway Protocol inherit করেনি।
  3. দুই class-ই required method implement করেছে। তাই static type checker structural compatibility গ্রহণ করতে পারে।
  4. checkout() concrete implementation-এর বদলে required behavior-এর উপর নির্ভর করছে।

Duck Typing বনাম Static Structural Typing

Duck Typing সাধারণত runtime behavior: কোনো object-এর প্রয়োজনীয় method call করা যায় কি না, সেটি দিয়ে কাজ চলে। Static Structural Typing-এ type checker আগে থেকেই declared Protocol-এর সঙ্গে object-এর structure compare করতে পারে।

কেন গুরুত্বপূর্ণ?

  • Unrelated class-কে একই interface-এর মাধ্যমে ব্যবহার করা যায়।
  • Third-party library বা external class modify না করেও compatibility প্রকাশ করা যায়।
  • Unit test-এ fake/mock implementation inject করা সহজ হয়।
  • Concrete class-এর উপর dependency কমে, design বেশি flexible হয়।
Common confusion: Protocol-এর সঙ্গে structural compatibility থাকলেই runtime-এ পূর্ণ validation হয় না। @runtime_checkable দিয়ে isinstance() check করা গেলেও সেটি মূলত member presence পরীক্ষা করে; method signature ও type correctness সম্পূর্ণ validate করে না।
Interview answer: Structural Typing type compatibility নির্ধারণ করে required members-এর structure দেখে, explicit inheritance দিয়ে নয়। Python-এর Protocol static type checker-কে এই contract প্রকাশ করতে সাহায্য করে।
23Dependency Injection (DI) কী? Python-এ DI-এর patterns ও benefits কী?⌄

Concept — Dependency কী?

একটি class বা function কাজ করার জন্য অন্য object/service ব্যবহার করলে সেটি তার dependency। যেমন OrderService order process করতে PaymentGateway ব্যবহার করে।

Dependency Injection হলো এমন design technique, যেখানে একটি component নিজের dependency নিজে তৈরি না করে বাইরে থেকে dependency গ্রহণ করে। ফলে component-এর concrete implementation-এর সঙ্গে tight coupling কমে।

Problem: Dependency নিজে তৈরি করা

Tightly coupled design
class StripeGateway:
    def charge(self, amount: float) -> bool:
        return True

class OrderService:
    def __init__(self):
        self.gateway = StripeGateway()  # নিজেই dependency তৈরি করছে

    def place_order(self, amount: float) -> bool:
        return self.gateway.charge(amount)

এখানে OrderService সরাসরি StripeGateway-এর উপর নির্ভরশীল। অন্য payment provider বা test fake ব্যবহার করতে গেলে service code পরিবর্তন করতে হয়।

Solution: Constructor Injection

Dependency বাইরে থেকে inject করা
from typing import Protocol

class PaymentGateway(Protocol):
    def charge(self, amount: float) -> bool:
        ...

class StripeGateway:
    def charge(self, amount: float) -> bool:
        print("Stripe payment")
        return True

class FakeGateway:
    def charge(self, amount: float) -> bool:
        print("Fake payment")
        return True

class OrderService:
    def __init__(self, gateway: PaymentGateway):
        self.gateway = gateway

    def place_order(self, amount: float) -> bool:
        return self.gateway.charge(amount)

# Production composition
service = OrderService(StripeGateway())

# Test composition
test_service = OrderService(FakeGateway())

DI-এর প্রধান patterns

1. Constructor Injection

Dependency constructor-এর parameter হিসেবে পাঠানো হয়। Required dependency-এর জন্য এটি সাধারণত সবচেয়ে পরিষ্কার এবং সহজে testable pattern। Object তৈরি হওয়ার সময়ই dependency পাওয়া যায়।

class ReportService:
    def __init__(self, repository):
        self.repository = repository

2. Setter / Property Injection

Object তৈরি হওয়ার পর setter বা property দিয়ে dependency assign করা হয়। Optional dependency বা runtime-এ replace করার প্রয়োজন থাকলে ব্যবহার হতে পারে। তবে dependency সেট না করেই method call হয়ে যাওয়ার ঝুঁকি থাকে।

class ReportService:
    def set_repository(self, repository):
        self.repository = repository

service = ReportService()
service.set_repository(repository)

3. Method Injection

শুধু নির্দিষ্ট operation-এর সময় dependency method parameter হিসেবে পাঠানো হয়। Dependency যদি পুরো object-এর lifetime জুড়ে প্রয়োজন না হয়, এই pattern উপযোগী হতে পারে।

class ExportService:
    def export(self, data, storage):
        storage.save(data)

4. Interface / Protocol-based Injection

Concrete class-এর বদলে Protocol বা ABC-এর মতো abstraction-এর মাধ্যমে dependency গ্রহণ করা হয়। এতে implementation বদলালেও consumer-এর code সাধারণত বদলাতে হয় না।

Composition Root কী?

Application-এর একটি নির্দিষ্ট জায়গায় concrete dependency তৈরি করে service-গুলোর মধ্যে connect করাকে Composition Root pattern বলা হয়। যেমন application startup বা configuration layer-এ repository, gateway, service তৈরি করে একে অন্যের কাছে inject করা। Business logic-এর ভিতরে সব জায়গায় object creation ছড়িয়ে না দেওয়াই লক্ষ্য।

Simple composition root
def build_order_service():
    gateway = StripeGateway()
    return OrderService(gateway)

order_service = build_order_service()

DI বনাম Dependency Inversion Principle

দুইটি related কিন্তু এক নয়। Dependency Injection হলো dependency সরবরাহ করার technique। Dependency Inversion Principle (DIP) হলো design principle: high-level policy ও low-level implementation সরাসরি একে অন্যের উপর নির্ভর না করে abstraction-এর উপর নির্ভর করবে। DI, DIP বাস্তবায়নে সাহায্য করতে পারে; কিন্তু DI ব্যবহার করলেই স্বয়ংক্রিয়ভাবে DIP মেনে চলা হয় না।

Benefits ও trade-offs

  • Testability: Real database/payment service-এর বদলে fake dependency দেওয়া যায়।
  • Loose coupling: Consumer concrete implementation-এর detail কম জানে।
  • Flexibility: Configuration অনুযায়ী implementation বদলানো যায়।
  • Maintainability: Object creation ও business logic আলাদা থাকে।
  • Trade-off: অতিরিক্ত abstraction বা বড় DI container configuration system বোঝা কঠিন করতে পারে। ছোট project-এ manual constructor injection যথেষ্ট।
Common confusion: DI মানেই কোনো framework বা DI container ব্যবহার করা নয়। Constructor parameter দিয়ে object pass করাও Dependency Injection। Container শুধু dependency creation ও wiring automate করতে পারে।
Interview answer: Dependency Injection হলো dependency-কে component-এর ভিতরে instantiate না করে বাইরে থেকে সরবরাহ করা। Constructor Injection সবচেয়ে common pattern। এটি loose coupling ও testability বাড়ায়। DI একটি technique; DIP একটি design principle।
24Functional Programming কী? Pure Function, Immutability, Higher-order Function ও Closure কী?⌄

Concept

Functional Programming (FP) হলো programming paradigm, যেখানে computation-কে function composition ও value transformation হিসেবে সাজানো হয়। এতে predictable function, immutable data এবং side effect নিয়ন্ত্রণের উপর গুরুত্ব দেওয়া হয়। Python multi-paradigm language: একই project-এ object-oriented, procedural এবং functional style একসঙ্গে ব্যবহার করা যায়।

1. Pure Function

একটি pure function-এর দুইটি গুরুত্বপূর্ণ বৈশিষ্ট্য থাকে: একই input-এর জন্য একই output দেয় এবং function-এর বাইরে observable side effect ঘটায় না।

Pure function
def add_tax(price: float, rate: float) -> float:
    return price + (price * rate)

print(add_tax(100, 0.10))  # 110.0
Impure function — external state পরিবর্তন করে
total = 0

def add_to_total(value):
    global total
    total += value
    return total

Pure function test ও reason করা সহজ, কারণ output নির্ভর করে শুধু input-এর উপর। তবে বাস্তব application-এ database, network, file system বা logging-এর মতো side effect প্রয়োজন হয়; FP style-এ এগুলোকে সীমিত boundary-তে রাখা হয়।

2. Immutability

Immutability মানে তৈরি হওয়ার পর object-এর state পরিবর্তন না করা। Python-এ int, str, tuple-এর মতো কিছু built-in type immutable; কিন্তু list, dict, set mutable। Tuple-এর ভিতরে mutable object থাকলে সেটির internal state বদলাতে পারে—তাই tuple সবসময় deeply immutable নয়।

নতুন value তৈরি করা
numbers = (1, 2, 3)
updated = numbers + (4,)

print(numbers)  # (1, 2, 3)
print(updated)  # (1, 2, 3, 4)

3. First-class ও Higher-order Function

Python-এ function হলো first-class object: variable-এ রাখা, argument হিসেবে পাঠানো এবং অন্য function থেকে return করা যায়। Higher-order function হলো এমন function, যা অন্য function-কে argument হিসেবে নেয় অথবা function return করে (অথবা দুটোই করে)।

Function as argument
def apply_operation(value, operation):
    return operation(value)

def square(number):
    return number * number

print(apply_operation(5, square))  # 25

4. map(), filter() এবং reduce()

Transformation ও filtering
numbers = [1, 2, 3, 4, 5]

squares = list(map(lambda x: x * x, numbers))
evens = list(filter(lambda x: x % 2 == 0, numbers))

print(squares)  # [1, 4, 9, 16, 25]
print(evens)    # [2, 4]

Python 3-এ map() ও filter() iterator return করে; তাই এখানে list() দিয়ে materialize করা হয়েছে। অনেক ক্ষেত্রে list comprehension আরও readable:

squares = [x * x for x in numbers]
evens = [x for x in numbers if x % 2 == 0]
reduce() — একাধিক value combine করা
from functools import reduce

numbers = [1, 2, 3, 4]

product = reduce(lambda a, b: a * b, numbers)
print(product)  # 24

5. Closure

Closure হলো inner function, যা outer function-এর scope-এর variable reference ধরে রাখতে পারে—outer function execution শেষ হওয়ার পরও।

Closure example
def make_multiplier(factor):
    def multiply(value):
        return value * factor
    return multiply

double = make_multiplier(2)
triple = make_multiplier(3)

print(double(10))  # 20
print(triple(10))  # 30

multiply() function তার enclosing scope-এর factor variable ধরে রাখে। এই captured environment-এর কারণেই double ও triple আলাদা behavior দেয়।

6. Function Composition

একটি function-এর output অন্য function-এর input হিসেবে ব্যবহার করে বড় operation তৈরি করাকে function composition বলা হয়।

def strip_text(value):
    return value.strip()

def normalize_text(value):
    return value.lower()

def compose(value):
    return normalize_text(strip_text(value))

print(compose("  PYTHON  "))  # python

Functional Programming-এর সুবিধা ও সীমাবদ্ধতা

  • Pure function unit test ও debugging সহজ করে।
  • Immutable data accidental shared-state mutation কমায়।
  • Function composition ছোট logic পুনরায় ব্যবহার করতে সাহায্য করে।
  • Side effect boundary-তে রাখলে business logic বেশি predictable হয়।
  • অতিরিক্ত abstraction বা nested lambda code readability কমাতে পারে; Python-এ readability ও team convention গুরুত্বপূর্ণ।
Common confusion: Functional Programming মানে class ব্যবহার করা যাবে না—এমন নয়। Python-এ এটি একটি style/paradigm, বাধ্যতামূলক programming rule নয়। Pure function মানে function-এর ভিতরে কোনো computation হবে না, সেটিও নয়; মূল বিষয় হলো external observable state-এর side effect না থাকা।
Interview answer: Functional Programming computation-কে function ও value transformation দিয়ে সাজায়। এর গুরুত্বপূর্ণ concept হলো pure function, immutability, first-class/higher-order function, closure ও function composition। Python multi-paradigm হওয়ায় প্রয়োজন অনুযায়ী FP technique ব্যবহার করা যায়।
25Python Memory Management কীভাবে কাজ করে? Reference Counting, Garbage Collection ও Memory Allocator কী?⌄

Concept — Memory Management

Program চলার সময় object ও data রাখার জন্য memory প্রয়োজন হয়। Python runtime object allocation, object lifetime এবং অপ্রয়োজনীয় object cleanup-এর বড় অংশ পরিচালনা করে। তাই সাধারণ Python code-এ প্রতিটি object-এর memory manually allocate/free করতে হয় না।

তবে Python language-এর সব implementation একই internal memory management ব্যবহার করে না। নিচের reference counting ও cyclic garbage collector-এর আলোচনা মূলত CPython-এর behavior নিয়ে, যা সবচেয়ে প্রচলিত Python implementation।

1. Object ও Reference

Python-এ variable-কে object-এর named box হিসেবে না দেখে object-এর reference বা binding হিসেবে বোঝা ভালো। একটি object-এর একাধিক reference থাকতে পারে।

একই object-এর একাধিক reference
first = [10, 20]
second = first

second.append(30)

print(first)   # [10, 20, 30]
print(second)  # [10, 20, 30]

print(first is second)  # True

first ও second একই list object-কে reference করছে। তাই এক reference দিয়ে mutable object পরিবর্তন করলে অন্য reference দিয়েও পরিবর্তনটি দেখা যায়।

2. Reference Counting

CPython প্রতিটি object-এর reference count track করে। কোনো object-এর strong reference তৈরি হলে count বাড়ে; reference remove হলে count কমে। Reference count শূন্য হলে CPython সাধারণত object-এর memory release করার জন্য deallocation শুরু করতে পারে।

Reference remove করার example
import sys

data = []
alias = data

print(sys.getrefcount(data))  # getrefcount নিজেও temporary reference নেয়

del alias
print(sys.getrefcount(data))

del data  # এই নামের binding সরানো হলো

sys.getrefcount() নিজেই temporary reference তৈরি করে, তাই printed value সরাসরি “কতটি variable আছে” তা নয়। Reference count implementation detail; application logic এর উপর নির্ভর করা উচিত নয়।

3. Garbage Collection (GC)

Reference counting একা সব object cleanup করতে পারে না। বিশেষ করে circular reference থাকলে object-গুলো একে অন্যকে reference করায় count শূন্য হয় না—যদিও বাইরে থেকে সেগুলো আর reachable নয়। CPython-এর cyclic garbage collector এ ধরনের unreachable reference cycle শনাক্ত ও cleanup করতে সাহায্য করে।

Circular reference
class Node:
    pass

a = Node()
b = Node()

a.other = b
b.other = a

# a এবং b একে অন্যকে reference করছে।
# বাইরের reference মুছে গেলে cycle garbage collector
# এই unreachable cycle cleanup করতে পারে।

del a
del b

CPython-এর cyclic GC মূলত container object-এর reference graph বিশ্লেষণ করে unreachable cycle খুঁজে পায়। এটি reference counting-এর বিকল্প নয়; reference counting-এর পাশাপাশি কাজ করে।

4. gc module

GC inspect ও control
import gc

print(gc.isenabled())  # automatic GC enabled কি না
print(gc.get_count())  # generation অনুযায়ী allocation counters

collected = gc.collect()
print("Collected:", collected)

gc.collect() explicit collection request করে এবং collected unreachable cyclic object-এর count return করে। এটি সব ধরনের memory সঙ্গে সঙ্গে operating system-এ ফেরত দেবে—এমন guarantee নয়। সাধারণ application-এ অকারণে GC disable করা উচিত নয়।

5. Memory Allocator এবং Python Memory Arena

CPython-এর memory allocation system বিভিন্ন স্তরে কাজ করে। Python object-এর memory request প্রথমে Python memory manager-এর মাধ্যমে যায়; ছোট object allocation-এর ক্ষেত্রে CPython-এর pymalloc allocator ব্যবহার হতে পারে। এটি memory pool/arena-ভিত্তিক allocation করে allocation overhead কমাতে সাহায্য করে। বড় allocation বা নির্দিষ্ট allocation path-এ lower-level allocator ব্যবহার হতে পারে।

  • Object allocator: Python object-এর জন্য প্রয়োজনীয় memory allocation পরিচালনা করে।
  • Pool: একই size class-এর ছোট block রাখার allocation unit।
  • Arena: একাধিক pool রাখার বড় memory region।
  • Underlying allocator: operating system বা C runtime-এর allocator থেকে বড় memory region সংগ্রহ করতে পারে।

এগুলো CPython-এর implementation detail; Python language specification সব implementation-এর জন্য একই allocator architecture বাধ্যতামূলক করে না।

6. del statement কী করে?

del x সাধারণত object-কে সরাসরি destroy করে না; এটি current scope থেকে x নামের binding remove করে। Object-এর অন্য reference থাকলে object বেঁচে থাকে। শেষ strong reference সরলে CPython object deallocate করতে পারে, তবে finalization ও resource management-এর আরও জটিলতা থাকতে পারে।

del মানেই object delete নয়
items = [1, 2, 3]
backup = items

del items

print(backup)  # [1, 2, 3]
# Object এখনও backup-এর মাধ্যমে reachable

7. Memory leak কি Python-এ হতে পারে?

হ্যাঁ। Garbage collector থাকলেও application memory leak বা unbounded memory growth ঘটতে পারে। সাধারণ কারণ:

  • Global list/dictionary-তে object জমিয়ে রাখা।
  • Cache-এ eviction policy ছাড়া data রাখা।
  • Long-lived object-এর মধ্যে অপ্রয়োজনীয় reference ধরে রাখা।
  • Event handler, callback বা closure-এ object ধরে রাখা।
  • C extension বা native library-তে allocation/freeing সমস্যা।
  • Unbounded queue বা background task accumulation।

8. Memory diagnose করার tools

tracemalloc — Python allocation trace
import tracemalloc

tracemalloc.start()

data = [i for i in range(100_000)]

current, peak = tracemalloc.get_traced_memory()
print("Current:", current)
print("Peak:", peak)

tracemalloc.stop()

tracemalloc Python memory allocation trace ও snapshot তুলনায় কাজে লাগে। এটি সব native/C-extension memory allocation track করে না। Process-level memory দেখতে OS tools বা psutil-এর মতো tool প্রয়োজন হতে পারে।

9. Object cleanup বনাম external resource cleanup

File, socket, database connection-এর মতো external resource release করার জন্য garbage collection-এর উপর নির্ভর করা উচিত নয়। Deterministic cleanup-এর জন্য context manager ব্যবহার করা ভালো।

Context manager
with open("data.txt", "r", encoding="utf-8") as file:
    content = file.read()

# with block শেষ হলে file close হয়,
# exception হলেও context manager cleanup চালায়।

GIL কি Memory Management?

না। GIL (Global Interpreter Lock) CPython-এর কিছু build-এ Python bytecode execution-এর concurrency নিয়ন্ত্রণের mechanism; এটি garbage collector বা memory allocator নয়। Python 3.13 থেকে free-threaded CPython build-ও experimental/optionalভাবে পাওয়া যায়, তাই GIL-কে সব Python implementation বা সব build-এর universal property বলা ঠিক নয়।

Common confusion: Object deallocate হওয়া, Python allocator-এর কাছে memory ফেরত যাওয়া এবং operating system-এ memory ফেরত যাওয়া—এগুলো এক ঘটনা নয়। Python allocator freed block ভবিষ্যৎ allocation-এর জন্য ধরে রাখতে পারে। তাই object delete করার পর process memory (RSS) সঙ্গে সঙ্গে কমবে এমন guarantee নেই।
Interview answer: CPython memory management-এ reference counting প্রধান mechanism এবং cyclic garbage collector unreachable reference cycle cleanup করে। Python memory allocator object allocation পরিচালনা করে; small allocations-এর জন্য pymalloc pool/arena ব্যবহার করতে পারে। Object deallocation মানেই memory সঙ্গে সঙ্গে OS-এ ফেরত যাওয়া নয়। External resource-এর জন্য context manager ব্যবহার করা উচিত।
